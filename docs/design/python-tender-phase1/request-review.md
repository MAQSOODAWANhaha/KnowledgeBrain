## 所有模型调用的流式与180秒空闲合同

统一client用于extract、verify、plan和OCR。实际请求必须`stream=true`并请求最终usage。
首个响应数据等待和相邻接收数据的空闲上限均为180秒；收到有效流数据后重置。
**没有总请求180秒硬截止。** 连接建立/连接池/写入故障单独处理，不与已发送后的空闲混淆。

在原始响应数据/SSE层观察活性，不能只给SDK聚合后的业务chunk设置超时。协议心跳/事件、
思考片段和工具参数片段都不等于最终业务正文，但不能因为SDK未产出content就误判无数据。
审计区分接收事件、业务正文、usage和完成标志；不执行模型返回的工具调用。

- HTTP/服务明确拒绝与连接中断分开；请求发送后超时、断流或取消保留部分审计并记录不确定性，
  不能当成功、不能捏造usage。已发送而执行/计费不确定的请求不自动重放付费；失败回执保留，
  需操作方显式决定后续重新提交。明确可重试的服务拒绝仍按既有有界基础设施策略处理。
- 崩溃恢复同样执行该规则：`request_digest`绑定完整无鉴权请求（含模型、消息、图片与协议配置），
  同run/source_version/domain_revision/task下的sent/uncertain不能换request_id绕过而再次发送。
  已正常完成且不可变response_ref可验证时，恢复复用该响应继续领域校验；不为checkpoint
  或业务产物尚未提交重复计费。未发送prepared和明确失败的处置与不确定请求区分。
- 正常流完成、正常finish reason、完整JSON对象且领域schema校验通过，才可提交对应领域产物。
  缺完成标志、截断JSON/工具参数、协议错误或拒绝都不能产生成功产物；工具输出不是业务JSON。
- 最终usage缺失时为unknown/null，不伪造0；仅usage缺失不等于已完成业务正文失败。
  收到的响应/部分流按单一不可变审计产物引用保存，不多份拼接回写或打印文档/秘密。

本地SSE与可控时钟验证：首数据超时、chunk间超时、总时长超过180秒但持续返回成功、
心跳与思考/工具增量、中途断连、正常结束、最终usage及usage缺失、截断JSON。
先完成实际发送体必要性审查，再更新预检和整个确定性回归。真实模型仍为0次。

### 表示和算法的保留理由

| 项 | 处理及必要性 |
| --- | --- |
| 文档身份 | document_id/document_version在请求根各一次，用于区别文件和补遗身份 |
| range_id、来源片段坐标 | 保留引用与真正切片边界；完整非切片不重复unit_id/存储定位，宿主可回溯 |
| 正文及条件原文 | 全部保留；有明确适用关系的条件、表头及scope目标保留，pending不冒充已解决 |
| section_id/heading_path | 共用sections，一章路径一次；不是逐行重复同一长路径 |
| 表格字段 | 保留column/start/end、实际非默认合并、部分空格、公式显示状态和图片锚点；去掉重复cell文本及默认值 |
| 空白模板 | 76行压缩成一次模板结构、真实range ID与区间，仍要求逐行有依据处置及独立审阅 |
| 已审议装饰图 | 98出现位置留canonical；host_reviewed_range_ids与模型reviewed_range_ids明确分开 |
| prompt/schema | 四阶段职责及严格输出合同必要；schema在system文本内，外部只用json_object，无tools或json_schema副本 |
| 实际图片 | 本原件无待OCR图；通用路径仍保留真正图片及表单内图片关联，不发送文本PDF页图 |
| 分包估算hint | 改为实际完整请求的指数扩张/失败间隙收缩；每候选复验，不把早期hint变成隐性包上限 |
