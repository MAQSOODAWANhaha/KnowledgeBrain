# Python 招标分析问题与修复记录

本文件统一记录 Python 招标分析在评审、测试和部署中发现的问题，以及根因、解决方案和
实际验证结果。字段定义仍以[字段字典](field-dictionary.md)为准，操作入口见
[runbook](runbook.md)，运行时间线和私有证据位置见[交接文档](handoff.md)。

## 维护约定

- 每次发现问题，先在这里新增记录，再修复；同一问题更新原编号，复发时追加证据。
- 每条至少写明现象、影响、根因、解决方案、状态和验证结果。根因未查实就明确标为待查，
  建议方案不得写成已实现。
- 修复后补充实际测试、部署和真实文件结果；离线回放、确定性模型测试、真实模型运行、
  人工语义验收分别说明，不能相互替代。未通过的用例和剩余问题如实保留。
- 原始回包、成功产物、用量和旧运行保留；不把清缓存、改摘要、伪造修订或删除问题作为修复。
  不在本文件提交密钥、招标全文或完整请求。`/tmp` 证据仅供本机排查，可能被清理；可重复验证
  以仓库测试及已登记的不可变产物为准。

新问题沿用下面的最小格式，无需增加工作流节点或状态：

```markdown
### BUG-XXX 问题名称

- 状态 / 发现阶段：待定位；真实文件核验。
- 现象与影响：……
- 根因：已确认事实；尚未证实的部分单列。
- 解决方案：准备或已经采取的修改，以及需要保留的约束。
- 验证：复现、回归、部署和真实文件结果；未完成的检查。
```

### 反复出现的三种模式

1. **让模型做宿主可推出的机械工作。** 誊写长ID、维护反向索引、逐范围写处置，反复造成
   整包拒收（003、009、017、018、022），每次以局部容错修补。
2. **只验证局部。** 以单包准入、单测通过为验收，没有回答全文件调用多少次、问题由谁通过
   什么出口解决、修订一次重跑多少（014、021、025至027）；阻断后无出口直到全量复审才发现。
3. **状态与证据分散。** 多处维护实时进度（016），证据只放`/tmp`或可删除的卷，代码长期未提交。

## 问题详情

### BUG-001 表格发送视图不便理解且证据边界不一致

- 状态 / 发现阶段：已修复并部署；压缩格式评审及真实文件离线预检。
- 现象与影响：单元格仅给字符偏移，模型需要自行切片；部分视图顺序偏离冻结来源顺序，
  仅发送 cell 时仍可能用未发送的整行文本校验证据。
- 根因：宿主定位结构直接用于模型阅读，发送视图与证据反查没有共用实际可见文本边界。
- 解决方案：发送宿主切好的 `cell.text`，能完整表达时省去重复整行；按文档、冻结范围和
  片段起点排序。抽取与关联共用可见证据校验，禁止引用隐藏整行或跨 cell 拼接内容。
- 验证：106 页文件离线预检覆盖 796 范围，无缺漏、重复或错误区间；239 表格行、805 cells
  与规范来源一致。Wire 减少属于字节测量，不能当作 Token 降幅或模型理解质量已通过。
  证据：`/tmp/kb-v2-preflight-celltext-9ghbrybb/report.json`；回归见
  [来源视图测试](../../../services/docreader/tests/unit/test_tender_source_view.py)。

### BUG-002 模型省略原文换行导致合法引文被拒收

- 状态 / 发现阶段：已修复并部署；旧真实抽取回包离线诊断。
- 现象与影响：92 处引文省略源 LF，严格子串检查拒收整个有效抽取包。
- 根因：精确引文匹配没有区分可唯一恢复的源 LF 省略与真实文字改动。
- 解决方案：精确匹配优先；仅在实际发送的同一可见文本中，允许恢复唯一原区间内省略的
  `U+000A`，记录诊断。不做 NFKC、任意空白或标点替换，不使用隐藏原文。
- 验证：旧 4 包离线恢复 92 处引文中的 137 个 LF，原始回包和冻结来源不变；歧义、越界
  与其他字符改动仍拒绝。见[引文恢复测试](../../../services/docreader/tests/unit/test_evidence_quote_recovery.py)
  及 `/tmp/kb-final-protocol-VvBnef/raw-replay-report.json`。引文可追溯不证明事项语义正确。

### BUG-003 让模型重复维护处置反向索引

- 状态 / 发现阶段：已修复并部署；真实回包处置校验。
- 现象与影响：2 处 `dispositions.item_ids` 各多声明一个事项 ID，有效事项受冗余索引冲突影响。
- 根因：已有 `items.evidence`，协议仍让模型独立维护同一引用关系的反向索引。
- 解决方案：模型判断处置状态和理由，宿主按事项直接证据派生 `item_ids`。处置缺失或矛盾时
  保留有效事项和具体问题送独立核验，不补造语义结论，也不清除模型明确的 `unresolved`。
- 验证：旧回包离线重建 2 处索引，原有 14 个明确来源未决保留；处置矛盾仍待独立核对。
  见[回包恢复测试](../../../services/docreader/tests/unit/test_analysis_response_recovery.py)
  及 `/tmp/kb-final-protocol-VvBnef/raw-replay-report.json`。

### BUG-004 可选数字字段错误导致有效事项被拒收

- 状态 / 发现阶段：已修复并部署；真实回包结构校验。
- 现象与影响：可选 `numbers` 存在缺 quote、quote 无法在该事项实际发送来源定位的声明，
  导致正文和证据有效的事项被拒收。
- 根因：将可选数字摘要的完整性与最小事项的可接受性绑定；同包其他事项的引文也不能
  证明当前事项数字声明有据。
- 解决方案：不完整或不可追溯时省略整个可选 `numbers` 并记录诊断，完整 `text/evidence`
  保留。数字归属、单位、比较关系及条件由独立 LLM 核验，不新增业务正则裁决。
- 验证：旧回包离线省略 2 个事项的 numbers；合法零值、同一已引用范围内互补引文保留。
  见[回包恢复测试](../../../services/docreader/tests/unit/test_analysis_response_recovery.py)。
  此修复不代表数字关系已经验证正确。

### BUG-005 完整流中的 JSON 无效

- 状态 / 发现阶段：已通过正式重试恢复该包；真实抽取。
- 现象与影响：请求 `f9408dfbe11c459fa2dc9344143e4e31` 有完整 SSE、DONE、stop 和 usage，
  内容仍因两个多余右花括号无法解码；4 包中该包的 278 个范围没有有效抽取回执。
- 根因：模型完整输出了语法错误 JSON，属于明确回包失败；不是网络超时或流式截断。
  内存中删除两个符号虽能解码，dispositions 仍为空，不能当作成功。
- 解决方案：保留原始失败回包和 usage，使用 BUG-006 的正式入口仅重试失败包；不手工改写
  回包、不用格式修补冒充覆盖或语义核验。没有保证模型永不再输出无效 JSON。
- 验证：同一 run/source/domain 通过正式 retry 后，4 个抽取包全部接受，共 319 事项、
  30 关系、796 处置，原 3 个成功包及 OCR 复用。语法诊断：
  `/tmp/kb-tender-terminal-audit-ay9itnq6/failed-json-report.json`；恢复事实见[交接](handoff.md)。
