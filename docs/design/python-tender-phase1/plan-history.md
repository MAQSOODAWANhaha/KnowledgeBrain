仅作设计依据；当前方案见[全量根因复审与统一优化方案](bug-fix.md#全量根因复审与统一优化方案)。


本节覆盖全部26个问题，不把每次现象都当成新的架构缺陷。五节点、统一事项、独立核验、
不可变产物和租约框架仍保留；需要调整的是节点内部的合同边界与任务组织。
A/B已在源码实现并验证，部署和真实调用进度以[交接](handoff.md)为准；C仍是候选实验。
以下修复顺序不新增主节点、RunStatus、业务正则、环境变量或通用Agent框架。
目标是让可用数据继续流转，真实问题可追溯地得到处理，而非让全部校验无条件通过。

这些问题有共同传播链：可选字段或范围说明不清 → 有效事项缺席/局部误报 → 原问题和
续报累计 → 无差别补读 → 候选与整章原文膨胀 → 更多关联/联合核验 → 更高的耗时和失败暴露。
字节估算过保守会增加分组，输出预留偏小又会隐藏输出负荷；两者不能简单相互抵消。
网络故障不是这条链的必然结果，减少调用只能降低暴露次数，不能当作网络根因修复。

## 五种处理边界

| 情况 | 宿主动作 | 继续条件 |
| --- | --- | --- |
| 可确定恢复的引用/格式冗余 | 规范化并留诊断，原回包不变 | 保留其他有效内容继续处理，不增加模型调用 |
| 局部字段或证据不能接受 | 保留有效核心及原声明、位置、具体错误，送模型核对 | 不整包作废，不以诊断替代语义判断；无法成立的核心仍标待核对 |
| 明确传输失败或完整回包违反必需合同 | 明确失败按现有策略恢复；合同拒收携带具体错误反馈纠正 | 沿用首次加3次的共享执行预算；不反复读同一被拒缓存、不叠加SDK重试 |
| 业务遗漏或歧义 | 继续有限核验，必要时显式修订/补源 | 不把业务问题当网络重试；不把“不再补读”当“问题解决” |
| 已发送但执行/回包不确定 | 保留sent/uncertain、原摘要与审计，先核对供应商结果或按明确授权建立新执行 | 不把丢失回包当未执行，不通过清缓存或改摘要自动重发 |

未知业务问题不能由代码判断无影响，已确认的来源/身份越界不能用容错变成合法证据。
但局部缺陷不应阻止无关来源和有效事项完成分析；最终确认仍依据真实未决问题。

## 按依赖安排实施

1. **先修产生问题的源头（023/024，守住001至004/022）。** Prompt分别写明conditions和
   exceptions；结构诊断保留具体字段/路径。有效核心事项不因可选字段错误整体消失，可能
   丢失的语义仍交独立核验。原文review用已有dispositions界定漏项目标，必要上下文照读，
   不新加一份让模型誊写的范围名单。回放4条异常声明和已存在联合体事项的反例。
2. **再减少重复任务（025）。** 在现有核验回包内表达既有问题续报及是否需要额外原文，
   宿主按问题身份组织一次补读。不增加独立分诊调用，不按code/关键词过滤，不把同来源
   的不同问题合并。字段与缺省行为只在[字段字典](field-dictionary.md#问题续报与按需补读)定义。
   原事项错误走显式修订；缺外部必要材料走补源；改变路由本身不清除任何业务阻断。
3. **并行校准预算，控制首批改动规模（014/021）。** 先核实模型/tokenizer和上下文口径，
   对照各操作真实输入、输出、耗时、失败及未知用量；按操作校准输出预留并重做完整请求准入。
   完成该校准前不因输入估算变小而扩大包。未核实时保留保守估算，不固定除以4，
   也不把16384当输出上限。报告全链路预计及实际累计开销，不增加用户未要求的费用硬门限。
   预算校准未完成不阻塞前两项修复；扩大单包前同时检查输出及长上下文理解质量。
4. **后做有对照证据的压缩与合批（025/026）。** 保留全台账发现及现有跨组范围作为基线。
   仅discovery延后引文是候选实验，须比较候选召回、误报、下游加载量和总用量，再决定采用。
   不根据单文件21→10包直接推广，不创建新的摘要事实表。先减少不必要候选；暂不把独立
   问题塞进同一associate/joint，避免一条finding牵连全包决议。接受边界未明确前保持分开。
5. **完成验收和运行闭环（005至013/015至020/022）。** 固定协议回归、隔离PG/Redis恢复、
   真实模型与人工语义核对分别报告。追加本次暴露的补读路由/候选发现案例，原28个review
   样本不能代表这些能力；付费评测复用现有客户端、审计与用量，不直连绕过围栏。
   新执行冻结新协议，旧运行和成功回执保留，部署及实测见交接；不在途热换Prompt。

## 暂不采纳的做法

- 取消跨组发现、按领域/关键词/数字正则筛掉比较：尚无证明不漏跨章节冲突的替代方式。
- 让一次全局摘要取代完整原文核验，或默认text等价于原始引文：当前容量和语义证据均不足。
- 一律重试所有失败，或把同一成功回包再读三次：分别破坏付费不确定性边界或无法产生新答案。
- 为了运行到analysis-ready而删除问题、自动确认、扩大作用域或用Decision覆盖错误原项。
- 只看单包fits、只比较locate数量、仅增加并发：无法解决输出负荷和下游累计开销。

## 成熟方案对照与三个交付批次

参考官方文档的设计模式，复用现有实现，不引入第二套Agent运行时：

| 参考 | 可借鉴的机制 | 本项目落点与边界 |
| --- | --- | --- |
| [LangGraph workflows and agents](https://docs.langchain.com/oss/python/langgraph/workflows-agents) | 固定顺序用workflow，动态问题由模型判断后路由；orchestrator-worker适合无法预先确定子任务的场景 | 五节点已经确定，保留StateGraph；在既有核验调用内判断补读需求，不增加supervisor/分诊调用 |
| [LangGraph durable execution说明](https://docs.langchain.com/oss/python/langgraph/functional-api) | 持久保存非确定性调用及副作用结果，恢复复用已完成结果；未完成的任务可能再次执行，需幂等设计 | 复用现有_save、CAS、租约和付费回执；checkpoint本身不能保证供应商只执行/计费一次，sent/uncertain仍单独保护 |
| [Pydantic AI output validators](https://pydantic.dev/docs/ai/core-concepts/output) | 将结构校验的具体错误反馈模型，并限制纠正次数 | BUG-010已经采用此机制，不另叠加框架重试；结构纠正与业务修订分开，业务正确性仍独立核验 |

“模型选择需读的来源，宿主按引用取正文”是上述职责划分在本项目的应用，不是这些框架
保证招标分析完整的结论。也不照搬自由工具循环、按类别多Agent或无限评审直到通过。

| 交付批次 | 修改范围 | 验收结果 |
| --- | --- | --- |
| A：先保住有效数据、消除误报 | extract Prompt与局部规范化、verify Prompt/本包完整性边界；同步字典、诊断和BUG-016文档 | 4条合并字段反例可保留有效核心及疑点；已有联合体事项不再因只出现在上下文误报漏项；真正漏项仍可发现。原包回放+相关单元回归 |
| B：减少无效任务、明确预算 | Issue两项可选信息、短引用、analysis共同任务/路由、现有回执与用量；评测输入同步 | 同一问题续报共享任务、记录不合并；false阻断问题进入本地处理，提示无需额外调用；Decision不连带清除续报；未知只兜底一次。隔离PG/Redis恢复+新语义案例+同文件实测 |
| C：验证后采用进一步优化 | 仅发现阶段的引文延后实验；候选执行合批另需独立接受边界 | 对照跨章节冲突、范围例外、评分与否决等真实语义结果，比较所有阶段成本；无证据不取消跨组覆盖。不是A/B实施前置条件 |

A/B中的schema、Prompt、发送视图和执行快照一起审查，避免再次出现局部改协议导致
缓存/预算/回包不一致。当前运行作为基线保留，待新代码和回归具备可审查结果后再安排
部署切换；不为验证某个失败分支故意破坏真实回包或强制制造付费失败。

实施完成的判据是：已发现反例得到修正，未决事项仍可追溯；原文覆盖、跨章语义及付费恢复
没有退化；全阶段用量和耗时可比较。真实流程到待确认或具体业务未决时如实展示，最终
analysis-ready仍需要有效人工确认。详细用例见[验收](acceptance.md#ab专项验收合同已验证真实语义待验)。

## 实施方案收敛：复用记录，减少额外机制

继续审查后，将上述“观察”落实为现有Issue记录，不新增Observation对象、观察版本或
独立状态机。合法related_issue_ids只决定共同处理任务；每条记录的身份、blocking及决议
接受仍沿用现有机制，Decision不得递归清除关联记录。这样既避免重复补读，也避免为了
防止旧决议清除新意见再维护第二套身份与快照。字段语义以字典为准，本节不重复定义。

false不能统一变成两次付费调用：现有策略允许的非阻断提示只展示；阻断且原文足够时
复用本地associate/joint，需改原事项时保留明确修订入口。所有本地和定位候选收齐后再
统一分组，不能先执行本地任务、后因discovery又执行一次。同一章节不构成问题同一性。
原文review后冻结本轮问题计划；后续新finding保留但不追溯重排或递归补读。

预算校准复用已有回执，先离线重规划、再冻结候选配置做独立真实样本验证，通过后用于后续执行。
下游候选尚未生成时调用量明确标未知，不能承诺全程上限；预算计入本地处理与失败纠正。
首批A仍是可独立验证的最小交付，B的字段、路由、决议和恢复一起交付，避免只部署过滤器；
C仍为后续实验。完成既定反例、恢复和真实文件验收后再按新证据调整，不扩充通用Agent框架。
