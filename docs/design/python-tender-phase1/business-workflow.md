# 第一阶段业务工作流：完整分析招标文件

## 目标、范围与当前状态

**输入完整招标文件及附件、澄清、补遗，输出经过核验、可追溯的招标事项台账。**
本阶段分析招标文件规定了什么，包括评分标准、资格条件、否决条件及其他业务要求。
原文明示的填表字段、证明材料、方案应包含的内容、签章和提交要求均属于分析范围。

企业响应数据、材料准备待办、响应动作、响应计划、加分取舍、实际得分、投标正文生成和
最终导出不在本阶段。输入缺少企业证书或实际人员资料，不构成招标文件分析的来源缺口；
缺少招标文件引用且理解规则必需的附件，则必须记录并阻断完整分析。

本文规定流程，所有字段、类型、可选性和枚举以[唯一字段字典](field-dictionary.md)的目标 v2 为准。
**五节点、新事项协议和 `analysis-ready` 已实现并部署；完整真实语义验收尚未完成。**
新入口确认后结束分析，不再推进旧Plan；旧运行记录及独立工具保留原义。
运行、测试及部署事实统一见[交接](handoff.md)，本文不重复维护实时包数。
下一修订的优化方案见[问题全量复审](bug-fix.md#全量根因复审与统一优化方案)，
拟新增字段只在字段字典的设计章节定义，不属于当前已部署合同。

## 分析范围由来源决定

下列内容用于阅读和查漏，允许交叉，不是固定节点或封闭业务枚举；原文没有的内容不补造。
项目身份、标段、采购对象和文件版本作为来源上下文保留，说明性文字不强行转成义务。

| 内容 | 需要保留的来源信息 |
| --- | --- |
| 资格及实质性条件 | 企业/人员资格、资质、业绩、信用、联合体及适用条件 |
| 评分标准 | 对象、指标层级、分档、公式、加扣分、分值/上限、计分条件和证明要求 |
| 否决及其他后果 | 触发条件、作用范围，区分否决、无效、不得参与、扣分、不得分和履约责任 |
| 技术及方案 | 参数、性能、标准、方案内容、实施措施、测试及证明要求 |
| 交付及验收 | 范围、数量、进度、交付物、验收方法及条件 |
| 服务及售后 | 响应/到场时限、维护、培训、保修、备件及例外 |
| 人员及组织 | 角色、数量、资格、经验、在岗要求及原文明示的人员信息字段 |
| 商务及报价 | 价格组成、税费、支付、保证金、有效期、合同及履约条件 |
| 文件及提交 | 内容、格式、表格字段、附件、签章、份数、提交方式、期限和程序要求 |
| 适用范围与修改 | 标段、主体、条件、例外、跨章引用、澄清及补遗的具体修改范围 |

例如“人员表填写姓名、证书编号并附证书”须完整收录，但不填写实际姓名或生成收集证书的待办。
“持 B 证加 2 分”须收录规则及证明要求，不决定是否争取、不预测企业得分。

## 五个主节点与放行条件

**登记文档集 → 解析冻结 → 统一分析 → 独立核验 → 人工确认 → `analysis-ready`**

| 节点 | 输入与产物 | 放行条件 |
| --- | --- | --- |
| `register` 登记 | 主件、附件、澄清/补遗的身份、版本、角色及已声明关联；来源清单和缺件问题 | 原件已持久保存、身份可追溯；缺件不能悄悄排除 |
| `freeze` 解析冻结 | 规范正文、章节、表格/合并关系、实际图片 OCR、附件位置、可用性目录及解析缺口 | 可读范围可先完成；必要来源缺口保留，不允许最终确认 |
| `extract` 统一分析 | 带必要上下文的小批原文；输出统一事项、逐范围处置、候选关联和未决引用 | 宿主组织完整逐范围处置；局部回包缺陷保留有效结果和待核对问题继续 Verify，不把本包不可见判成全文缺失 |
| `verify` 独立核验 | 完整来源和抽取结果；固定 locate/associate/review 子操作发现跨源候选、有限补读并独立核对事项和决议 | 全源及事项/关联/决议覆盖完整，候选已联合审阅；必要来源、作用域、冲突或语义问题未决则 blocked |
| `confirm` 人工确认 | 展示来源、事项、评分/后果规则、关联及问题，逐条处理剩余语义疑点并确认当前版本摘要 | 无硬阻断、每个语义疑点均有驳回或保留的人工结论、确认与当前来源/领域修订及核验结果一致，提交确认回执后进入 analysis-ready |

结果视图由来源、事项、核验产物及确认回执组装，不增加报告生成 LLM 节点。
无需为人员、评分、技术等分别建立 Agent，也不引入主 Agent 自由选择后续工作流。
阶段内只执行有固定输入、产物、预算和独立回执的候选发现、补读关联与核验子操作；
没有已知问题不意味着可以跳过全台账的跨源候选发现。

模型负责事项、证据选择及业务关系的含义；代码负责身份、原文定位、反向引用、分包、
预算、存储和推进流程。可恢复引文、冗余索引和可选数字细节不完整只记宿主诊断，
不使整包失败；无法追溯的声明交给独立核验，不由代码推断业务或静默删除。
具体容错边界统一见[字段字典](field-dictionary.md#回包容错与继续核验)。

## 统一事项与来源关系

事项只共享必要身份、类型、内容及原文证据；具体字段、可选细节及模型交换示例统一见
[字段字典](field-dictionary.md)。义务、评分规则、后果规则、文件及提交要求保留各自含义；
领域标签仅用于导航和查漏，不能据此排除其他类别的要求。

- 可选字段有原文依据才出现，不填占位；合法零分、零数量必须保留。
- 省略不证明原文没有、不适用或核验通过。含歧义、缺必要上下文或待解析引用时登记问题。
- 一段可产生多个原子事项并共享证据；拆分必须保留共同条件、分档、公式、封顶和作用范围。
- 关联记录评分针对什么、后果由什么触发、义务需要哪些原文明示的文件，以及补遗修改什么。
  只引用真实存在的事项并保留来源证据；未知目标先记未决，不从章节标题编造事项 ID。
- 部分补遗通过有证据的决议明确修改范围、全部保留内容及替代事项，纯删除不要求虚构替代。
  当前视图投影独立核验接受的决议，保留原项历史；不按发布日期自动覆盖，不靠宿主做范围相减。
- 适用性只分析原文的标段、主体、条件和例外，不判断企业是否符合，不记录评分采纳或准备完成状态。

例如“负责人须持 A 证；持 B 证加 2 分；未附 A 证复印件则否决”，应表达资格义务、
评分规则、文件要求及否决触发关系。不能把 B 证加分当作强制资格，也不能把否决扩大到所有人员材料。

## 一轮补读与独立核验

1. extract只携带本包正文、必要上下文及其章节信息，不发送全局目录。不在本包出现的内容
   不等于全文缺失。完整目录由宿主保存，后续reference定位时提供。
2. 全部抽取完成后，verify先执行原文review，独立读取所有必要来源及对应事项/处置，
   包括non_item/unresolved范围，检查遗漏、误解、条件、数字归属、评分和后果；保留具体问题。
3. 随后locate定位已知引用，并对完整事项台账发现可能冲突、修改、条件依赖或改变事项
   含义且台账尚未体现的跨包/跨文件组合。当前实现按容量组织块内/块间发现及问题合批，
   不按业务分类或关键词排除跨组检查。目录仅用于定位，不能作为正文证据。
4. 宿主仅从本次冻结材料装载候选的完整相关原文、条件及事项，保留每份来源身份。需要建立
   关联、解决问题或解释补遗时，associate 输出待验关系及 Decision，不能直接清除原问题。
   每个引用最多一次候选定位、一次带原文的补读关联核对；所有输入输出以字段字典为准。
5. 仅对提出决议的候选执行独立joint review，检查关联、条件、例外、数值关系、表头继承、
   评分、后果和补遗修改范围。只提出关系、没有决议的候选不进joint，关系标为模型提出、
   未独立核验。有决议的候选须有共同装载相关原文的联合核验回执，不能用分开请求的覆盖
   并集代替。决议须逐条审阅并明确接受；只有有效接受才能解决其绑定的具体 issue_id，
   未接受、反对或审阅失败仍保留原问题，不共享 associate 对话历史。
6. 目标找不到、候选有歧义、正文不可读、联合上下文超预算、含义仍不清或出现新引用链时，
   保留问题并转人工处理。不递归补读，不访问外部链接；人工须给出依据，必要时补充来源或
   建立领域修订后重新验证。漏抽或错项走显式纠错，不能由核验或决议静默改写。

来源覆盖声明由宿主检查，内容是否遗漏或误解由 LLM 核对及必要的人工裁决确定。
正则或关键词可提供定位线索，不能作为最终业务语义裁判。核验不静默改写抽取结果；
遗漏或错误进入具体问题，通过显式修订纠正并重验，不以模型空 findings 清除旧阻断。
晚发布补遗不自动全局覆盖原文件，必须有明确的修改对象、范围和来源依据。

下一修订先在上述顺序内消除多余工作：模型说明是否还需原文、是否续报已有问题；
宿主按具体问题组织一次补读，已知原文内的错项进入现有纠错修订。可用事项继续展示和核验，
问题不因“不需要补读”被清除。续报保留现有Issue记录，只共享处理任务；已知原文可用于
解释的问题直接进入本地associate/joint，纯非阻断提示不额外调用模型。Decision只解决
明确列出的记录，不连带清除续报。漏项检查目标、可选字段局部容错及缺省路由统一见
[下一修订字段合同](field-dictionary.md#问题续报与按需补读)。
本轮不增加自动反复修订循环；缺失必要外部来源仍需补充，确认不代替纠错或补源。

## 状态、修订与恢复

运行状态的枚举及含义以[字段字典](field-dictionary.md)为准。必要来源缺失、作用域未审议、
覆盖或预算等分析不完整的硬阻断使用 blocked；执行/协议失败使用 failed；核验完成且无硬阻断即进入
waiting-confirmation，剩余语义疑点由人工在确认时逐条驳回或保留，分级见
[问题分级与人工处理](field-dictionary.md#问题分级与人工处理)。
当前版本确认有效后进入 analysis-ready，不再执行响应规划。

运行状态、模型请求状态、子操作回执和业务适用性分别表达；不增加按业务领域的状态机。
模型请求 succeeded 或子操作有回执，只证明响应保存或产物提交，不证明业务核验通过。
当前工作区已按上述边界区分协议失败和业务未决；完整验证及部署状态以交接为准。

来源变化使用 source_version；同来源业务纠错使用 domain_revision，重新核验并使旧确认失效。
业务格式使用独立 schema_version，旧回包不自动满足新合同。问题决议绑定具体问题身份、
来源/领域版本、证据及处理结果，不能按 code 批量清除。

分包同时约束输入容量和输出工作量，完整事项及必要原文不能被截断。公共表头、规则和事项
可在独立候选间复用，不因此将其合成不可分大包；同一具体 issue_id 的多个候选须联合核对，
单个候选不得拆分。必要的完整联合上下文超限时明确阻断。
若唯一图像数为 U、抽取包 E、locate 批 D（含引用定位及跨源候选发现）、associate 批 A、
全部独立 review 包 V（含候选联合核验及决议审阅），则计划全部确定后的无故障调用数为
`U + E + D + A + V`，A/V含本地处理。候选未生成时A/V尚未知，不能将部分计划称为
全程上界。各阶段发送前固定实际批次和完整输入/输出预算，候选形成后的 A/V
在发送前更新计划与费用估算；新候选调用不能隐含在旧包数中，不包含响应计划调用。
块间组合的批次数可能随块数平方增长，须计入 D 和阶段预算；无法完成必要发现计划时
明确阻断并转人工，不以静默跳过组合控制费用。

成功回执和请求审计保留；所有调用失败包括uncertain共享单元首次加三次，可能重复计费，
详见[恢复合同](field-dictionary.md#失败执行的显式恢复)。仍在途的sent禁止并发发送，
新协议、重分包或改提示不能重置已有运行的重试额度。
旧运行记录及六阶段产物保持原义，不改名成已完成的新分析。每次部署与真实运行单独记录，
文档目标不代表对应协议已经部署或通过实测。

## 交付、实施与验收

最终交付为来源清单、完整事项台账、评分与后果规则视图、关联及问题/决议记录。
各视图投影同一台账，不复制维护另一份评分或风险事实；存在阻断时也保留可读取的局部结果，
但不能宣称完整分析。analysis-ready 不证明投标人合格、实际得分或投标文件已编制完成。

1. **文档先行**：统一本文、字段合同、状态、交接及验收入口，清楚区分目标与现行代码。
2. **合同与纵切**：工作区已同步实现共享schema、提示、抽取/核验、摘要/确认和结果视图，
   贯通五节点，不接入旧 Plan；不只改终态名称或增加几个字段。
3. **语义与恢复回归**：验证正反语义用例、一轮补读、跨文档关联、修订确认失效、成功复用和 uncertain 有界重试。
4. **真实文件验收**：保留既有来源/作用域问题，完成必要裁决后执行五节点；分别报告合同测试、
   真实模型流程完成情况和人工标注的漏检/误报，固定模型通过不等于模型业务能力通过。

首批验收包含：同句资格/评分/否决/证明关系；无评分不补造；分档/公式/上限及合法零分；
扣分、不得分与否决区别；条件、例外、表头单位继承；部分补遗修改；跨包引用补读成功或未决；
必要附件缺失阻断、缺企业响应资料不阻断；修订后旧确认无效。它们是回归场景，不是全部业务清单。

## 与后续投标编制的衔接（设计边界）

最终业务目标是根据招标要求编制投标文件，包含大纲、规定模板、匹配的知识内容及有依据的
响应。本节说明后续设计方向；一期仍以分析确认结束，字段定义仍由字段字典统一维护。

以下编制流程按[knowledge_required_v2合同](field-dictionary.md#编制最小修订knowledge_required_v2)
统一；源码、部署和真实验证状态见交接，不以文档修订声明已验收，不增加主节点或复杂状态。

编制以“持续形成可编辑投标文件”为目标：资料缺失、未确认、响应不足或复核问题均不
作为生成、保存或导出的业务门禁，原文明示必填信息也可先留空/待补。文件生成与内容
是否满足要求分别报告；原分析确认仍保留其含义，不伪造完成。编制固定可用资料快照，分析确认和资料齐备不作为编制入口；具体执行与真实验收状态见交接。

技术方案按适用标段收集当前可用的技术参数及标准、实施与验收、服务与人员、评分及证明、
实质性约束和格式规则，保留已知条件、例外及补遗。尚缺内容标注待补，不作为生成前提；
要求完整性作为后续质量核对目标。项目现状、现有系统、业务
规模等必要背景可以是说明性原文，不必强行抽成事项；后续按冻结来源引用装载。
不能只以技术章节或domains标签筛选方案输入，事项摘要也不能替代必要原文及表格。

### 已确定的业务流程

上传招标文件是业务起点；企业资料、知识库和产品信息可随时提供，不要求
全部齐备后启动。下表是业务顺序，不新增六个分析节点或六次人工审批。
最终报价、单价、总价、折扣等保留字段，最后由人工填写；招标预算、最高限价和评分
数字照常保留。已有历史价格不自动采用为本次投标价格，不影响其他正文继续生成。

| 步骤 | 做什么 | 可见产物及衔接 |
| --- | --- | --- |
| 1 理解招标 | 读取可用原文与分析结果，整理背景、要求、评分、文件格式和提交约束 | 可追溯要求及具体疑点；资料不全或未确认不阻止进入编制，后续可继续补充 |
| 2 搭建文件结构 | 按本项目规定确定分册、目录、表格和附件位置；已有大纲调用同时选择support_origins并产生search_intents | 缺资料仍保留完整结构；宿主绑定引用并联合来源/意图，混合表单不因依据类型复制，不要求先选产品 |
| 3 准备候选资料与共同依据 | 宿主执行由实际原文/规则规划的有限业务检索词，不发送要求JSON作AND查询；仅汇总有知识支撑的共同安排 | supports共享实际原文和知识，保留范围、产品/版本及可读证明依据；无企业知识仍可写来源支持的背景 |
| 4 分任务匹配并编写 | 单次write匹配改写，每个block/fill选择target_ids及support_ids，附件选attachment_ids；宿主管正式引用和原表 | 企业应答未匹配留空；背景/源文可确定填值可选tender支持，不能把要求写成我方承诺；未知价格始终空白 |
| 5 汇总与复核 | 检查实际应答、附件及有候选却完整判空的语义结果，b/f/a精确定位删除；有足够支持的正文或语义空稿可一次定向修订 | 初审仅接口失败保留U0待核；初审否定先形成S0，改稿失败/空回包/再核不可用退S0；保留各稿及缺口继续导出 |
| 6 交付文件 | 按规定分册组装可编辑文件，保留空位并提供对应缺口清单 | 可继续编辑的投标文件及剩余事项；生成成功不代表资料已齐、已满足全部要求或已完成外部提交 |

步骤2/3可交错；有本位置允许支持的任务进入4，完成一批可复核一批。support_origins
只决定允许的依据及调度，不证明语义正确；模型仍须判断背景、企业应答及支持关系。
全人工/全无允许支持空位不写作、不正文复核；写作传输失败纯空稿耗尽恢复后记录运行
原因。有候选但模型完整判断不匹配的空稿仍独立复核，不能按“无正文”跳过漏匹配检查。
步骤5是内容改进，不是放行审批；步骤6可组装已有成果，不要求先关闭全部问题。补充
资料或修改方案后，只更新相关位置及必要的一致性复核，不固定重跑整份分析/标书。
大文件的调用按完整业务单元及输入/输出容量组织，不能按总页数要求模型一次写完。
最小验收包括“缺信息仍能获得可编辑文件”和“缺口不被编造成已满足”，详细内容质量
另外核对，不把未填内容误判为整个生成失败。

### 补资料与重新生成

1. 一次资料补充或更新动作作为一批，汇总受影响任务后更新；不随每个新增片段或检索
   结果反复重写。已开始任务使用固定快照，新资料用于后续更新，不增加确认或审批步骤。
2. 同一业务事实在多个位置使用时，补充一次即可更新相关内容；按已有引用及适用范围
   关联，不能只因字段同名就跨标段合并。实际文件中需要重复出现的响应位置仍然保留。
3. 重新生成另存新稿，保留原稿和已有修改，说明本次更新范围。首版不做Word人工修改
   自动合并，也不承诺识别尚未读取的外部编辑；无需增加编辑器或通用版本管理平台。

以上属于原步骤的操作规则，不增加业务阶段或固定模型调用。更新批次按受影响任务
去重后处理，保持原输入/输出预算；共享事实联动及新稿保存由宿主管理，模型不回抄名单。

全过程须可追踪“来源事项／评分点 → 响应位置 → 采用的内容与证据 → 生成结果”。有章节
标题不代表已回答要求，检索命中不代表企业满足条件，文字齐全不代表实际得分。
语义匹配、响应充分性和证据适用性由模型及必要的人工判断；宿主管理身份、引用、版本、
来源装载、覆盖及执行。企业资料不足不改变招标要求，不用生成文字冒充证书、业绩或测试结果；
缺口随受影响内容展示，其他独立章节可以继续起草。

招标规定模板中的固定文字、表格结构、字段及签章位置须保留来源；企业写作模板用于组织
内容和样式，不覆盖招标规定。先在Python中完成分析到编制的闭环，复用分析台账，通过
引用读取必要原文，避免固定再做一轮全量要求抽取；编制消费当前可用资料的固定快照
独立启动，原有确认结果可作为依据但不作为入口开关，不在confirm后增加必经第六节点。

业务上，一项要求可能同时涉及方案、偏离表和证明附件，先用真实样例明确必要的响应位置
及引用，不先新增通用映射框架。Rust、API及页面接入后置，届时再核对既有合同及适配差异；
本轮按[Python闭环任务规划](implementation.md#python投标编制闭环任务规划独立于一期)推进。

技术响应以功能如何满足及实现方案为核心；品牌、型号、版本和配置为可选补充，不作为
写作前置，也不新增选型确认门禁。能匹配则采用，缺省时继续编写有依据的功能方案；
原文明示某处必须填报时仅保留该处待补，不编造事实、不暂停其他内容。规定骨架、知识
匹配与有允许支持的独立写作任务可并行。v2合同统一supports/support_ids，
宿主适配为持久material_ids及新增source_refs，不迁移全部旧稿。source_id仍指原表，
同表不同格可取不同来源；不以proposed或approach兜底生成企业方案。真实附件须有
可判断证据，未读原件不能仅凭标题选入，content_ids中的a1只移除该附件。
U1按自身内容重新分配b/f/a别名，U0旧序号仅用于历史定位，不直接删除U1。
四项语义职责、skill边界、共同依据及
完整交付验收见[编制架构草案](authoring-architecture.md)，正式结构见字段字典，实际验证状态见交接。

### 调用、预算与修订约束

1. 全文件模型调用按`N_分析 + N_大纲组织 + N_依据准备 + N_正文生成 + N_编制核对 + N_重试纠正改稿`
   分别计量。分析沿用上文公式并包含其重试及两两发现的规模风险；编制侧按首次发送批次
   计量，失败重发（含uncertain）、合同纠正和业务改稿另计，成功缓存复用不增加发送。
   v2编制L=O+B+W+R+C+R2，R/C/R2≤W，故L≤O+B+4W；付费发送上界沿首次加三次为4L。
   大纲O含support_origins/search_intents，语义匹配包含在W，不增规划或匹配轮；
   全无允许支持和人工位置不计W/R，有招标来源支持的说明可写，有候选的语义空稿仍计R。
   知识查询Q次按首次加三次最多4Q次HTTP尝试，无命中/不适用不重试至命中。后续批次及纠正上限须在
   纵切设计中确定，未知项不记零，不承诺全流程线性增长或提前给出费用上界。
2. 单请求按完整提示、相关要求与规则、必要来源和表格、采用资料及实际输出工作量准入；
   引用让宿主按需装载，不能代替模型需要理解的内容。按章节任务预算输出，不能只核算输入，
   也不能未经实测沿用分析输出预留；输出包括大纲检索意图及逐block/fill目标和support引用，
   supports中必要原文/知识仅发送一份。检索词最长256字符不等于限制原要求，完整不可分任务
   超限时记录待调整任务，不静默删约束。
3. 来源不清或事项错误沿分析修订出口处理；资料缺失由用户补充或选择有据替代；模型保留
   匹配歧义及响应不足。本次先留空/待补并继续生成和导出，不等待修订或补齐；补充后
   复核相关内容。明确无依据才移除，初审接口不可用保留尚未否定的U0待核；初审否定后
   形成S0安全稿，修订失败或再核不可用退S0，不让已否定内容复活。各稿及回执保留，
   不把未核对写成缺资料，不增加业务状态机或循环重读。
4. 同一分析修订下的样式修改不触发重新抽取；来源或领域修订按现行合同重验并使旧确认
   失效。后续根据实际引用依赖及完整请求摘要确定重跑范围，公共选型或承诺变化须复核所有
   受影响章节，不能预先承诺只重跑一个章节或静默沿用旧稿。grounding_policy进入
   basis/write/review真实请求及执行spec，新策略不能静默采用旧策略无依据正文。
   v2改变已有outline输出，旧106页样例的17份来源回包不能直接复用成新意图结果，
   须重新预审O及费用。后续明确重审用新执行继承前驱，真实理由进入请求；同ID完成稿
   不覆盖，不清缓存或加盐。单query回执仅在范围/知识版本可证明一致时复用，目标重新绑定。
5. 模型只判断语义关系、选择相关内容及生成回答；宿主持久绑定引用并派生任务覆盖和反向
   索引，不要求模型重新誊写已知来源元数据、完整章节名单或覆盖清单。

### 最小纵切验证

先选同一真实文件中的“技术条款＋方案评分规则＋技术偏离表”，追踪其分析结果如何进入
大纲、表格、知识证据和最终正文，同时保留必要背景、缺材料及响应冲突的处理结果。
分别核对要求有无遗漏、方案是否具体回应、评分依据是否展开、表格和证据能否回溯；
不能仅以结构通过验收。真实材料及调用证据保存在仓库外的私有证据目录，仓库只保留合成示例。
用这条业务链确定最小对接字段及是否需要跨章目标扩展，再实施后续协议。
