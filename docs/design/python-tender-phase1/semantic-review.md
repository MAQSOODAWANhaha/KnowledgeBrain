# LLM 语义职责与宿主规则审查

## 状态与范围

最新一期目标收敛为**完整分析招标文件**：register → freeze → extract → verify → confirm，
终态为 `analysis-ready`。该五节点及v2事项/核验协议已实现并部署，真实调用正在验证；
部署和执行快照统一见[交接](handoff.md)。下文保留此前规则审查的历史证据。字段以[唯一字段字典](field-dictionary.md)为准，
职责和接口见[领域合同](domain-contract.md)。

分析包括评分、否决、技术、服务、售后、人员等源文事项，以及明示的填表、附件、签章和
证明要求。本期排除企业响应数据、响应计划/动作/准备待办、评分采纳和实际得分；计划生成
及独立计划审阅均不属于本期后续任务。

统一事项仅必填 `item_id/kind/text/evidence`，kind 为 `obligation`、`scoring_rule`、
`consequence_rule`、`submission_requirement`。其余业务信息有来源才输出，没有则省略，不用空
对象、`null` 或“无”凑字段；省略不能当作语义已经核验。无法判断的内容通过外部问题或
待解析引用保留。先全源发现，再针对具体问题作有限处理，不先按业务类别路由来源。

新主线使用统一事项抽取和独立locate/associate/review，宿主校验结构、来源、必要覆盖、
版本和执行事实，不再调用下文旧要求反查、冲突/整条失效推断及响应计划工具。它们仍在
源码中作为历史独立工具保留。新分析路径的SupportingIndex仅用语言命中选择上下文候选，
不自动绑定作用域、制造pending或产生语义阻断；有证据的人工scope_decisions仍可绑定。
scope审议校验非空理由、来源证据及真实目标，不要求理由命中特定词表；CLI使用当前核验
中的范围问题，不按问题code猜测其语义。parser及旧路径仍有历史启发式，不能宣称已彻底移除。

五节点迁移时完整Python回归896 passed / 15 skipped，包含隔离PostgreSQL/Redis及确定性模型
验收；后续A/B回归和定向真实验证见[交接](handoff.md)，完整业务语义及人工验收尚未完成。下文保留
基于 `2ad480b` 的历史实现审查、合成样本和离线引用检查事实，旧测试及wire证据保持原义。

## 职责边界

| 承担方 | 职责 | 结论的边界 |
| --- | --- | --- |
| Extract LLM | 从全部来源统一发现四类事项，理解义务、评分、后果、提交要求及其对象、条件、例外、数值和关系，逐来源处置 | 模型抽取是待核对结果，不因某类业务无字段而补造信息 |
| 独立 Verify LLM | 重读完整来源及必要上下文，核对遗漏、数字归属、比较关系、作用域和适用性 | 独立调用不保证无漏检，须用标注样本评测 |
| 宿主 | 校验结构、身份、来源定位、引用覆盖、版本、预算、回执和执行状态 | 格式、引用或摘要有效不等于语义正确 |
| 人工复核 | 裁决来源歧义及语义争议，提供有证据的标注与审议 | 确认不能覆盖未解决问题或来源缺失 |

自然语言的业务含义由带来源上下文的 LLM 审阅及必要的人工裁决确定。正则可以处理
约定格式、定位文本或提出审阅线索，不能凭关键词命中、字面重合或未命中来最终判定
自然语言语义正确、错误或不存在。不得通过继续扩充比较词、动作词或作用域词表，
把当前实现扩展成通用语义判定器。

语义疑点需有明确审阅结论；未解决时保持未决。宿主问题按当前协议保留阻断，
不能将其改名为格式提示或仅凭 `findings=[]` 清空。决议及修订须可追溯，保留来源、问题
和结论，重新验证并使旧确认失效。缺失原文或只有 pending
定位元数据时，LLM 不能代替补齐来源。语义审阅也不能豁免结构或身份校验失败。

跨包目标只作一轮补读与核对，目录只说明可供补读，不等于已经收到目标正文。目标缺失、
有歧义或补读后仍无法判断时转人工裁决，不递归追索或自动循环修复。裁决需要具体问题、
当前版本和来源证据；修订后重新核验，不能按问题 code 批量清除未决项。
目标输入输出以字典的 locate/associate/review 为准：定位及关联核对只产候选与待验决议，
独立 review 明确接受具体 Decision 后才生效。完整台账还须发现无显式引用的跨源候选，
联合判断读取全部相关原文；ID 覆盖并集不能代替联合核验。补遗保留/替换/删除的含义由
LLM 或有证据的人工裁决给出，宿主不计算自然语言范围差，也不改写原事项。

运行状态中，`failed` 表示执行或协议失败，`blocked` 表示业务未决或必要来源缺口；仅在
独立核验完成且无阻断时进入 `waiting-confirmation`。确认精确绑定来源/领域版本与清单摘要，
不能代替问题解决，确认后为 `analysis-ready`。模型请求成功、子操作有回执和命令完成
各有独立含义，不代表分析语义通过；成功产物和 `uncertain` 付费围栏均继续保留。

## 历史六阶段流程的实际能力（计划部分不属新一期）

- `verify_pack` 先运行局部规则，再对可发送的完整输入调用独立 Verify LLM，合并两者问题。
  单独的 `check_requirement` 返回无问题不代表完整流程已经放行。
- 人工确认在 Plan 之前。Plan 当前调用生成模型后只做宿主检查，没有独立的计划语义审阅；
  上游人工确认不能解释为已确认尚未生成的计划。
- 当前 `Task` 仅有 extract/verify/plan/ocr。本轮不新增调用类型或审阅循环。
  原先拟议的计划语义审阅已移出本期范围，不以补齐它作为新一期分析流程的验收条件。

## 历史宿主校验与保障边界

下表记录旧六阶段工具的校验及可验证范围，不表示每项仍在v2主线执行。新主线在
`_normalize_items`及`checks/analysis.py`核对结构、原文引文、逐范围处置、操作覆盖和决议
目标；版本、回执、预算及发送围栏继续保留。这些保障不要求模型重新解释约定格式。

| 位置 | 当前校验 | 可证明的范围 |
| --- | --- | --- |
| [schema.py](../../../services/docreader/tender/schema.py) `Contract`、`ArtifactRef` | 字段/类型/枚举、摘要格式、内容寻址路径一致性 | 协议和产物身份有效，不证明正文含义 |
| [extract.py](../../../services/docreader/tender/requirements/extract.py) `_normalize_extraction` | body 处置恰好一次、ID 唯一、引用列表与 evidence 关系一致 | 回包结构完整；逐范围处置不证明范围内部无遗漏 |
| [verify.py](../../../services/docreader/tender/checks/verify.py) 引文与来源检查 | range 存在、引文为精确非空子串、至少一处 body 证据 | 引文可定位；截短引文仍可能遗漏比较词和条件 |
| `verify.py` `reviewed_counts`；[aggregate.py](../../../services/docreader/tender/checks/aggregate.py) 覆盖检查 | 审阅 ID、包、处置和要求引用恰好覆盖 | 审阅声明完整，不证明模型理解完整 |
| [scope.py](../../../services/docreader/tender/evidence/scope.py) 来源/目标检查 | 决议对应当前问题、证据覆盖该条件、目标为同文档 canonical 范围 | 决议可追溯；不能证明 bind/local_only 的解释正确 |
| [constraints.py](../../../services/docreader/tender/planning/constraints.py) 摘要检查；[plan.py](../../../services/docreader/tender/planning/plan.py) ID 检查（现行计划合同） | 摘要与宿主快照一致，每个适用要求对应一个计划项及持久引用 | 绑定正确，不证明 action 忠于原文；现有快照还含启发式解析值，不纳入新一期分析目标 |
| `verify.py` 明确 `scoring.total/components` 的 Decimal 合计 | 结构化数值有限且合计一致 | 算术一致；合计关系是否由原文明示仍需语义核对 |
| `schema.py` 等级策略；llm/workflow/integrations | 问题最低阻断级别、预算、租约、版本、回执、确认失效和发送围栏 | 保留执行保障；语义审阅不能直接撤销这些约束 |

来源引文的空白容差是独立的定位协议调整，不是语义审阅替代品。后续若实施，必须保留
原文片段和可追溯位置，检查歧义并让后续校验使用一致的解析结果；本轮仍为精确匹配。

## 历史自然语言规则清单与后续处理

下列规则记录历史行为；新主线已退出旧要求反查、聚合及规划路径，上下文词表只提供候选，
来源解析及旧路径仍保留语言启发式，不能将“已列入审查”解释为已全部删除。
涉及 `constraints.py` / `plan.py` 的条目保留现行计划规则及历史局限，其“后续”只说明未来
若恢复计划业务应重新审视的职责，不属于本期实施或验收任务。

| 位置 | 当前实际行为 | 后续处理目标与评测重点 |
| --- | --- | --- |
| [context.py](../../../services/docreader/tender/evidence/context.py) `_navigation`、`_segments` | 用标题/标点/换行模式判断导航和条件句界，影响上下文候选 | 区分原生结构与启发式线索；核对目录、视觉换行、跨段条件及漏选上下文 |
| `context.py` `_scope_role`、`condition_context` | 用条件/替代/范围词表选择候选；部分直接绑定章节，其余产生 `condition_scope_unresolved` | 候选词不能决定最终作用域；由完整来源的语义审阅和显式决议支持绑定，核对误绑定、漏绑定及假阻断 |
| `scope.py` `_GENERIC_RATIONALE`、`_LOCAL_BOUNDARY`、`_LOCAL_BASIS` | 理由命中特定词表或缺少词表内容时，拒绝人工审议提交 | 保留非空理由和证据/目标校验；理由是否充分交给语义审阅与负责裁决的人，不要求特定措辞 |
| `extract.py` 非要求理由词表 | 理由等于“无要求”“空白行”等字符串时改为 unresolved 并阻断 | 保留逐来源、有依据的处置要求；理由充分性由上下文审阅判断，覆盖简短但充分及长篇但空泛的理由 |
| `verify.py` `NUMBER`、`UNIT`、`numeric_values`、`_number_supported` | 数字集合及数字/单位的局部文本反查失败时阻断 | 可作为局部核对线索，不能证明数字归属、比较关系或单位继承；用完整证据上下文评测漏检和误报，不新增通用三元组正则 |
| `aggregate.py` `_conflicts` | 同对象/条件/例外、去数字后同文而数字不同，产生阻断性潜在跨文档冲突 | 为跨来源审阅提供候选；措辞相同不证明冲突，措辞不同不证明无冲突 |
| `aggregate.py` `_apply_amendments` | 校验显式替换目标后，按目标范围及替换文档要求生成 applicability 决议 | 保留目标身份、环及缺失引用检查；复核“整条失效/部分替换”的业务推断，不能只凭存在替换文档要求证明语义覆盖 |
| `constraints.py` `_relations`、`_quantities`、`_obligation_quantities` | 词表推断比较关系，并据此阻断计划中的数值/单位/关系差异 | 历史计划范围：词表不能证明计划保真；不扩充比较词表，本期不实施计划审阅 |
| `constraints.py` `_literal_preserved` | 要求 action 字面保留对象、条件、例外，并用邻接否定词排除部分匹配 | 历史计划范围：字面重复不证明语义保真，正确改写可能误阻断；本期不评审企业响应动作 |
| `plan.py` `PLACEHOLDER`、`GENERIC_ACTION`、`LOCATION`、`FIELD`、`ACTION` 及无需材料理由正则 | 用指定词、分隔符和措辞判定位置、动作及材料说明是否具体，产生阻断问题 | 历史计划范围：关键词不能证明具体性或充分性；本期不生成位置、动作或准备待办 |

[view.py](../../../services/docreader/tender/evidence/view.py) 的空白模板压缩只改变发送表示：
模板行仍需模型结合表头及条件逐行处置和独立审阅。只有已证明的空白页或有显式审议记录的
装饰图片进入 `host_reviewed_ranges`；不能将空表格自动判为无义务。

## 已复现事实与未验证部分

历史审查提取当时的纯函数做过以下最小复现；该轮未运行完整pytest，也未调用真实模型：

- `check_requirement` 无法单独发现正文把“30天、60万元”写成“60天、30万元”而 `numbers`
  仍保留正确配对的情况，也无法单独发现“至少”改成“至多”。这不证明独立 Verify LLM 会漏检。
- `_quantities` 把“不大于30天”识别为 `gt`，把“不超过30天”识别为 `lte`；现有词表不是可靠的
  通用语义解析器。
- 对上述单位互换、结构化 numbers 正确的样例，现有 Plan 规则会拒绝沿用错误正文的 action。
  摘要不能纠正上游错误，但也不能据此断言下游必然按错误配对执行。

## 分析阶段后续任务与成功标准

1. 准备正反语义样本：数字/对象串位、比较反转或遗漏、条件/例外遗漏、表头单位继承、
   等价改写、补遗部分替换和跨文档冲突。记录来源、上下文、预期结论及人工裁决；
   模型自评不能充当人工 ground truth。合成样本与真实文件标注分开。
2. 用现有独立 Verify 做语义评测，分别记录原始 LLM findings、宿主问题及聚合结果。
   对错误样本报告漏检，对正确样本报告误报与宿主误阻断；不靠移除困难样本改善指标。
3. 用统一四类事项合同覆盖评分分档、否决条件及明示的填表/附件/签章/证明要求，保留源文
   可选信息和待解析引用；对具体复杂问题作一轮补读核对，仍未决则人工裁决。
   不增加通用 supervisor、业务分类预路由或无界自动修复循环。
4. 根据评测调整最少的输入/提示/审阅协议及规则职责。语义样本和结构/覆盖/恢复回归均需
   核对；旧测试若只固定关键词或逐字复制行为，应按修订后的合同重评，不能直接改成宽松放行。
