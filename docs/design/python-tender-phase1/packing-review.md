# 分包设计评估：结构优先，完整请求容量准入

本文件先于最终分包算法改写提交。结论已按父任务收敛：**最小完整章节/连续原生章节范围
适合作为优先语义单元，但不是唯一结构类型、固定长度块或一次模型请求。结构决定边界，
完整请求 token 容量决定是否需要拆分。** Rust 仅只读借鉴合理主干，不改源码/依赖/执行链路。

## 为什么采用，以及适用边界

相比固定字符块，章节通常保留一个义务的对象、条件、例外及相邻表格；强制按长度切会把这些
拆开。但“最小”不能解释为只取最深叶子标题：父章直属正文、标题前前言、章节之间附注都必须
拥有唯一正文归属。也不能把章节看作完全自足，父条件、引用和表头仍是有来源的依赖。

| 来源形态 | 优先语义单元与边界 | 不能做的假设 |
| --- | --- | --- |
| 有可靠章节的正文 | 文档顺序中的连续 section_id 所有直接正文/表格/图片载体；子章另有归属 | 不能只保留叶子而丢父章正文，也不能把整棵父子树重复计正文 |
| 导语、父条件 | 本身仍归属原正文范围；后续需要的完整来源片段作为support，明确适用目标 | 祖先所有正文不等于适用条件；optional候选不等于已解决作用域 |
| 无标题前言/附件 | 使用可靠原生文档/段落/表格区域，不虚构标题；完整附件能装下就不先切 | 无标题不意味着可丢弃，也不按页数/字符数强制切 |
| Excel | 可靠worksheet、table/region、row group及原锚点表头；不同表保留身份和归属 | worksheet不必等于一个包；不能把无标题表改造成虚假章节 |
| 多文档引用 | 独立文档保留身份；只有明确可追溯关系允许相关范围合包，否则分开并保留引用待核 | 同一项目、上传顺序或晚文件不代表作用域关系 |
| 单巨表 | 整结构实际超限后按行组、必要时单元格拆，保留合并关系和完整必需表头支持 | 不先按固定行数/列数碎片化，不擦掉空字段语义 |
| 单巨段/单格 | 只有单结构仍超限才沿句/段界细拆，最后Unicode安全边界；保留原坐标与片段链接 | 不在来源登记时先按6000字符拆碎再把碎片当请求原子 |

## Rust 到 Python 的规则对照

| Rust只读事实（相对仓库根） | Python采取的规则 / 差异 |
| --- | --- |
| `crates/bidding/src/outline/discover_planner.rs:680` 按同document、同section_id连续atoms分组；`discover.rs:2496` native id/ordinal/heading fallback | 按原生归属及顺序分组，保留父章直接正文；不筛leaf，不虚构未识别标题 |
| `discover_planner.rs:593` 完整章节前缀；`:448` 同文档相邻/明确跨文档endpoint关系 | 先尝试合法邻接结构合包；合包不是全局最少包优化，独立文档不默认合并 |
| `:641` 小章合并，单完整章实际失败后 `:739` 才章内结构回退 | 不设字符、页数、原子数最终包上限；每个最终候选都通过完整请求估算 |
| `:283` 句界/UTF8细拆；`:304` 表格行→格→格内文字、保留表头 | Python保留既有字符坐标语义与Unicode安全边界；原grid/合并关系保持不可变 |
| `:476` frozen bytes只作hint；`:606/:711` 累积索引复用、避免反复复制全量尾部 | 来源/支持索引与序列化权重一次准备；测得权重仅帮助选候选，每个最终完整请求仍复验 |
| `agent.rs:2227` 实际request probe；`agent_runtime/chat/tokenization.rs:247` 全body估算 | Python规划和发送共用同一request构造/预算函数，包含真实prompt、消息、schema/response_format、正文、全部必需support及必要图片 |
| Rust部分required support只先探测首个交付页，后续还有自动交付/读取回执 | **不照搬**。当前Python没有后续交付节点，一次extract/verify必须带齐必需support；未知范围用待审引用并阻断，不能只计首段冒充完整 |
| Rust祖先/同章正文包含optional支持候选 | **不照搬为已解决条件**。明确范围才绑定；关键词候选不直接变成全章条件，需诊断真歧义/启发式假阻断 |
| Rust旧纠错窗口可扩大 | **不照搬**。本次普通及纠错均受服务实际支持C约束，不默认为2C |

## 请求预算和执行规则

普通 `C=131072`。沿用已读合理默认：安全预留4096、内部响应预留16384，每张实际发送图片
估计16384；消息/工具framing也计入。响应预留仅供准入，**不发送max_tokens输出硬上限**。
未知模型tokenizer继续明确标记保守UTF8字节估算；估算身份、prompt摘要、model、C与预留
随配置固定，不能称为真实usage。`gpt-6-luna`在已读Rust同样没有tokenizer的精确名单映射。

1. 原件冻结保存完整原生结构。定位索引可按行/段持有坐标，但不按索引片段大小决定请求包。
2. 建立连续原生章节/结构范围及其必需支持索引；保留正文唯一覆盖，支持不重复计覆盖。
3. 文档顺序提出完整合法邻接候选，用实际完整请求估算准入；失败才缩小完整章节前缀。
4. 单完整章节仍失败，先子章/条款/段落/行组等可靠结构；单结构仍失败，才文本细拆。
5. 每个最终包记录章节/结构身份、边界原因、split lineage、完整request输入估计、预留、C、
   token估算方法与准入结果。不可再拆且完整必需支持仍超限，明确问题，不裁掉支持后假通过。
6. 验证/计划加入真实已抽取要求后重新验完整请求。不能以抽取时能装下推定后续也能装下；
   必要结构重分只在依赖与覆盖能保持时采用，否则明确未决，不产生ready。

## 差异回归与真实预检（实施后更新事实）

- [ ] 完整章节可超过旧6000/12000字符仍不被强切；增大C不会保留隐藏字符小包上限。
- [ ] 父章正文/前言、子章、累计可靠条件、无标题附件全覆盖且正文不重复。
- [ ] 相邻小章允许合并；无关系跨文档不合；巨章尾部不回填下一章造成边界混乱。
- [ ] Excel跨表/表头、单巨表→行组→单格、巨段Unicode细拆，仅在完整请求超限后发生。
- [ ] 必需支持全文参加最终probe；支持单独超限明确阻断；结构碎片保留原始来源与合并关系。
- [ ] 每个最终包实际probe成功；未知/非单调probe不能用估算hint替代最终校验；准备不全量反复扫描。
- [ ] 同原PDF重新预检，逐包报告token/边界原因及准备耗时，解释422/520/796来源粒度差异、图片用途和作用域触发类别。

旧21包是固定字符算法的诊断基线，**不再作为满足本合同的验收结果**。历史4包不作为
优化目标；输出包数由真实结构及完整请求容量决定。真实模型继续暂停，原件/正文/图片不入GitHub。

## 存储与传输边界（用户硬原则，先于实现）

冻结证据是规范内容；原件和不可变业务历史必须保留，但不能反复嵌入整篇正文。

| 层 | 保存内容 | 不保存的重复副本 |
| --- | --- | --- |
| 原件/规范冻结证据 | 原件内容hash；原生正文、grid/合并关系、共享章节/定位索引；图片唯一内容与独立出现位置 | 不再额外保存可由native units重建的整篇rendered content副本 |
| 分包计划 | source/单位ID、区间、正文引用、支持引用、结构/边界原因、预算测量 | 不嵌入正文/整表/图片base64；章节路径/表结构共享引用 |
| 请求发送视图 | 按引用惰性物化当前包；同请求正文/支持按来源范围去重 | 不构造完整全量来源快照后为每包再拷贝；跨请求确实必需支持允许重复并计预算 |
| 要求 | 必要要求语义、原文证据、来源定位引用、范围处置 | 不回存整包来源正文和大型表结构 |
| 验证 | 各范围/要求结论、问题、补遗适用覆盖、上游要求引用/摘要 | 不再回显完整要求清单；计划从既有要求产物引用读取 |
| 响应计划 | 具体响应动作/目标/材料及不可变要求引用/摘要 | 不把整份要求、证据引文和约束快照再复制到每个计划项；完整约束只在校验时读取 |
| 模型审计 | 每个已收到的原始模型响应只保存一份内容寻址产物，请求记录引用；实际usage/uncertain | 不重复打印原始响应或带秘密的完整请求；若保留请求只保存必要审计摘要/引用 |
| checkpoint | 固定数量的阶段状态和产物引用 | 不保存正文/base64/完整消息历史，不在逐包步骤复制不断增长的已完成映射 |

内容去重仅用于完全相同的文件/图片内容，不把不同来源位置的同文义务合成一个来源。
当前六阶段图并行包结果放阶段产物索引；checkpoint不随着每个包追加全量历史映射。

图片用途以可追溯视觉/位置审议为依据，不能只靠重复次数或图片大小。显式reviewed装饰
可以保留图片载体与“非要求”依据而跳过OCR；未知用途保持未决，业务图需要OCR/VLM。
本次实际两份内容的结论只适用于同hash原件，不推出通用“所有小图是装饰”规则。

验收必须记录原文件、冻结数据、分包计划、checkpoint、模型审计各层唯一字节；逐请求记录
正文/支持token估计和来源去重信息、图片唯一内容/出现次数、准备耗时。按相似结构2倍/4倍
样本检查无必要平方级增长。正文唯一覆盖和必要支持不能为降字节数而牺牲。

追加差异用例：同名章节不同身份；父章直属正文；多级表头、跨页续表、纵向合并；无标题
附件结构降级；最小正文+全部必需支持仍超C明确问题。原件真实31项关键词假阻断需要修复
宿主分类，不以模型confirm清空；其余结构/引用绑定问题继续有依据处理，不假称原件歧义。
