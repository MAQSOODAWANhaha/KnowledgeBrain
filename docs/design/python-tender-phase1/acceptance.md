## 最终投标文件

验收对象是同一版本的投标文件是否盖住当前原件和补遗里适用的要求。分析通过、目录通过或成功出件，都不能单独算整份通过。

分母从全部原件和补遗建立，不能从模型已经选中的大纲反推。每项核对：原文和条件、这次是否适用、响应位置、实际 Word 的内容和证明、处理结论。模板里有了、有依据的响应、待补、待核、有依据的不适用，要分开记。`manual` 或 `not_required` 不是义务已经完成。

| 维度 | 需要证明 |
| --- | --- |
| 稳定 | 固定来源、代码、解析器和模型配置。重新生成和中断恢复都能解释关键组成、原式范围和未决项为什么变了。 |
| 正确 | 回到原件核对组成、资格和否决、评分依据、参数、原式、条件和例外。Schema 合法不等于语义完整。 |
| 一致 | 来源到成品、成品到来源都能对上最终 Word 的版本。章节、表、附件和应答不串位。只审已经选中的表，发现不了没选的必交项。 |
| 高效 | 质量和完整性相同之后，再比调用、重试、Token 和耗时。修订只重跑受影响的任务。 |

还要打开同一份 Word，看阅读顺序、原表和续表、分页、图片和目录。没有企业资料时，只能验收模板、原式和空位，不能宣称企业已经满足、证明有效或报价签章已经完成。缺材料不阻止保存和导出，但验收结论不能写成通过。

## 最低验收线

上面是完整验收。第一份真实文件先过下面这条最低线，过了才算 1/4。过线之前不新增协议或阶段，只修缺陷和推进[一条要求链](../../../plans/single-requirement-chain.md)。

1. **要求不漏：** 以分析事项为分母，每条适用事项都有响应位置，或者明确列在缺口清单里。人工抽查原件 3 处以上评分表和资格条款，没有台账和缺口清单都漏掉的要求。
2. **原式表正确：** 招标指定的格式表在 Word 里是表，列数、表头和合并单元格与原件一致，固定文字和签章位置都在。
3. **缺口不被编造：** 没有企业资料的位置留空或写待补，不出现虚构的证书、业绩、人员、参数或价格。
4. **文件可用：** 同一份 DOCX 能在 ONLYOFFICE 打开、保存、重开，并导出 PDF。

逐字保真只要求原式表格、固定文字和签章位置；其余正文允许和原件有解析造成的空白、换行差异，这类问题记为解析器缺陷，不判定验收失败。

## 领域限制

- 解析不完整、附件没展开、Excel 显示不完整、OCR 读不出，都保留为可追溯问题。不能靠确认把它们清掉。
- 冲突和遗漏仍要独立模型和真实语义验收。数字规则不是通用语义证明。
- 上下文容量用保守估算。不知道 VLM 容量时，不挪用对话模型的容量。
