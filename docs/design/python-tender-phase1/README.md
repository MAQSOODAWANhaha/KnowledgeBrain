## 工程原则与边界

**文档先行。** 先提交方案、接口合同、职责边界、实施清单和验收标准，再实现。
发现设计与实现偏差时，先判断是方案缺陷还是实现问题，更新对应文档，再继续。
本目录描述新增 Python 路径；旧 Rust 文档及历史验收证据保持原含义。

业务语义由 Extract/独立 Verify LLM 理解及核对，必要时由人工裁决；宿主负责结构、
来源、覆盖、版本和执行保障。自然语言正则不能作为最终语义判定依据。
本期需求、业务范围及唯一流程顺序以[业务工作流](business-workflow.md)为准，
结构及字段语义以[唯一字段字典](field-dictionary.md)为准。分析覆盖资格、评分、否决、技术、
服务、售后、人员、商务以及文件/提交等原文事项；这些是查漏维度，不是固定专长 agent。
原文明示的填表字段、附件、签章、证明材料及方案应含内容属于分析对象；本期不填写企业
响应数据，不生成响应动作、材料准备待办、得分策略或实际得分，也不生成和审阅响应计划。
事项仅共享必要身份、类型、内容与证据，其余信息按来源出现；不得因结构有字段就补造信息。
本轮按[职责边界与规则审查](semantic-review.md)实现新的分析主线；旧独立工具和历史
规则仍保留。新分析路径把SupportingIndex的语言命中仅用作上下文候选，不据此自动绑定
作用域或产生语义阻断；显式人工范围决议保留，parser及旧工具的历史启发式仍须评测。
[v2合成语义样本](semantic-cases.md)含13组正反配对、2个跨文档及4个范围/路由样本，共32份当前
核验输入，使用当前schema和可见引文检查。[离线导出与判定流程](semantic-evaluation.md)
保留本地标注与模型输入隔离；样本尚未经过人工标注，部分定向真实调用不能计为整套语义验收。

本阶段不得修改 Rust 源码、Cargo 依赖或现有 Rust 执行链路，不切流、不删除旧实现，
不自动合并或部署。新增入口仅显式启动。未来接入合同见 [contracts.md](contracts.md)，
不代表 Rust API 已存在。独立验收完成与最终生产集成完成是两个不同状态。

最新目标固定五个主节点：`register → freeze → extract → verify → confirm → analysis-ready`。
所有可读来源先统一抽取，再独立查漏与核对；verify 内按需补读跨包原文，一轮后仍不能
确定的引用、作用域或冲突转人工裁决并重新核验，不自动循环或按业务分类跳过来源。
未决阻断项不能靠 confirm 强制放行；缺少必要原文时保持 blocked。
verify 内 locate/associate/review 的输入输出、决议独立接受、部分补遗生效投影及跨源联合
核验合同统一见字段字典；没有显式引用的相关规则也须进入候选发现，不能只检查覆盖并集。
知识材料检索、投标正文生成、成稿审查、最终导出不在本期。分析完成不代表投标人已满足
资格、材料齐备或投标文件合格。无需通用 supervisor、专长 agent 或通用运行时。
当前已部署格式容错、默认重试、心跳及两类核验身份修复；通用合同恢复等剩余问题见[问题记录](bug-fix.md)。

早期完整Python回归为896 passed / 15 skipped，包含schema、客户端/流式、业务核验及真实

### 现有工程职责

保留 `services/docreader/` 单一 Python 工程。复用 `parser/`、`models/`、`proto/`
及 `main.py` 原生 gRPC 接口，不改变默认命令。生产镜像 Python 3.11，新增依赖通过
`pyproject.toml` 与 `uv.lock` 锁定；显式 setuptools 包表必须覆盖新增包。

| 目录 | 职责 |
| --- | --- |
| `llm/` | CHAT/VLM 配置、请求、上下文校验、累计用量、失败/不确定状态；无业务编排 |
| `tender/evidence/` | 文档版本登记、原生解析、实际图片 OCR、冻结来源与包索引 |
| `tender/requirements/` | v2统一事项抽取、证据及逐来源范围处置；保留旧独立抽取工具 |
| `tender/checks/` | 全源审阅、locate/associate/review、关联/决议及覆盖核验；保留历史独立校验工具 |
| `tender/planning/` | 历史响应位置及材料需求规划工具；新五节点主线不调用 |
| `tender/prompts/` | 版本化领域提示，输入文档作为数据 |
| `workflow/` | 唯一业务阶段编排 LangGraph、状态与 PostgreSQL checkpointer |
| `jobs/` | Dramatiq Redis broker + AsyncIO、小消息、领取与回执、失联补投 |
| `integrations/` | 独立 CLI、持久业务表、文件引用；未来受控 API 边界 |

同镜像运行 gRPC、dispatcher、worker、CLI 等不同进程角色，不建多个微服务项目。
Dramatiq AsyncIO 每进程一个事件循环，消息并发仍受 worker 线程数约束；原生解析通过
线程/进程隔离执行，不占用事件循环。大文件不进队列、不进 checkpoint。

### 当前图和持久状态

LangGraph 的节点按五个阶段连接，人工节点使用持久 interrupt。checkpoint 只保存
run_id/source_version/domain_revision、状态、registered_ref/frozen_ref/pack_plan_ref/
items_ref/verification_ref及checklist_digest；字段以[唯一字典](field-dictionary.md)和
`tender/schema.py`为准。确认绑定当前来源、领域修订及核验摘要，成功后到达analysis-ready。
每阶段产物通过不可变内容寻址文件写入，再以数据库带围栏事务登记回执；重放节点先读
已有回执，因此“业务提交成功但 checkpoint 未保存”不会重复生成业务版本。

业务 PostgreSQL 表保存 run、版本、命令、执行租约/围栏、产物回执、确认、模型请求审计。
LangGraph checkpoint 表由官方 checkpointer 初始化。Redis 只是投递；业务结果不依赖 TTL。
初期独立提交将 run + start 命令在同一 PostgreSQL 事务落库；dispatcher 领取带 token，
投递后记录 published，只有 worker 执行回执才表示执行。过期 published/执行租约可补投。

每个 run 同时只有一个有效执行租约；epoch 单调增加，所有业务提交检查 epoch、租约和
取消意图。heartbeat 在独立协程观察取消；节点边界再检查。旧执行者不能提交或覆盖
checkpoint；实现需同时保护图执行与业务产物，不能只给产物加锁。
人工 interrupt 持久化后结束当前 actor，释放 worker；confirm 事务产生独立 resume 命令。
运行取消直接写取消意图，不排队等待长任务结束。来源变更产生新版本和新 thread_id，
旧确认失效；旧执行结果不会流入新版本。

## 最新一期领域边界

1. 文档集含所有主件、附件、澄清补遗和明确版本/修改目标。重复、缺失、不可读是可追溯问题。
2. 冻结保留章节、段落、表格/单元格/合并关系、实际图片、附件位置及 parser 的 partial/
   unsupported 信息。文本 PDF 不逐页渲染给模型。扫描页和实际图片才调用 OCR/VLM。
   Python literal OCR 是本次新增领域能力，不假定 Rust OCR 已移植。
3. 包只引用冻结单位。小章节合并、大章节切分；导语、条件、表头作为带来源的 supporting
   context，不重复计入正文覆盖。发送视图可压缩全空表格行，保留原始网格与部分空字段语义。
4. 每个正文范围必须有事项、带依据的非事项处置或未决。资格、评分、否决与文件提交要求
   可以共享证据并关联；条件、例外、数值、表头及跨章引用按来源保留。逐范围处置不证明
   段内事项已全部抽出，字段缺省也不能解释为“原文没有”或“已核验无问题”。
5. 独立验证既核对已有事项和关系，又重读全部来源找遗漏；数字归属、比较关系、条件及
   补遗适用性由 LLM 审阅及必要的人工裁决确定。新主线不依赖旧数字词表或冲突规则判定
   业务含义；上下文词表仅提供候选，parser及旧路径启发式的影响须继续评测。评分合计须有原文
   依据，不假设均为100。补遗只影响明确目标，不以后发时间全局覆盖。
   局部包语义失败隔离保留成功包；依赖失败范围的结果不得放行，全局不得假成功。
6. 人工确认绑定来源/领域修订及事项、关系、问题、审阅清单摘要；变更后旧确认失效。
   未决阻断项不能靠确认强制通过；确认完成才产生分析完成结果，不再生成响应计划。

## 模型、失败与观测

配置仅从环境读取，延续 `KNOWLEDGEBRAIN_CHAT_*`（含 `LLM_*` 既有别名）与 VLM 语义。
VLM 的地址、密钥和模型独立配置，不自动继承 Chat，也不根据模型白名单判断图片能力。key 不写文件或日志。
单次上下文容量与累计预算分开；不自加 `max_tokens` 输出硬上限。纠错仍受同一服务容量限制。
合理默认并发/超时/退避；SDK 内建重试关闭，队列仅重试基础设施失败，语义问题在图内返回
领域问题/受限修复；不能 SDK、图、队列叠加无限重试。

每模型请求在发送前登记，成功记录真实 usage，已发送但响应丢失标记 uncertain，重试可能
重复计费不可伪称 exactly-once。阶段耗时、请求/包数、usage、未决项与实际产物均持久记录。
当前追加的[请求必要性与流式合同](request-review.md)要求所有新Python模型交互streaming、
连续180秒无数据才超时，且uncertain不自动重付费；实现与验证证据在追加评审中单列。
确定性 mock 模型只验证合同和恢复，真实模型语义验收另列。真实调用前报告输入、endpoint
与估计范围并核对既有授权；已授权范围不重复确认，uncertain 请求不自动重付费。
