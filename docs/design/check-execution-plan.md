# Discover → Organize → Check：支持交付与验证计划

## 状态与范围

本页是当前唯一实施状态与反例验收矩阵，依据经审查的整改合同实施。生产接口见[证据运行时契约](evidence-runtime-contract.md)。本轮已实现宿主自动支持交付、审计保留、worker 容量隔离和 Check 一致性门；全库回归已完成，唯一失败项的脚本模型修正已定向通过。本页规则是持续有效的验收合同，旧测试、CI 或真实运行不追溯授予新实现通过。

目标是全文件 Discover → Organize → 独立 Check 的 template-ready，投标人空位仍保持空白。knowledge、匹配填充和填充后验收延期。不迁移旧检查点，不新增通用调度、预算、证据框架或模型工具。旧失败记录和费用账本保持原样；合同改变后新建运行，同合同内仍支持持久恢复。

## 1. 来源选择与职责

区分三类来源，不以一个“required”集合混淆它们：

1. **owned body**：当前包唯一拥有的原子/精确范围，负责提取与源处置。分包不得重复拥有或遗漏。
2. **解释所需结构支持**：由原生结构或已确认关系能确定的最小范围，例如覆盖 owned cell 的合并格、已标识适用的行头/列头、显式续表关联所需表头、与当前来源有明确端点的限定关系。关系标识只确定应交付的范围，不替模型证明条件适用。
3. **语义候选**：仅有同节、祖先节、位置邻近或词语相似关系的正文。可以供定位或有依据的进一步读取，但不能全部成为提交前置门。不得把整章正文默认附入每包。

首版允许规则仅使用已有字段，不将文档级关系升级成全文件必读：

| 冻结字段/关系 | owned 端点匹配与输出范围 | 缺失或含糊时 |
|---|---|---|
| `structured_forms.definition.cells` 的 `row/column/row_span` 与有效列跨度（canonical 优先 `column_span`，解析定义的 `col_span` 按既有统一读取规则归一） | 同 table；重建 owned 行时包含 row-span 与该行相交的锚格，输出这些格的完整文本范围，不复制全表 | 无 span 证据不猜合并；保留原生格并标明结构待核 |
| 同表 `header_role=column_header/row_header` | 列头在上方且列区间与 owned 格相交；行头在左侧且行区间相交；输出对应完整头格，层级头逐层同规则 | `none` 或无法确定范围不自动升级为头；Check 需检查结构歧义 |
| `document_relations` 的 `kind=ExplicitReference,status=Confirmed,required=true` 且两端有 `unit_id` | 以 document_id+原生 unit_id 精确匹配 owned 引用端；只交付另一端完整原生单元（表端仍按预算分页），不沿关系递归扩展整个文件 | 文档级 `unit_id=None` 仅是可探索关系，不自动必读全文件；关系冲突/缺失保持问题出口 |
| 续表/后置限定 | 同原生表身份或精确关系端点按以上规则；已有 `attachment_chains` 还用同文档/已解析章节、相同列数、重复或空表头、两表间无正文确定结构链，复用该输出并只带所需头格。此结构规则不证明业务适用，不能凭相邻页或标题相似扩展 | 不凭相邻页猜续表；由各自 owned 源处置发现并提出有证据的修复，无法关联则未解决 |

这些选择规则已实现，元数据能支持其准确性仍由 S1–S5 与真实文件分别验证；不新增未经解析验证的“必要”标签。

结构支持选择应返回可复核的来源范围与选择原因，复用现有 EvidenceRef/关系信息，不新增独立权威清单。去重以同 carrier 的范围并集为准；相同文字但不同来源不能合并身份。缺少 header/span/续表关系时，不凭位置猜确定关系；保留为待解释来源，在独立 Check 源处置中检验，无法判断则未解决。必要范围包含后向或前向关系端点，不以 `ordinal < owner` 一概排除后置例外。

跨文件关系只使用冻结文件集中的明确来源端点；不存在的公告或附件报告缺失，不生成正文。未确认的跨文件关系只能在现有获授权的读取范围内探索，或由目标来源自己的 owned 工作读取后进入既有修复流程；不得新增跨包访问权限或由模型把候选升级为确认关系。没有合法读取入口则保持未解决，不把文档标题匹配当条件事实。图片必须保留 source/region 与文档、sheet 或 compound-parent 归属；缺少 Excel 绘图锚位置不能据路径声称精确行归属。位置歧义维持未解决，不编造锚点。

support 不增加当前包 owned 覆盖、不能完成另一个包，也不能被静默提升为 primary。若模型发现主要求属于另一来源，应走现有重开/修复出口，不改写所有权掩盖错提。支持关系变化须撤销受影响的语义判断；保留无关结果需有独立性依据。

## 2. 宿主确定性交付与预算

宿主按稳定来源顺序选择尚未确认的结构支持，通过现有请求装配、frame、续页和 journal 交付；模型不必先请求一个已确定必交付的 ID。自动附页采用宿主构造的合法 user 消息（正文及必要 image parts），不伪造 assistant tool_call 或无对应调用的 tool 消息。沿用 frame 生命周期，封存对象为最终 SDK wire 中该消息的精确内容/图像身份及请求摘要，关联该请求的持久 Received；已扩展既有 frame 的载体匹配，不沿用仅查 tool_call_id 的确认逻辑。可选语义探索仍使用现有读取工具，不增加工具。若结构支持不完整，提交拒绝应列出确切缺失范围/状态，后续由宿主续交，不让模型重新猜目录。

分包规划计入首发拟交付的支持、结构和协议内容；每次最终发送必须计入当次实际支持正文、原生表格结构、目录、提示、工具、历史、游标、图片、安全余量和输出预留。未来历史尚不存在，全支持交付成本与后续请求容量必须通过固定窗口逐步闭合验证，不能声称规划已计全未来历史或将全部支持一次塞入首发。规划与 worker 共用支持页构造，但规划使用规划请求模板，不声称全部协议字段与 worker 逐字相同；最终 compact/project 后的实际 worker wire 再完整计量。去重只能减少同一请求中的重复载体，不把其他 worker 的阅读信用借给当前 worker。未知模型使用可核实或实测校准的 profile，不能冒用其他模型配置；经验余量不是服务长上下文证明。

优先完整原生范围；超窗使用现有无损 UTF-8/原生格续页。最小页或不可分身份/图片仍放不下时，明确容量失败，不截断伪报完整、不提高窗口掩盖。正文、游标和观察共同增长时也必须经过最终门；候选试配与实际发送使用相同游标状态。授权累计费用独立于单请求容量；缓存命中、cached tokens 和未发送预留不擅自抵扣实耗。

并发发送先串行完成预算预留和 durable Sending，再允许 provider 调用。未知发送仍占预留，不能自动退款或重发。实际已收响应重放不重复计 usage 或应用结果。自动交付实现须证明“只够一个请求”的双 worker 场景不会双花。Sending 保存前失败且 provider 调用数为零，与 durable Sending 后尚未发出、以及已发但结果未知分开记录；前者仅在持久状态能证明未发且账本恢复一致时释放预留，后两者不能仅凭内存标志退款。

## 3. 交付、身份与恢复

- 页面准备/排队/封存均不算实际已读。只有同一输入、来源、claim/revision 下的精确实际请求，取得并持久化有效完成响应后，才确认它确实携带的原文范围。模型已收到与模型语义理解是不同事实。
- 首版有效完成谓词沿用 `valid_tool_turn`：`finish_reason=tool_calls`、至少一个调用、每个调用的 id/name 非空且 id 唯一，加上 durable Received 与精确请求/frame 匹配。`stop`/无调用、`length`/截断和传输错误不授信。多调用/未知工具/坏 JSON/旧模型 scope 属于新动作错误；若上述完成条件满足，仍可独立确认先前实际页面，之后按动作合同拒绝。
- 响应中的新动作参数错误，不应反向否定同一有效完成响应已确认的先前交付；先验证宿主请求/响应及 frame，再独立校验模型新动作。传输失败、截断或不满足有效完成条件的响应不授信。此解耦已实现，验证见下述矩阵，不放宽动作 scope。
- 未发送取消不计交付；Sending 取消保持未知状态和预算；Received 重载从相同内容幂等确认。部分页仅确认其范围，不能生成完整支持信用。确认失败是宿主错误，不以业务修正无限重试。
- 原始阅读观察、失败回执与操作身份持续保留为审计；请求投影不得重新引入不成对旧 tool 消息。独特观察不能因 repair 失败而静默丢弃；重复观察压缩仅作用于请求投影。
- claim/revision 改变后保留“曾经读过”的历史事实，但不恢复旧授权、旧句柄、旧游标或旧 Check 信用。最小首版在新 claim 下重新精确交付需要的支持，不开发跨 claim 信用迁移。重复交付成本计入预算。
- request 身份继续逐请求防重放；是否减少模型可见 handle 轮换，须先证明同业务 scope 绑定稳定且当前请求/旧动作仍能严格区分。本轮不删除身份校验，也不自动接受模型抄回的旧 scope。
- 重复提交使用现有 operation 身份及参数摘要：宿主持久 Received 重放或已保存领域回执的内部重放可返回相同操作/参数的原结果；新模型请求必须先通过 live scope 校验，旧参数不能借幂等入口绕过授权。不同参数不能冒充同一操作。领域变更与回执持久化失败后重放不得重复新增要求或丢失先前结果；修复必须沿生产 commit/reload 验证。

## 4. Check 的独立语义范围与完成门

Check 根据当前 canonical 主证据重建完整原段/原生行，加上与被引格相交的合并范围、适用行头/列头、明确续表和支持关系；结构支持保持辅助角色，不能自动成为当前要求的 owned 主体。读取全部相关 quote 后才比较，不继承 Discover 已读信用。

确定支持至少要有与原要求主证据实际 carrier/range 相交、且明确 relevant 的 primary；related/context 不能单独冒充 primary。只有 not_relevant 或 unclear 主引用的比较不能给确定 supports/retain。decision 应覆盖它声明的主证据和支持，并且不能忽略已观察到的 relevant 限定；有相关但未纳入判定的冲突/条件，应要求补全比较或维持未解决。这里校验的是显式声明的一致性，不根据中文关键词推断义务。

`not_required + retain` 并非天然错误：原要求本身可以正确表达“无需提交”。保留否定、例外、条件与可选项的语义；不能为使验证器通过改为肯定要求。相反，未解决的比较不能只改标签洗白，必须修复来源/主张后 fresh Check。

响应目标区分 instruction、mandated_response 与 editable blank：说明不能冒充投标人承诺；规定原文通过 canonical 范围复制；未提供的投标人事实保持空白。模板通过要求具体字段/格式/操作位置与义务绑定，泛化“提供材料”不算履行。

阶段写入或重开撤销受影响的 Check epoch、比较、源处置和模板复核；旧原文缓存只作载体，不作新信用。明确的 worker 局部失败释放调度名额，独立包仍可继续 Discover，并在既有条件满足后执行 partial-source Check；当前不扩大为局部 Organize 或局部 template-ready。全文件 Discover 完成后才走正常 Organize→完整 Check。依赖失败范围的工作不伪装独立。全局 ready 仍需全部必要包、来源处置、要求比较与具体响应目标通过。人为暂停、未知发送及输入/配置完整性错误保持全局阻断。文档缺失/冲突可以形成带问题报告，不能等同 clean template-ready；系统故障不能改名为文档问题。

## 5. 停滞与状态增长

删除“六次拒绝等于无进展”的近似。重复失败检测只在同输入/业务状态下比较宿主可确定等价的动作与错误类：合法参数按现有业务校验规则归一化（含 trim-empty、明确无序集合）；非法 JSON 保留原始参数指纹，不合并为 Null。不能任意排序有业务顺序含义的字段，也不试图判断任意自然语言是否语义等价。

只有精确确认的新原文范围或成功业务产物推进已确认进展；排队、目录浏览、领取工作、换 operation ID、改空白不算。正常分页超过六轮允许继续。同一失败再次出现且无相应进展可终止该 worker，审计保留；不同自然语言改写仍可能耗尽授权预算，因此不宣称任意循环可被语义识别。为避免同一原文跨 claim 的历史 union 误判，新 claim 的交付状态与跨 claim 审计事实分开比较；重新交付旧原文不能洗掉业务失败循环。宿主交付屏障未满足时，模型的提前提交只产生缺页反馈，不拿它与上一 claim 的业务失败签名比较；宿主继续交付缺页。屏障满足后才比较相同业务提交错误是否重现，保留其跨 repair 失败记忆；源/语义状态确有变化需纳入比较状态。该规则不是无限宽限，交付必须严格增加本 claim 已确认范围并受容量、授权费用和取消控制。

registry 优化先记录固定来源多代请求的 scope/binding 数、投影/克隆/保存耗时及 wire tokens。清理必须证明 pending Sending/Received、续页、待交付 frame、重放和历史解码均不再引用相关 scope；否则保留。不得为减少内存恢复过期句柄，也不引入第二套缓存身份或后台回收框架。性能收益未证实前不列为功能验收阻塞。

## 6. 反例验收矩阵

以下是持续适用的验收门槛；当前实现与测试结果分开记录，使用公开合成材料，真实材料与模型结果仅私有保存。每个用例记录输入/配置/代码摘要、实际 wire、逐请求输入/输出预留/剩余窗口、最终覆盖、状态、回执与次数，不能只断言 mock 返回值。

| ID | 最小场景 | 必须断言 |
|---|---|---|
| S1 | 同节大量无关前文、祖先正文、一个明确合并表头 | 不全章强制；明确结构支持交付；候选不冒充必要条件 |
| S2 | 正文义务后出现否定例外；跨页续句 | 后向检索不是唯一入口；独立源处置发现例外，最终主张保留条件或未解决 |
| S3 | 跨表/跨页续表、两层列头、上方跨行“不适用” | Discover 与 Check 都包含所需精确结构；无错列归属，支持不占 owned 覆盖 |
| S4 | 两文件明确补充关系与一个仅同名附件 | 读取明确关系端点；不凭同名套条件；缺文件不编造 |
| S5 | DOCX compound 图、XLSX 同 sheet 多图、同像素不同来源 | 实际图像身份独立；缺锚不猜行；OCR/缓存不算视觉已读 |
| L1 | 自动排队后取消、传输失败、截断、旧 scope 新动作 | 分别覆盖 stop/无tool、length、合法tool_calls+坏JSON/旧scope；未完成不授信，合法完成仅确认实际页面；自动user附页无伪造tool对 |
| L2 | Received 保存后崩溃、commit 前后重载、同 operation 重放 | 分别验证宿主Received重放只应用一次、旧模型新请求仍拒绝；不同参数同身份拒绝 |
| L3 | 补读→repair 仍失败→claim 轮换→重载 | 独特观察审计不丢；旧 handle/cursor/Check 信用不可用；必要新交付成本可见；多页重交付期间相同提前提交不误停，交付完成后重复业务错误仍停 |
| L4 | 一包最小页/prepare 容量失败，另一包无依赖 | 失败包终止，独立Discover及已有partial-source Check继续；不启局部Organize；全局ready=false；人工pause全局停止 |
| G1 | 同失败 A→A、A→B→A；九次有效修正；超过六页有效阅读 | 重复失败可停；真实修正和交付不因固定次数停止；重载不复活终态 |
| G2 | 空白逐次增加、不同 operation ID、相同坏 JSON、逐步修正坏 JSON | 等价业务失败不能绕过；不同语法修正不误并为 Null；pending 不清失败集合 |
| C1 | 所有 primary 为 not_relevant/unclear；auxiliary-only primary | 不能判定确定支持；正确主证据+相关支持可通过 |
| C2 | 合法“无需提交”；肯定义务遭 relevant 例外反驳 | 保留合法否定；不能忽略相关例外、改 verdict 洗白或用 support 代替 owned |
| C3 | 已完成 Check 后修改正文、支持、目标或重开 | 旧比较/epoch/模板信用不能 ready；fresh Check 后才恢复 |
| B1 | 支持+目录+观察+多路 cursor+图片接近固定窗口 | 最终 wire 计全；逐页无损；最小不可容纳明确失败、零额外发送 |
| B2 | 双worker只够一次额度；Sending保存前失败、保存后未发、已发未知分别注入 | 断言provider调用数、重载账本与预留一致；无双花；未知消费不退款；重放不重复计费 |
| B3 | 同来源多代请求、源内容改一字、相同像素不同身份 | 测量 registry 增长；缓存身份不混；冻结输入变更拒绝旧状态 |
| E1 | 全文件，含零要求范围、要求+问题、固定文字/表格/空位 | Discover 全范围处置→Organize 具体目标→fresh Check；失败与未测明确分列 |
