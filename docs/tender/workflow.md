# 招投标业务工作流、编制架构与运行时接口

本页统一定义招投标的**分析流程、发送边界、编制架构、实际模型调用表**以及**证据层/模型层运行时接口**。字段与枚举合同见 [字段字典](field-dictionary.md)，工作台与 Word/ONLYOFFICE 见 [工作台与 Word 编辑](workbench.md)，验收口径见 [验收与语义评测](acceptance.md)，当前动态进展见 [招投标入口 · 当前状态](README.md#当前状态交接)。

## 分析主流程与发送边界

**登记文档集（`register`）→ 解析冻结（`freeze`）→ 统一分析（`extract`）→ 独立核验（`verify`）→ 人工确认（`confirm`）→ `analysis-ready`**

| 节点 | 输入与产物 | 放行条件 |
| --- | --- | --- |
| `register` | 主件、附件、澄清/补遗身份、版本、角色与缺件问题 | 原件持久保存、身份可追溯；缺件不悄悄排除 |
| `freeze` | 规范正文、章节、表格/合并、图片 OCR、附件位置与解析缺口 | 可读范围可推进；必要来源缺口保留并阻断最终确认 |
| `extract` | 小批正文 + 必要上下文 → 统一事项、逐范围处置、关系与未决引用 | 宿主组织逐范围处置；局部回包缺陷保留有效结果与待核问题继续核验 |
| `verify` | 冻结来源 + 抽取事项，按预算分批独立 `review` | 区分硬阻断与人工待核；缺页或漏报原子不再触发额外模型轮次 |
| `confirm` | 展示来源、事项、评分/后果、关系与问题，逐条裁决语义疑点并确认摘要 | 无硬阻断、语义疑点均已驳回或保留、摘要与当前版本一致；硬阻断仅阻止确认，不阻断编制或导出 |

- LangGraph 固定图为上述五节点（`services/docreader/workflow/graph.py`），无报告生成节点，不按业务类别拆多 Agent；`locate`、`associate`、`joint` 已退役，核验只发 `review`。
- **职责分工**：模型负责语义抽取、证据选择与关系判断；宿主负责身份、原文定位、反向索引、分包、预算、存储与流程推进；正则/词表不能充当最终语义裁判。

### 当前发送边界

1. **分析调用数**：实际准入的抽取包数 + 准入的 `review` 请求数（OCR 另计）；分开统计计划条目、唯一逻辑请求与物理发送；每个逻辑请求最多合同纠正 2 次、传输重发 4 次，两类分开计数，物理发送上界 7 次（见 [字段字典 · 失败执行的显式恢复](field-dictionary.md#失败执行的显式恢复)），成功回执按完整摘要复用。
2. **准入预算**：在 `131072` 上下文、输出预留 `32768`、安全余量 `4096` 下，单次输入准入上限 `94208`（抽取按 UTF-8 字节估算，review 按校准 Token 估算）。
3. **抽取软目标与紧凑处置**：多范围抽取包输入软目标 ≤ `55,000` 字节且单包正文范围 ≤ `200`（单条不可拆大范围按 `94208` 准入）；`non_item` 用固定理由码逐范围声明。
4. **严格 Schema 与抽取语义边界**：v2 文本抽取与其他任务统一采用 `response_format={"type": "json_object"}` 并在系统提示词中附带单份同源 JSON Schema（计入执行身份，避免非全必填 `strict: True` 的 `json_schema` 被兼容网关忽略或双份挤占输入预算）；`kind` 仅限四类固定枚举（资格、人员、技术与履约要求均归 `obligation`），`scoring`/`consequence`/`submission` 严格与对应 `kind` 绑定；独立条款不因后果相似而在 `relations` 错绑（[BUG-314](bug-fix.md#bug-314未经允许转包的合同后果错绑到另一解除条件)），同条款前置政策/法律依据跨行须纳入 `evidence`（[BUG-319](bug-fix.md#bug-319小微企业价格扣除事项缺少本条政策依据)）；多个独立触发条件共用后果须列全各条件并保留原文引证；表格序号列不写入 `numbers`，窄格折行数字在 `text`/`numbers[].value` 还原真实数值并保持字面 `quote`；履约/实施/验收阶段交付成果归为 `obligation` 而非投标提交件，签署/扫描总则中的举例性条件文档不写入无条件 `submission.documents`。
5. **同源纠错零抽取**：CLI `correct` 继承基线冻结来源与抽取分包，发 0 次抽取，允许引用同文档跨包原文范围，保留未改包产物与既有宿主问题，重排并重验受影响 `review`。
6. **不誊写原则**：模型只回语义事实、短引用 ID 与理由码，不誊写宿主已知或可推导的原文、页码、表格或覆盖名单。

### 核验怎么发

- `verify` 只发 `review`：宿主对整份来源待核正文及同页/同节范围取并集，以 `32,768` 输入 Token 为软目标按文档顺序分批；每个查漏正文范围仅归属一个主请求，未同包覆盖的关系与显式人工作用域按预算补审。
- 缺页/残页记 `analysis_page_source_unavailable`，漏报原子补待核，不再开额外轮次；重复引用、未知编号、上下文环、正文与上下文重叠拒收。
- **同源范围延续（BUG-312）**：冻结来源、分包、作用域与查漏范围一致时，同源纠错优先沿用直接基线的主核验分组，只重发完整摘要变化的请求。
- **PDF 表格与逐字行互补**：同页表框内逐字行唯一匹配单元格（含勾选选项或相邻双格首行）时，查漏请求互带完整表格行与已有事项引证作为阅读上下文；歧义留人工。
- **跨章作用域附带（BUG-299）**：`review-scope` 提交的人工作用域结论除独立作用域补审外，凡查漏或关系补审请求读到该决定的控制条款或目标时一并附带。

### 状态、修订与恢复

- 运行状态：`pending` / `running` / `blocked`（硬阻断）/ `waiting-confirmation`（待人工裁决语义疑点）/ `failed` / `cancelled` / `analysis-ready`。
- 版本隔离：来源变更升 `source_version`；同源纠错升 `domain_revision` 并使旧确认失效；协议格式由 `schema_version` 隔离；问题决议按 `issue_id` 与版本绑定，不按 code 批量清除；必要缺件经 `revise` 的 `expected_document_ids` 声明；`confirm` 阶段不调用模型或解析器，从人工确认中断点续跑时只核对 `workflow_protocol` 兼容性与确认摘要/决议并保留该修订原固定的 `execution_spec`，允许跨越提示词、解析器或请求预算部署完成确认；仍在模型/解析阶段的续跑继续严格校验 `execution_spec`、`source_spec` 与 `request_budget`，配置变化时立即以 `execution_config_changed` 失败。
- 恢复边界见 [字段字典 · 失败执行的显式恢复](field-dictionary.md#失败执行的显式恢复)；在途 `sent` 禁止并发重发，改提示/重分包不重置已有额度。
- Web 项目按完整来源登记核对分析、大纲和新确认。目录已保存而登记未完成的原件记为 `source_registration_pending`，有其他可用原件时可生成带待核的草稿。新分析须先补齐原件登记并核对多文件角色。新确认和纠正使用当前来源，已受理的同键请求可读取原回执。

## 编制架构与缺资料默认处理

**核心不阻断原则**：任何资格、评分、产品、人员、价格、证明、模板或分析未确认问题，均**不阻止**生成、保存、预览或导出 DOCX——能写的写、未知的留空/待补，文件生成状态与内容齐备状态分开报告。

### 缺资料时的默认处理

| 情况 | 默认处理 |
| --- | --- |
| 名称、型号、人员、参数等必填信息未知 | 保留原字段/格位留空（不破坏原格式时可注“待补充”），不阻断生成 |
| 报价、单价、总价、折扣等最终值 | 保留原表与招标预算/限价，最终值留空交人工填写，不填 0 或自动算价 |
| 无匹配企业知识 | 企业应答留空，不自由编造或拿招标要求复述充当应答；有招标来源支持的背景可保留 |
| 缺证书、报告、授权或签章 | 保留附件/签署位并记待提供，不用生成文字冒充原件 |
| 规定格式来源暂缺或不可读 | 用当前已知结构保留位置与待补说明，不声称已保留未知原格式 |
| 未确认分析或冲突未决 | 固定当前可用快照继续生成，冲突值保留待核对，不静默选边 |
| 局部写作/复核耗尽重试仍失败 | 写作失败留空位；初审接口失败保留未被否定 `U0` 待核；已有明确否定时改稿失败或再核不可用回退安全稿 `S0` |

### 四个语义职责、大文件制作与回退

| 职责 | 责任范围与边界 |
| --- | --- |
| 组织响应位置 | 按招标规定结构与有效要求确定分册、章节、原式表与附件位；宿主管稳定引用，不一事项一章 |
| 准备响应依据 | 有限业务词检索，汇总有知识支撑的共同方案；去重 `supports`；产品型号可选，不因缺型号阻断功能方案 |
| 编写响应 | 依据允许的 `supports` 与原模板分任务编写正文与填格；仅选 `target_ids`/`support_ids`/`attachment_ids` |
| 复核响应 | 核对实际内容、附件及“有候选却判空”的语义空稿；`b/f/a` 精确定位，无资料/人工空位免复核，明确无据才移除 |

- **内容制作方式**：项目化正文由模型按完整业务单元分任务生成；固定格式与原式表由宿主装载（`manual_fill` 不调写作）；证书/报告原件按引用插入；目录/页码/`is_volume` 分册由宿主组装。冻结来源里「投标文件格式」的目录条目存在时，导出的一级目录和对应章标题严格遵循这些条目的序号与原文（规范化顿号后多余空格），插在两个已编号一级章之间的无序号附属文件归为前章二级子章，末尾格式外补位章按同体系顺延一级序号；全稿所有二级及以下多级子章节（不限于三级，按实际树深度递归至 `N.1`、`N.1.1`、`N.1.1.1`…，Word 支持 Heading 1–9）统一规范为多级阿拉伯数字编号（剥离原件混杂的 `5-1`/`（一）`/`1.` 等旧前缀并消除漏号与跳号），无格式目录时全稿使用原生多级数字编号（`1`、`1.1`、`1.1.1`…）；正文原式首行去序号后与已输出的章标题等价时跳过重复首行。
- **三对象隔离**：会话大纲（唯一接受显式补丁）、整树回包、人工 Word（分叉，新导出为候选不覆盖人工已保存稿）相互独立；覆盖统计与版本/SHA 不一致标待核。
- **知识用途与履约边界**：产品规格/证书用于事实证明，规程用于方法参考，历史方案仅借鉴结构（历史项目名/人员/型号/价格/承诺绝不迁移）；正式履约承诺须有业务授权。
- **一次改稿与回退（`U0 → S0 → U1`）**：初审明确否定内容剔除得 `S0`；仅 `can_revise=true` 且有足够依据的任务最多改稿 1 次得 `U1` 并再核；改稿失败/空回包/`U1` 再核不可用回退 `S0`；初审接口不可用保留未被否定 `U0` 待核；不自动循环追求“零问题”。
- **宿主边界**：Python 宿主负责身份、不可变引用、预算、缓存、重试、租约与组装导出，不引入通用自由调度 Agent；签章、授权、付款与平台递交属外部业务动作。

## 编制目标设计：一条要求链

实施路线见 [修复与改进路线 · W2 一条要求链](../../plans/improvement-roadmap.md#w2-一条要求链)。有冻结来源的自动大纲统一走 `single_requirement_chain_v1`（`bid_format_source_outline_v1` + `item_placement` + `proposal_outline`）。分析事项台账是唯一覆盖分母。宿主从冻结表格和原文行复制原式、固定文字与签章。投标格式开头的独立封面置于目录前，保留原件的项目名称、填写位与签章方式。封面标题与字段表在同一页，或标题下有投标人盖章、代表签字和日期栏。电子签章式样也可由同页的项目名称栏、投标单位电子印章栏和日期栏确认。逐字竖排的“投标文件”按原页上连续的四个标题字识别，字间可有空行。标注“不适用”的编号式样为复制边界。

### 新链格式补位与事项归属

流水线：`格式章节选择` → `格式补位` → `编译` → `事项归属` → `宿主结算`（字段见 [字段字典 · 新链事项归属](field-dictionary.md#新链事项归属)）：

主件同时给出独立递交要求和各文件组成条款时，宿主将对应条款绑定为分册。册内按组成清单的顺序安排原式，依据同文档的文件名、附件编号、从属原式或明示引用的技术卷确定归属。分册保留原文编制要求，企业应答随证据填入。共同封面在整稿目录前；归属有歧义的原式留在整稿，列明文件名和来源供编制人员调整。仅列业务部分的项目沿用单份整稿。

组成清单中明确排除的名称和附件编号限制该册的成员资格；同一项中另列的正向成员仍按原顺序采用。仅被排除、缺少正向归属的原式列入整稿待核。

同一文件总目录的投标格式章节明示某附件不适用，格式目录只重复列出同号同名条目时，宿主记录两处来源，跳过仅列名的条目。同号另有未标注不适用的独立原式时保留原式并提示核定。

分册组成条款指向原件中的特定卷时，该卷编号附表的同页说明明确要求投标人填写本表，宿主把对应冻结网格随分册保留。已复制的原表按来源去重，条件式和明示不适用的附表保留各自的适用边界。这一步只装载来源原式，缺企业依据的响应格留空。

格式选择把同一父章内的原句或句内片段误作标题时，宿主可以保留同批其余已核实章节。该候选须没有子章和显式正文窗口，引用本包连续原行，且其整段已完整落在所声明父章或其子章的同一复制窗口内，期间没有原表需要另定归属。交付待办列明来源和实际承载章节。无法证明这些条件、附件编号被当作文件名或整批没有有效章节时，仍走原有纠正与失败出口。

格式章节中明确标作“目录”的连续编号清单只提供文件名。选中的名称只定位到清单时，保留该章与具名原式待核事项，正文填写位留空。实际式样从所选的独立原式标题开始复制；同页重复出现的附件编号可标志清单结束、原式开始。显式正文窗口跨出所选目录条目时，格式回包进入纠正。

1. **格式章节选择（`bid_format_source_outline_v1`）**：通常 1 次逻辑请求（宿主兜底 0 次），仅读格式章节短标题行；文件名须落在独立标题、编号后的标题或同一标题清单的文件边界上。并列文件名按括注以外的分隔符区分，正文句内的名词保持在原段。单独成行标题、子编号格式与可选提交方式各成一章，同行“或”择一成一章，“不适用”不选。模型按招标文件原文结构同时返回 `parent_heading_ref`（上级章 `heading_refs[0]` 行号，根章为 `null`）与可选 `label`（含原文序号与大小写的展示标题），宿主严格校验 `parent_heading_ref` 指向本节先出现的已选章节、同文档且无环，且 `label` 必须为所引 `heading_refs` 原文连续子串且不以 `附件`/`附录`/`附表` 映射号开头（支持首行序号标题与次行文件名拆行的原式）；存在独立封面时始终置顶。标题行整体超出准入预算时按原文顺序分片，每片 1 次逻辑请求，切点优先落在附件编号或编号式样标题前，必要时附带只读 `parent_context` 供跨片父引用；每片只回本片标题、不回 `body`，宿主合并后按整节规则统一校验。单行连同 Prompt 仍超限、或分片请求失败时，该片标题不进大纲并记 `outline_directory_plan_failed`；全部分片失败时本次大纲执行失败。每份登记文档（主件、附件、补遗、澄清）各找一个格式章节锚点，按登记顺序各发各的请求（仅主件有格式章节时与单文档请求相同），每节的隐含复制窗口和不适用范围都止于本节末尾，不跨文档。补遗或澄清格式章节里的每一章记 `outline_directory_format_source`，写明来源文档和页码；不同文档出现同名格式时各章都保留，记 `outline_directory_format_conflict` 交编制人员核定，宿主和模型都不择一。
2. **格式补位（宿主 0 次调用）**：`submission_requirement` 点名且不在格式章节内的必交文件，宿主在引证页及前页找同名独立标题行（跳过已归属节点、格式章节页及明示「不适用」式样）补成 `outside_format` 候选章，按同文档原文顺序切分复制窗口（前章止于下一候选章、已有格式节点或格式章节页之前，并跳过页眉页脚与页码装饰行，保证正文行归属互不重叠），追加在主格式章节末尾（不按物理页码插队到封面或第一章之前），格式外原式的保留与事项归属分别结算。提交事项无适用条件或例外、点名的文件与同页原文标题引证相符、复制窗口含冻结表格时，宿主按来源网格逐表保留空白原式；同一事项可点名多张表。其他候选须有事项落位才保留。原文标注不适用的编号式样及其子表排除。补遗或澄清内联替换某张原式（无格式章节标题、证据页在补遗或澄清里）且格式章节已有同名章时，宿主在该补遗或澄清的引证页及前页找同名独立标题行补成一章，记 `outline_directory_format_conflict`；这一章不是 `outside_format` 候选，不因无事项落入而删除。
3. **事项归属（`item_placement`）与待核过滤**：按预算分批（每批 ≤ `120` 条，且多条一批时输入不超过准入输入预算的一半），每批都带完整位置目录与本批事项语义字段（不重复发送引证摘录 `evidence`）；单条事项连同位置目录仍超出准入预算时不发送，与未采纳批次一样记 `outline_item_placement_failed` 留待核，不中断执行。单条事项未超过整窗时仍单独发送。每批 1 次逻辑请求，模型只回位置短 ID、理由代码（`evaluation`/`performance`/`document_wide`/`not_applicable`）或 `null`（待核；解码将字面字符串 `"null"` 归一为 `null`）；宿主落账为 `rule_refs`、`constraint_rule_refs`、`outline_rule_excluded` 或覆盖台账 `pending`。`outline_directory_literal_pending` 仅保留落入大纲实际复制窗口的页/行，不把非格式页的重复表行混入大纲待核。
4. **方案子大纲展开（`proposal_outline`）**：对已挂知识应答位、无固定原表且归属规则数 ≥ `6` 条的开放编制方案章，宿主汇总本章规则摘要与对应招标文件原文小节标题清单（同时涵盖评标办法与采购需求），并发发起有界模型请求（结果按原章节顺序落账）按招标文件实际层级生成多级子章节树（不限于三级，支持二级/三级/四级及以上）并按短 ID 分配全部规则。输入装不下准入预算一半时，自动拆为「1 次仅基于小节标题与评分摘要生成子章节树 + 复用 `item_placement` 半窗分批把本章规则归属到子章」。宿主校验树深度（相对父章 ≤ 5 级）、无环、ID 唯一且规则 100% 守恒（`null` 留父章总述），并裁剪未承载任何规则的空生成叶节；调用失败或拒收时保留父章原单目标应答位并记 `outline_proposal_structure_pending`，不阻断大纲与导出。

### 新链方案正文与评标待核

补遗、答疑的原式可以作为来源明确的候选随草稿出件。逐份引用同一文件的效力条款才结算该文件的优先依据待核。格式标题及同名原式只定位材料，未决提示随大纲、Word 与交付包待办保留。

- **方案知识应答位与多级展开**：唯一手填原式、标题以“方案”结尾且原式为纯编制指引的方案章，宿主保留原式说明并在其后追加知识应答位承载归属规则；当规则数 ≥ `6` 条且存在模型执行器时，由 `proposal_outline` 按招标文件要求与评分维度展开为多级子章节（不限于三级，规则总数严格守恒，失败优雅降级为单目标待核）。
- **评标待核裁决**：归属返回 `evaluation` 先留 `pending`，编制人员经工作台抽屉/大纲保存 `evaluation_decisions` 显式裁决去向。
- **方案原文上下文**：经 `source_additions` 绑定冻结主件背景段，仅在 Word 标注「原文上下文（非企业应答）」，不充当企业依据。
- **开标一览表项目名称**：宿主自动识别主件公告唯一项目名称并仅在《开标一览表》唯一空「项目名称」格回填；有补遗/不唯一/非空交人工手填。

## 编制实际模型调用

Web 端分大纲执行（`outline_only`）与正文执行（固定大纲）；保存 Word 后可单独复核。已保存版 [PDF 出件](workbench.md#pdf-与报告) 与常规组装新增模型调用为 0。下文均为逻辑请求数，每个逻辑请求各有合同纠正 2 次、传输重发 4 次的恢复额度；整次执行另受按阶段计划累计的运行级上限约束（见 [字段字典 · 调用、预算、恢复与修订](field-dictionary.md#调用预算恢复与修订) 第 7 条）。

### 大纲执行（一条要求链 `single_requirement_chain_v1`）

有冻结来源的自动大纲统一按一条要求链执行：

| 阶段 | 任务 / Prompt | 次数 | 随什么增长 | 单次输入与超限去向 | 代码入口 |
| --- | --- | --- | --- | --- | --- |
| 格式章节选择 | `directory_plan` / `bid_format_outline` | 每份含格式章节的文档 1 次（超限按原文顺序分片） | 格式章节数与分片数（通常 1） | 仅短标题行；单片超限或失败该片留待核并记 `outline_directory_plan_failed` | `select_bid_format_plan` |
| 事项归属 | `item_placement` | 按预算分批（每批 ≤ 120 条、多条不超过半窗） | 有效事项数与位置目录规模 | 完整位置目录 + 本批事项语义字段；单条超限或未采纳留 `outline_item_placement_failed` 待核 | `place_items` |
| 方案子大纲 | `proposal_outline` | 仅规则数 ≥ 6 条的开放方案章每章 1 次（超窗拆为 1 次仅树 + `item_placement` 分批归属） | 开放方案章数 | 本章规则摘要 + 原文小节标题清单；失败或拒收保留单目标位并记 `outline_proposal_structure_pending` | `expand_proposal_outlines` |

- 单次输入边界、跨片父引用与缺口规则见[新链格式补位与事项归属](#新链格式补位与事项归属)。
- 非冻结来源或整稿回退路径使用 `outline` / `outline_assemble`。

### 正文执行（固定大纲）与保存后复核

| 阶段 | 任务 | 次数 |
| --- | --- | --- |
| Q 知识检索 | HTTP（非模型） | 默认并发 `6` 调度去重检索词与已选资料版本并按输入顺序确定性归并；每检索词 1 次 `search`、命中文档各 1 次 `document`、需原件各 1 次 `file`（各最多 4 次尝试） |

## 运行时接口合同（证据层与模型层）

- **证据层**：`register_manifest(manifest, artifacts)` 持久化原件；`freeze_sources(registration, artifacts, ocr)` 在线程/进程池异步产出冻结索引（每文档 raw、每 pack 存内容寻址文件，checkpoint 只存引用）；`EvidenceRepository(artifacts).iter_packs` / `load_pack` 复用冻结 refs。OCR 回调只用于真实图片且不覆盖原件，文本 PDF 禁止静默全页 fallback；附件无正文记 `attachment_content_not_extracted`。
- **解析与分包边界**：
  - Excel 正文取唯一 row 范围、raw 留全网格、drawing anchor 补图片偏移、全空行压缩视图但留 `body` 身份、`display_incomplete_reason` 升级为可见问题；Word SECTION 保留原生定位；PDF 补齐 image occurrence，字形抽取跳过 PDFium 合成的零宽占位空格（`FPDFText_IsGenerated`）以避免表格与正文断字断数，重复页边与不可读图记 `partial`，原件损坏属技术失败。
  - `supporting` 只累计前文同节/祖先节条件与表头（混合小章包用 `scope_binding.applies_to_range_ids` 绑定）；无法切出完整条件句时写 `pack.pending_scope_context`（仅定位与 `scope_binding` 元数据，不含正文/表格/图像），模型空 findings 不解除阻断。
- **模型层**：`ModelConfig.from_env(mapping=None)` 单一配置源（可选大纲覆盖项 `KNOWLEDGEBRAIN_OUTLINE_MODEL` / `KNOWLEDGEBRAIN_OUTLINE_REASONING_EFFORT` 复用 Chat 端点与上下文上限，仅作用于 `outline` 作业，未配置时沿用 Chat）；`OpenAIModel(config, store, lease, prompts, concurrency=2, timeout_seconds=60).call(task, payload, images=())` 关闭 SDK 重试，仅接受本地图像字节/data URL；分析节点 `TenderNodes`、编制执行入口 `execute_document`/`generate_document`、保存稿复核 `execute_saved_review` 与知识检索（`KnowledgeProvider`/`WebKnowledgeProvider`/`_FrozenKnowledge`）均默认有界并发 `6`（模型请求共享进程内 429 冷却保护，知识检索并发不改变 `spec()`、HTTP 次数或持久化回执/重试额度）。
  - 默认连续 60 秒无非空原始响应字节超时（收到流字节重计时，不限总墙钟）；`timeout`、`retry_policy=split_transport_contract_v1`、`outline_source_binding_contract=batch_excerpt_coverage_v1` 计入冻结执行身份。
  - 请求状态 `prepared → sent → succeeded / failed / uncertain`（真实 usage 缺失留 `null`，收部分流后超时记 `uncertain`）；错误分 `ModelInfrastructureError` / `ModelSemanticError` / `ModelConfigurationError`；429 按 30/60/120 秒退避并持久化 `not_before`；同一进程内某端点收到 429 后，该端点的全部并发槽位在冷却结束前都不发新请求（冷却取 `Retry-After`，至少 30 秒、至多 120 秒；不跨进程共享）；首原始字节/首解码块/首非空正文/最大 raw 静默/排队耗时独立计量且不进请求身份。
