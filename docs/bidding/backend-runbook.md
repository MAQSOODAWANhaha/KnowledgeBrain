# 招投标运行与故障处理

设计、合同与任务状态以 [统一方案](../../plans/bidding/product-two-phase.md) 为准。本页不保留废弃流程的运行配方。

## 运行前

核对当前构建、数据库基线、冻结输入、模型与工具合同摘要及依赖服务。新合同不恢复旧检查点。服务地址、镜像和环境变量以当前部署配置为准，不从历史试验记录复制。

## 故障定位

- 解析：按文件和来源范围检查失败、缺页、图片及网格问题；不能仅依据 parse ready 宣称语义完整。
- 模型：区分请求预留、响应已存、工具提交；已存响应恢复不能再次调用供应商。
- 进度：查看扫描范围、要求映射、引用和核对问题，不把心跳或索引读取算作进展。
- 预算：检查首次执行绝对截止、累计物理尝试和读取量；重试不清零，不手改已冻结请求绕过预算。
- 发布：核对对象暂存、数据库收据、current 和 expected；版本冲突保留用户稿，不手工覆盖。
- 保存：区分 forcesave 请求和回调持久化，重复／乱序／过期回调不得更改新版本。
- 填充：不支持域、图片、签章、排版和章外内容时阻止有损重建，保留原稿。
- 导出：同版本 DOCX 转 PDF；失败明确报告，不回退旧正文渲染器冒充同版输出。

## 验证与记录

按主方案 T0–T9 和 A01–A20 定向验证。记录命令、退出码、样本和输出摘要、合同、依赖与跳过项。单测、隔离 PostgreSQL、真实模型、ONLYOFFICE 保存重开及 PDF 转换分别报告；零测试、mock、健康接口不算真实链路验收。

历史提取／复核轨迹保留于相关 results、review、diagnosis 文档与 artifacts；其中旧工具名、预算和继续运行命令不作为当前操作依据。不自动重启旧耗尽运行、不重置数据库、不删除业务文件。
