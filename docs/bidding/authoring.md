# 投标生成领域与状态归属

唯一业务设计与实施账本：[统一方案](../../plans/bidding/product-two-phase.md)。本页定义共享数据的归属，不维护第二条生成流程。

## 数据链

冻结文件集合 → 完整扫描范围 → 有据提交要求 → 要求与章节映射 → 摘要绑定的核对结果 → 已保存 Word 版本。

- 冻结输入包含文件角色、解析身份、来源、表格、补遗关系、处理决定和问题。
- 提交要求保存 ID、内容、适用条件、精确依据、指定格式及引用；不是关键词分割出的标题。
- 章节保存 ID、父子、顺序、用途、关联要求 ID、成立依据和格式依据。文本标题可以归纳，不能用于代替身份与覆盖关系。
- 组织性节点和正文承载节点分开；正文状态不决定大纲完整性。
- 不适用是要求的来源判断；未完成、解析失败和绑定失败是问题，不能混成省略状态。

## 状态与恢复

分配范围、投递确认范围、检查完成范围分开。Coverage 记录实际投递凭据，扫描结果决定发现进度。网格按实际范围计算，搜索不授予阅读或检查凭据。

Checkpoint 保存阶段、要求、大纲、引用、问题、核对摘要和预算；Session 可重建，每轮投递紧凑业务状态。Journal 负责原字节预约、响应持久化与原子提交，不代替语义核对。

输入／合同变更拒绝恢复。任务沿用 pending／succeeded／failed，阶段与原因是进度详情；不新增一套独立任务表。详细合同、工具和完成条件见主方案第 3–5 节。

## 文档与权限

Word 是用户正文主源，模型只能生成授权的空章内容。请求绑定主体、工作区、来源和 expected 版本；后端校验权限、幂等、租约与 CAS。稿件变化不反向修改冻结招标依据。

现行方案不包含 official／draft-fill 双模式、旧独立正式编制或强制终稿复核。新数据合同直接落新基线，不设计历史兼容转换；现存文件与历史证据不得因此被自动删除。

## 评审后固定边界

发布只由[主方案](../../plans/bidding/product-two-phase.md)第 3.4 节阻断清单决定，其他问题作为版本绑定提示保留。核对只能读取已保存核对片段，不能重新扫描全书。填充白名单仅普通标准段落、受支持表格及可重建 TOC；图片、签章载体、扫描件、自定义样式、页眉页脚、首章前非 TOC 内容和不支持的 DATE／REF 一律提交前拒绝并定位。字段落点使用主方案第 4.1 节，不另建 schema 或状态表。
