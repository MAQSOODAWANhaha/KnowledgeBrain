# 投标文件版本、保存与发布

生成合同见 [大纲运行时](../design/evidence-runtime-contract.md)。版本是编辑历史，不是草稿／终稿等级。

## 当前文件身份

工作区 current 指向具体版本与 DOCX 摘要。打开、保存、填充、导出均绑定具体身份，不能以当前章节标题替代版本身份。

ONLYOFFICE 回调持久化后才算保存成功；重复回调幂等，乱序／过期会话不能覆盖新版本。编辑器配置与保存协议详见 [docx-editor.md](docx-editor.md)。

## 生成发布与后续填充

现有 DOCX 新轮 API 接收文件并执行 `InitialDocx` 校验，前端客户端提供发布方法；自动从大纲生成首次 DOCX 与这些上传发布路径应分别核验，不能相互代替。

保存和导出绑定具体版本与 DOCX 摘要。运行期间用户保存了新版本，不能用提交时的 expected 覆盖。

对象先暂存，事务内登记文件版本、current 和任务结果；同一发布重放返回同一收据，不创建额外版本。错误留下明确任务状态，已有 current 不受影响。

知识库填充属于后续阶段，接入时必须读取冻结大纲，不改写用户已保存的正文；发布成功后刷新 current，下载不得继续使用缓存的旧 version_id。这是后续接入要求，不表示本轮已完成填充。

## 导出

下载必须指定已保存 DOCX。后续 PDF 导出须从同一 DOCX 转换，导出清单记录 source version_id、DOCX 摘要与输出摘要；后续编辑不改变历史导出，只使其不再代表当前版本。现有冻结导出来源 API、导出客户端及 `ExportPane` 已提供代码路径；当前候选的同版 PDF 与完整导出验收仍需独立确认，不以保存功能代替，也不据此写成导出尚未实现。

不要求先进入旧正式编制或终稿复核。转换失败、保存未完成和文件损坏仍必须明确失败；报告仅陈述实际执行的检查。

## 验收

重复请求、重复和乱序回调、并发保存，以及同版 PDF，按本页的版本身份核对。这些是验收要求，不是历史通过声明；不另设终稿复核门。
