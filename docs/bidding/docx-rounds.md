# 投标文件版本、保存与发布

业务设计与状态以[统一方案](../../plans/bidding/product-two-phase.md)为准。版本是编辑历史，不是草稿／终稿等级。

## 当前文件身份

工作区 current 指向具体版本与 DOCX 摘要。打开、保存、填充、导出均绑定具体身份，不能以当前章节标题替代版本身份。

ONLYOFFICE 回调持久化后才算保存成功；重复回调幂等，乱序／过期会话不能覆盖新版本。编辑器配置与保存协议详见 [docx-editor.md](docx-editor.md)。

## 生成与填充

首次生成绑定预期空版本，再次生成与内容填充绑定提交时 expected。运行期间用户保存新版本，CAS 必须拒绝覆盖。

对象先暂存，事务内登记文件版本、current 和任务结果；发布重放返回同一收据，不创建额外版本。错误留下明确任务状态，已有 current 不受影响。

填充以用户已保存结构为输入，原稿兼容性失败则不提交有损任务。成功后前端统一刷新 current；下载不得继续使用缓存的旧 version_id。

## 导出

下载指定已保存 DOCX；PDF 从同一 DOCX 转换，导出清单记录 source version_id、DOCX 摘要与输出摘要。后续编辑不改变历史导出，只使其不再代表当前版本。

不要求先进入旧正式编制或终稿复核。转换失败、保存未完成和文件损坏仍必须明确失败；报告仅陈述实际执行的检查。

## 验收

重复请求、重复和乱序回调、执行者切换、发布边界崩溃、并发保存、填充成功立即下载，以及同版 PDF 见主方案 A12、A17–A19。
