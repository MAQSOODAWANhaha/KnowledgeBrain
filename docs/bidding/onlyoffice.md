# ONLYOFFICE：编辑、保存与同版导出

生成合同见 [大纲运行时](../design/evidence-runtime-contract.md)。本页维护已有 DOCX 的编辑、保存和下载边界。知识库填充属于后续阶段，不作为本轮已实现前置步骤；不设独立正式编制或终稿升级。

## 正文与版本

DOCX 是正文主源。ONLYOFFICE 打开指定已保存版本，用户自由编辑；保存回调持久化后更新 current。不能只以浏览器已发送保存命令视为保存成功。

API 与编辑器通过版本、会话和用途绑定的授权访问文件与回调。保留过期会话、重复／乱序回调和并发保存的校验。具体配置、签名、缓存失效和回调协议见 [docx-editor.md](docx-editor.md)。

## AI 与用户内容

后续知识库填充接入必须只读冻结的 `OutlineArtifact`，不得改章节、规定文字或把用户已保存的正文交给模型重写。编辑器里的正文以已保存的 DOCX 为准。生成或填充期间用户若已保存更新版本，不能覆盖那一版。

不把编译中间结构当成另一份正文主源。

## PDF 与报告

PDF 导出须由同一已保存 DOCX 转换，输出绑定源身份。代码已有冻结导出来源读取、前端导出入口和指定版本 composition report 下载路径；当前候选的真实同版 PDF 与完整报告验收仍需核验，不能将“未验收”写成“未实现”。报告只能包含实际执行的检查和已知问题，下载报告的能力不能批准未执行的语义审查。

## 部署与验证

保留现有服务 origin、CommandService origin、API origin、JWT／用途签名、字体及许可配置。实际镜像版本以当前部署配置为准，不使用历史方案中的旧 pin。

健康接口只证明服务可达；必须验证真实文件打开、编辑、保存、关闭重开、下载和同版 PDF。历史环境／许可记录不能当成当前生产验收。技术说明见 [接入文档](../../plans/bidding/onlyoffice-integration.md)。字体、许可、最终模板外观和完整故障验收仍需落实，不能从健康检查推定完成。
