# ONLYOFFICE Docs：在线 DOCX 编制目标契约

> 状态：**方案已确认；普通实施与隔离开发验证已授权，任务见[实施台账](../../plans/implementation-tasks.md)**。ONLYOFFICE/DOCX 主链已有部分实现及隔离验证，真实 Agent 整稿与同版本 PDF 尚未完整验收；本文定义技术目标，具体完成状态以台账证据为准。
> 业务流程以 [`prd.md`](prd.md) 为准；本文定义编辑、保存、AI 入稿及 PDF 输出目标。
> ONLYOFFICE 编辑与出件的接入顺序见 [`../../plans/bidding/onlyoffice-integration.md`](../../plans/bidding/onlyoffice-integration.md)。

## 1. 决定与边界

采用 ONLYOFFICE Docs 在线编辑真实 DOCX，不再扩建以 Markdown 或 Tiptap/ContentBlock 往返转换为核心的正式正文链。ONLYOFFICE 是 DOCX 在线 Office，不是微软 Word，也不承诺与所有桌面 Word、字体环境完全一致。

用户仍只看见「文件 / 编制 / 导出」三步：

```text
当前招标文件集合 → 文件级解析或结果复用 → 要求与规范
                                              ↓
                                  初始 DOCX / AI 候选
                                              ↓ 用户确认
                                   ONLYOFFICE 在线编辑
                                              ↓ 保存回调
                                  我方持久化 DOCX 版本
                                              ↓ 冻结出件版本
                       同一 DOCX 下载 + ONLYOFFICE 转 PDF + 独立检查报告
```

- 未变更且已有可用结果的招标文件直接复用；新增、变更或无可用结果的文件才处理。
- 项目汇总包含当前完整文件集合；招标变化后开始新一轮整稿，不修补或自动合并旧稿。
- 报价表、价格内容和需提供附件全部编入一份投标文件；独立提交要求由用户导出后自行拆分处理。
- 检查报告独立提供。风险、缺失、待确认内容不形成业务编辑或导出闸门；技术保存、文件完整性和转换失败不能伪装成功。
- 解析工具内部的中间文本或 Markdown 可以暂时保留，但不是投标正文真源，本次不重写全部解析系统。

## 2. 正文与业务数据的归属

| 内容 | 正式来源与职责 |
| --- | --- |
| 正文、标题、表格、图片、分页及文档样式 | DOCX；在线编辑状态经回调持久化后形成我方可追溯版本 |
| 要求、表格规范、证据、报价、权限、检查结果 | 继续结构化保存；通过文档版本及目标定位关联 DOCX |
| OutlineNode / ContentBlock | 可用于业务映射、初稿生成或 AI 候选中间产物，不再是第二份正式正文 |
| PDF 与检查报告 | 绑定同一出件 DOCX 版本及其摘要；属于派生产物，不反向覆盖 DOCX |

不将用户编辑后的 DOCX 转回 Markdown/ContentBlock，再按旧树重建整稿。用户在 Word 中修改标题、顺序或表格后，后台不得按旧 OutlineNode 强制回写。

结构化报价或业务数据更新也不等于 DOCX 已更新：对应修改须作为待接受内容或经确认的定点操作入稿，并重新保存、检查。不得因快照存在就宣称报价表已出现在正文。

文档定位可采用经验证的书签、内容控件等稳定标记。它们关联要求、证据和候选目标，而不是让外部树重新控制全文。目标删除、重复或失效时，标记关联待核对，不猜位置、不编造覆盖结论。

初始 DOCX 可以单向生成。指定 DOCX 模板与固定表按招标要求处理，是否保真必须通过真实样稿验证；模板中的招标方附件或图片不得因此自动成为投标方证明。

当前优先交付的是整本投标文件模板：本项目全部章节及其层级、顺序、目录，与各章节内应填写的表格一起生成到同一份可编辑 DOCX。指定目录和格式优先，表头、固定文字、合并关系、填写区域及签署位置属于本期范围；不能用空目录或孤立表格替代整本模板。没有明确指定格式时，按本项目要求组织待确认结构，不套通用固定章节，也不把旧 Workspace 的已填正文带入新轮。

具体内容自动填充可后置：企业、人员、业绩、技术响应、报价等尚未取得或尚未自动写入的内容保留可人工填写的空位或待确认提示，不造事实。模板完成仅表示章节和表格结构可供继续编制，不表示这些要求已响应。后续自动填充仍须遵守候选确认、人工修改保护和保存入稿约束；内容填充的完整实现不作为本期模板文件生成的验收前置。

## 3. 复用与替换

继续复用项目/Workspace、对象存储、源文件解析与复用、来源身份、知识检索、证据和报价快照、候选确认、CAS/权限、异步 Job、独立报告及历史输出。

替换的是正文主写入与正式出件来源：

- 编制画布接入 ONLYOFFICE 编辑器，不继续双向同步 Tiptap 正文。
- 保存链持久化 DOCX 文件及版本身份，不再将正文保存等同于块 mutation。
- 切换后的正式 PDF 由保存的同一 DOCX 经 ONLYOFFICE 转换；不再独立按旧 ContentBlock 调用自研 PDF renderer 重排。
- 旧渲染能力如用于初稿，限于新稿的单向生成；不得用来重新生成已被用户编辑的正式稿。

迁移前的旧代码是存量实现，不因选型批准就删除，也不因此宣称新能力已接通。验收切换后不维持两份正式正文或两个竞争的正式 PDF 出件链。

## 4. 最小接入职责

以下是待实现职责，不是已存在的 API 路径或数据库 Schema。

### 4.1 打开编辑器

后端确认用户、项目、Workspace、新稿轮次与文档访问权限，生成编辑 config、文档读取地址及必要 JWT。前端只接收已签名配置并嵌入编辑器，不能自行选择其他项目的文档或签发权限。

ONLYOFFICE 编辑服务负责在线文档会话；我方仍负责受控文件读取、持久化存储、版本、授权及导出记录。文档服务能读取文件不代表该地址可以公开匿名访问。

### 4.2 会话与文档版本

ONLYOFFICE 的 `document.key` 是编辑服务会话/缓存身份，不等于我方每次持久化 DOCX 的版本号。按官方生命周期建立会话与项目、新稿轮次、打开基线的绑定；不在每次回调后随意换 key 造成活动会话分裂，也不能让新一轮稿复用旧会话身份。

每份可出件文件必须有可核验的 DOCX 对象、摘要及版本身份。沿用既有不可变对象和 CAS 思想，不先设计新的通用版本平台。

### 4.3 接收保存回调

回调处理必须：

1. 校验签名、回调状态，以及会话与文件所属项目、新稿轮次的绑定。
2. 只在对应保存完成状态读取文件；状态 `2` 表示 ready for saving，`6` 表示 forcesave 完成，`3`/`7` 是保存错误。其他状态按官方语义处理，不能全部下载并称保存成功。
3. 从受信文档服务读取文件，校验格式、大小及内容完整性，持久化对象并计算摘要。
4. 通过经校验的版本关联提交文档版本；持久化失败不能推进当前稿或返回保存成功确认。
5. 按回调协议返回结果；技术错误保留可定位状态，不能只在前端提示后丢失文件。

重复回调应幂等；旧会话、新轮错配或过期回调不能覆盖新稿。同一会话内多次保存的幂等、新旧关联及乱序保护必须在接入实现中明确并测试，不能仅按回调到达时间认定“最新”。无法确认新旧关系时不得推进当前版本。

### 4.4 先保存，再导出

浏览器显示保存中、ONLYOFFICE 已接受 forcesave 请求、我方已持久化 DOCX，是不同状态。发出 forcesave 不等于保存完成。

导出当前稿时先确认该次编辑状态已通过保存回调持久化，再冻结具体 DOCX 版本。若用户持续编辑，明确本次导出对应的已保存版本，不把其后的编辑混入该次输出。

保存未确认、失败或版本冲突时，显示等待或明确失败；不能静默取旧文件并标为“最新稿”。下载历史版本可以独立显式选择，但不能成为绕过当前稿保存失败的隐式回退。

## 5. 安全与部署前置

- JWT 签名在后端完成，secret 不进入浏览器、前端配置源码或日志；编辑 config 和服务间请求、回调按各自方向校验。
- 文件读取授权限制项目、具体文件及用途；回调不接受客户端任意指定项目、存储位置或目标版本。
- 回调下载和转换读取校验受信源、协议、主机、重定向与访问范围，设置响应大小、超时等资源预算。不因 JWT 有效就抓取任意 URL，不开放全网任意抓取。
- 部署明确浏览器、API、ONLYOFFICE 与对象存储之间可达的地址及凭证边界。私有服务地址只能在明确允许的服务范围内使用，不全局放开内网访问限制。
- 使用授权允许、已验证的 ONLYOFFICE 版本及固定的部署字体环境；确认并发、嵌入、生产使用与 API 权利，不默认免费无限制。
- 普通实施与隔离开发验证已获授权。本地 runtime Compose 已包含 Community Document Server（`onlyoffice`，见 `deploy/.env.example` 的 `KB_ONLYOFFICE_*` 与 `ONLYOFFICE_HOST_PORT`）；缺项时编辑入口 fail-closed。Community 不代表生产嵌入许可。O0 字体/并发/生产许可仍须核实，采购、生产部署、现有数据操作及提交不在此次授权内。

## 6. AI、报价与证明入稿

AI 仍只生成候选。已有事实需要投标侧支撑，拟议方案可以先作为待确认草稿；招标要求和招标图片不能被改写成我方已具备的事实与证明。

候选绑定生成时的文档版本、目标定位和支撑资料。用户接受后，通过获许可且经验证可用的文档接口或插件定点修改 DOCX；接受前校验目标和当前编辑状态，不在后台覆盖用户正在修改的整稿。写入后仍须经过保存回调确认，不能只因客户端命令已发出就宣称入稿完成。

初稿阶段可以一次性生成 DOCX；已有用户编辑后不得以“重新生成候选”为由整本替换。定位失效或版本不匹配时让用户重新核对候选，不自动猜测插入位置。

**选定 ONLYOFFICE Docs 不等于选定或购买外部 Automation API，本方案没有采购决定。** 普通在线编辑、保存回调、后台生成 DOCX 初稿及 DOCX→PDF 转换不依赖该附加 API；仍须核实 ONLYOFFICE 本体的部署、嵌入许可及选定版本能力。

AI 定点入稿可优先验证**编辑器内官方插件**：通过插件自定义 UI 调用我方知识库/生成服务、展示候选，用户确认后使用公开插件 API 插入内容。例如插件可通过 `executeMethod` 调用 `PasteHtml` 插入 HTML；这不自动保证复杂表格保真、目标定位或并发修改安全，仍需验证上述目标校验、人工修改保护与保存闭环。

只有采用**外部 Connector 从我们网页直接操控打开中的编辑器**时，才涉及外部 Automation API：该 API 仅面向 ONLYOFFICE Docs Developer，且是额外收费能力。它不是所有 AI 功能或基础接入的必买前置；不得把插件与外部 Connector 视为能力完全等价，也不得承诺插件可免费商用。插件能力和所用产品部署/嵌入许可仍需分别验证。

只使用公开插件或已获许可的文档 API，不通过跨域 DOM 或私有协议绕过。采用能力未获验证或所需许可未确认时，只将相关能力记为未完成，不把尚未选定的外部 Automation 授权当作基础编辑或全部 AI 功能的阻断前置。

报价应根据固定表格规范把明细、税额、合计写入实际 DOCX，保留其结构化数据来源。需提供的证明附件必须以真实内容进入整本；文件名或对象引用本身不等于附件已提供。缺料可提示后继续，已选嵌入文件损坏则明确技术失败。

## 7. PDF、页码与最终报告

正式出件读取已保存且冻结的同一 DOCX，调用 ONLYOFFICE Conversion API 转 PDF，下载 DOCX 和转换后的 PDF，并独立提供检查报告。转换失败不能回退到旧自研 PDF 重排后仍宣称同一出件链成功。

同一引擎有助于减少格式差异，但“转换成功”不等于“证明页码正确”。Conversion API 的 DOCX→PDF 能力不直接承诺书签到最终页码的完整映射，也不保证桌面 Word 使用不同字体时分页一致。

证明引用的出件工序仍需实现和验证：

1. 保留文档中的证明目标与引用关系，辨认同一材料的实际出现位置。
2. 依据真实排版结果取得页码并回填文档；回填也是文档修改，须保存后再转换和复查。
3. 有限轮计算至引用稳定，最终 DOCX、PDF、映射和报告绑定同一最终保存版本。
4. 无法稳定时清除或降级未确认的确定数字引用并明确提示，且验证实际输出不残留错误数字；不能安全生成有效文件则技术失败。不得保留上一轮数字伪装稳定。

不能可靠取得映射的接口或版本，不算自动页码回填已验收。正文修改后重新保存、排版和检查，不重新解析未变的招标文件。

最终检查覆盖实际文档的报价、附件、引用和已识别要求，不能只检查数据库存在相应快照。报告绑定具体输出版本；随后修改当前稿，不改写历史输出的检查结果。

报告包含高风险、缺失、待确认及独立提交要求，不能写入正式投标正文。整本导出不代表单独提交要求已满足，用户拆分后自行核对目录、页码、证明引用和提交格式；系统不承担自动拆分或拆分稿验证。

## 8. 完成判定

方案已确认，普通实施与隔离开发验证已获授权；任务状态见[实施台账](../../plans/implementation-tasks.md)。已有增量或历史本地验证不代表接入运行验收。以下全部有真实证据后，才可宣称接入完成：

- 授权、部署版本、网络与字体配置满足采用能力的要求。
- 真实 DOCX 可以打开、编辑、保存、重开，合并表格、非等宽列、页眉页脚及图片附件经保真验证。
- 我方存储收到已验证文件；保存失败、重复、过期及乱序回调不导致丢稿或错稿。
- 当前稿导出等待正确保存，DOCX/PDF与报告身份一致，不静默导出旧文件。
- AI 通过批准接口定点入稿且不覆盖人工；价格和附件在实际整本中可核对。
- 页码反馈及安全出口经过真实排版验证，业务缺料可出件，技术损坏不伪装成功。
- 新链验收后撤除旧正式正文主写入与正式自研 PDF 输出入口，不保留双真源。
