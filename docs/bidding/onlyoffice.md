# ONLYOFFICE：编辑、保存与同版导出

当前业务与任务：[统一方案](../../plans/bidding/product-two-phase.md)。产品只有“大纲生成 → 可选填充 → 编辑保存下载”，不设独立正式编制或终稿升级。

## 正文与版本

DOCX 是正文主源。ONLYOFFICE 打开指定已保存版本，用户自由编辑；保存回调持久化后更新 current。不能只以浏览器已发送保存命令视为保存成功。

API 与编辑器通过版本、会话和用途绑定的授权访问文件与回调。保留过期会话、重复／乱序回调和并发保存的校验。具体配置、签名、缓存失效和回调协议见 [docx-editor.md](docx-editor.md)。

## AI 与用户内容

AI 填充是独立用户操作，读已保存版本、只处理空章。无法可靠保留图片、签章、域、排版和章外内容时阻止有损填充；编辑和下载原稿不受影响。填充成功刷新 current，版本冲突拒绝覆盖。

本期不实现完整 DOCX 定点插入或两份正文自动同步。编译器中间结构不成为另一份用户正文主源。

## PDF 与报告

PDF 由同一已保存 DOCX 转换，输出绑定源身份。报告仅包含实际执行的检查和已知问题，不是未执行语义审查的批准。

## 部署与验证

保留现有服务 origin、CommandService origin、API origin、JWT／用途签名、字体及许可配置。实际镜像版本以当前部署配置为准，不使用历史方案中的旧 pin。

健康接口只证明服务可达；必须验证真实文件打开、编辑、保存、关闭重开、下载和同版 PDF。历史环境／许可记录不能当成当前生产验收。技术说明见 [接入文档](../../plans/bidding/onlyoffice-integration.md)，当前验收记录统一进入主方案 T9。

## 评审后固定边界

发布只由[主方案](../../plans/bidding/product-two-phase.md)第 3.4 节阻断清单决定，其他问题作为版本绑定提示保留。核对只能读取已保存核对片段，不能重新扫描全书。填充白名单仅普通标准段落、受支持表格及可重建 TOC；图片、签章载体、扫描件、自定义样式、页眉页脚、首章前非 TOC 内容和不支持的 DATE／REF 一律提交前拒绝并定位。字段落点使用主方案第 4.1 节，不另建 schema 或状态表。
