# 招标解析之后的一次大纲

实施缺口见 [大纲计划](../../plans/bidding/outline-gaps.md)。本文是产品合同，不把未接通的投影写成已经交付的行为。

## 用户流程

1. 上传招标文件并等待解析完成。解析未完成时不能生成大纲。解析完成也不会自动开跑。
2. 用户点击生成大纲。一次运行依次做完发现、组章、规定模板和收尾，得到冻结的 `OutlineArtifact`。
3. 之后由 `response` 做知识库填充：只读这份冻结大纲，把投标人槽和签字槽填上证据或标成待人工补充。这一步不是 `DraftStage::Fill` 上的模板职责。`response` 不重新解析招标文件，不改章节，不改规定文字。
4. 用户在编辑器里改已保存的投标文件，保存后下载。需要 PDF 时从同一份已保存 DOCX 转换。

没有草稿编制和正式编制两条生成流，也没有强制终稿复核才能下载。

## 一次大纲里的四步

| 步骤 | 做什么 | 不做什么 |
| --- | --- | --- |
| 发现 | 按章节边界领取阅读包，提交该包里的要求；同一包失败后按字段错误再交 | 不写章节，不写模板，不查知识库 |
| 组织 | 写出章节树，每个附件表只绑定一个章节 | 不重新领取阅读包，不写模板正文 |
| 模板 | 用 `put_slots` 写入招标文件已经给出的文字。投标人槽和签字槽留空，并带 `match_query` | 不改章节，不填写我方报价、资质、人员或证书 |
| 收尾 | `read_outline` 核对章节、附件绑定和模板槽，然后 `finish_outline` | 不改章节，不重新扫描 |

章节用途只有两种：`group` 容纳子章节，`response` 是投标人作答的章节。分组章节不能带知识库响应槽。

## 三个包

| 包 | 产出 | 边界 |
| --- | --- | --- |
| `analysis` | 对冻结招标文件的记录、关系和修复 | 不发布章节，不写模板 |
| `outline` | 章节树、附件绑定、规定模板槽，收尾后成为 `OutlineArtifact` | 不评审分析记录，不匹配知识库。生成合同以这个包为准 |
| `response` | 按冻结大纲上的响应槽填写知识库证据 | 不解析招标文件，不改章节，不改模板。没有证据的槽保持 `【待人工补充】` |

`OutlineArtifact` 带项目身份和冻结输入摘要。响应结果用大纲摘要绑回这一份，不能绑到另一轮大纲。

## 记忆

不保留一份随运行增长的语义记忆。能恢复的状态在检查点里：发现进度、工具草稿和阶段。会话只复用当前窗口里的模型对话。
