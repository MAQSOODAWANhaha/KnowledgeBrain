# 一条要求链：编制改为消费分析台账

2026-11-19 决定。属于[修复与改进路线](improvement-roadmap.md)的 W2。做完删除本页，结论并入业务工作流、字段字典和验收。

## 决定

1. 分析事项台账是编制唯一的要求来源。编制只决定「放在哪、怎么写」，不再逐原子重新分类全部原文（BUG-254）。以第 2 步实测为准，实测不达标再回来改决定。
2. 保真范围：原式表格、固定文字、签章位置照原样，由宿主从冻结网格复制。其余正文用解析文本加引用。解析瑕疵记为解析器缺陷，不进编制链。
3. DOCX 接缝：整稿重新生成产出新稿，不合并旧稿。编辑后由 AI 出候选并定点入稿的能力推迟，当前只交付「整稿加人工编辑」。
4. 第一份真实文件通过最低验收线之前，不新增协议或阶段。只修缺陷和做本计划。

## 目标链路

```text
分析  register → freeze → extract → verify → [confirm]  → 事项台账（带证据引用）
编制  ① 结构：格式章节 + 提交类事项 → 分册、章节、原式表
      ② 归属：事项短 ID + 章节树短 ID → item_id 对应 target_id
      ③ 原式填充：宿主复制原表，模型只填有依据的格子
      ④ 依据 / 写作 / 复核 / 改稿（沿用）
      ⑤ 导出 DOCX → ONLYOFFICE
```

## 五问

1. 调用：分析 P；编制 = 结构 k（格式章节包数）+ 归属 ⌈事项数/批⌉ + 依据批次 + 写作 T + 复核批次 + 至多 1 次改稿和 1 轮再核。都随事项数和任务数线性增长，没有读全文的请求。
2. 单次最坏输入：各阶段按预算分包。结构只读格式章节，装不下按章拆。
3. 新问题和出口：分析漏报会让标书漏项，出口是分析待核或修订；事项归属不到位置进缺口清单，用户在 Word 里安排；解析错误进解析器缺陷。
4. 修订：来源变化重跑受影响的包、受影响事项的归属和任务；只改事项时重跑所在归属批次和关联任务。
5. 誊写：归属和填格只回 ID 和填值。

风险：分析的语义验收也是 0/4，所以先做纵切实测再切换。
