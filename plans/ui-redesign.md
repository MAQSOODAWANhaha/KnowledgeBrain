# 投标台 UI 全面重设计

## Context

现网 `web/`（Vite + TS，hash 路由）功能能走通，观感是空米黄纸 + 细线按钮，被判「完全没有设计」。

你已拍板：

1. **全部屏同一水准**（登录、标列表、条款、勾选、预览、资料、产品）
2. **重新设计**：条款不再做成「一篇文章 / 中间一张稿纸」
3. **失败标准**：看起来不专业

这是 Operate 整站换世界，不是打磨旧 `DESIGN.md`。产品事实不动：测试模式可空登录、条款人确认、系统排序人勾选、过程 Word / 定稿 PDF、⑥ 不做、招标文件不进产品库。

## Approach

做成 **标书案卷台**：白天办公、浅色、一种无衬线、信息密度够、控件像仪器。不要博客稿纸，不要后台卡片宫格，不要深色赛博。

共用壳：顶栏（当前标 / 阶段 / 人）+ 左栏导航（投标 / 资料 / 产品），七屏同一套按钮、表、空态、载入。

各屏：

| 屏 | 新结构 |
|---|---|
| 登录 | 左说明右表单；测试模式写清「直接进」 |
| 在办的标 | 案件表：名称、负责人、截止、派生状态；行内开标，不靠大片空白 |
| 条款 | **工作台**：上阶段条，左文件，中条款表（技术/商务、草稿/已确认、必须），点行右侧改文案/确认/偏离/补图。不是长文 |
| 勾选 | 候选表 + 覆盖率列 + 勾入；已选钉在上面 |
| 预览 | ①–⑤ 分册目录 + 正文，导出钉在顶栏 |
| 资料 | 四个分类夹表 + 上传 + `index_ready` |
| 产品 | 产品线/型号表 + 手册上传 |

状态一律进壳：解析中 / 抽条款 / 匹配中 / 失败可点 / 载入失败可重试。禁止整页只写「载入…」。

后端零改。`api.ts` 只补 UI 缺的字段。做成后作废旧证券纸 `DESIGN.md`，按实装重写。
