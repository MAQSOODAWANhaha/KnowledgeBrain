# 分段匹配 + 过程成稿

| 项 | 值 |
|---|---|
| 状态 | 已按「先商务」收口，待拍板开工 |
| 日期 | 2026-08-19 |
| 范围 | **投标应答卷**（①–⑤），不是装订递交的全套投标文件 |
| 过程 | 先商务资格，再按技术段选型写点对点 |
| 先改领域 | `docs/bid-platform-domain.md` §0/§5/§7/§9 与本文对齐后再迁表 |
| 不做 | 一条参数一个产品、全书一个排行榜、回写 .docx、LibreOffice、解析 MD 反推勾选 |

## 1. 现场过程（唯一主线）

```
上传招标 → 切段、抽参数（已有）
  → 【先商务】确认资格/业绩/商务条款 → 看 hit/缺件 → 补证或标偏离 → 编④⑤
  → 【再技术】按勾选段：确认参数 → 本段匹配 → 勾型号 → 人评/补图 → 编该段②
  → 编①③、随时 Word；齐了下 PDF
```

先商务：不够格可以少砸技术，但不做门闩（商务没做完仍可进技术段）。
技术：交换机段的参数一起为交换机找型号。不是一条参数一个产品，也不是全书打全部产品。
商务：公司级。`family=commercial` 即使抽自「第三章」也只进商务。

对外叫 **投标应答卷**。不含⑥（函/授权/报价/保证金）、不含买方表格套红。

## 2. 现在偏在哪

抽取按 `BidSection` 是对的。错在：全书一次 `/match`、项目级 `BidPick`、任一已勾产品命中就算 cover、成稿只读现算。

## 3. 模型

```
BidProject
  BidMatchUnit              勾选段 = 匹配单元
    = 一个 BidSection，或若干相邻节 merge_into 同一锚段
    clauses[]               本单元已确认 technical
    candidates[]            只按本单元参数排序
    BidSectionPick[]        (project, unit, product, version, 本单元快照)
  BidClause.assessment      unset | meet | partial | deviate | fail
  BidBooklet.parts[]        ① / 2:{unit} / ③ / ④ / ⑤
  commercial                仍打 company
```

- 解决方案 = **各勾选段已勾产品的并集**。不另建方案表。同一型号可出现在两段。
- 覆盖只看 **该条款所属勾选段** 的 Pick。`section_id` 仍是抽取段；沿 `merge_into` 走到锚才是勾选段。禁止环。无段手补进「未归段」。
- 人评挂条款。成稿 MD 另存。
- `BidMatchJob` 按勾选段 debounce（该段确认集哈希）。商务路仍项目级一次。

### 3.1 并段（第一期最小口）

匹配单元默认 = `BidSection`。相邻节可 **并入上一段**（`merge_into = 锚 section_id`）。  
3.1 一般要求 + 3.2 参数并到「核心交换机」后，共用候选和勾选，避免同一交换机构两次。  
多文件都有「第三章」：默认两段；人可并到同一锚。不做自动按标题合并。

### 3.2 成稿

```
BidBookletPart
  key            "1" | "2:{unit_id}" | "3" | "4" | "5"
  markdown       当前正文（GFM 子集）
  generated_at / edited_at
  stale          依赖的结构化数据已变
```

| 分册 | 生成依据 | 人改 | stale 当 |
|---|---|---|---|
| ① | 项目字段 + 各段已勾产品 | 综述、称呼 | 任一段勾选变 |
| ② 每勾选段一篇 | 段标题、本段产品、参数表、建议应答 | 措辞、说明 | 本段勾选/人评/参数确认集变 |
| ③ | 人评 partial/deviate/fail + 建议 unmet | 偏离理由 | 任一人评或 unmet 变 |
| ④ | 商务 hit | 材料说明 | 商务 hit 变 |
| ⑤ | must miss | 补救说明 | 商务 miss 变 |

- 第一次打开某 part：按当时数据生成。
- 数据变：标 stale，**不覆盖**人稿。人确认后「按最新重生成」。
- 生成 ② 每条已确认技术参数带锚 `<!-- clause:{id} -->`。人可改句子，导出时锚必须还在。
- `ended`：成稿只读，仍可下载。

## 4. 覆盖与人评

建议（现算，只对已确认技术、只看本段 Pick）：

| 建议 | 条件 |
|---|---|
| pending | 本段还没有 Pick |
| need_rematch | 有 Pick 但不含该条或 text/must 过期 |
| cover | 本段至少一个 Pick 该条 hit |
| unmet | 本段 Pick 均未 hit 且 must |
| uncovered | 均未 hit 且非 must |

人评优先写入 ②③ 的**默认句**，但不许用 `meet` 盖住建议 unmet（先换产品重勾，或改评 partial/deviate/fail）。  
`deviate`/`deviate_note` 迁到 `assessment=deviate` + 成稿句子。  
③ 含：人评 partial/deviate/fail，以及建议 unmet（未被人评成 deviate/fail 的）。

## 5. UI

进标 **默认落商务**（有商务 draft/缺件时）。商务做完或侧栏再进技术勾选段。确认都在当前段的表里完成。

```
侧栏                         主列                    检查器
本标                         [表 | 文稿]
  商务  ← 默认               表：确认 / hit·缺件        去补证 / 人评偏离
  勾选段（可并入上一段）     表：确认 / 建议 / 人评     本段候选 + 勾入去掉
  未归段                     文稿：该 part MD           当前条：人评、补图
成稿                         ①③④⑤ 与各段②，均可编
```

- 表：匹配与人评。文稿：标书句子。检查器 **没有**第二套应答编辑器。
- 没有「为这一条选一个产品」。
- 成稿目录：stale 黄点。导出前若有 stale 或漏 must，警告/拦住。
- 窄屏：侧栏、检查器变抽屉。

MD：一篇 part 一个有界编辑器。允许段、粗斜体、列表、表。禁止 HTML/YAML。不用 Plannotator 全书壳。

## 6. 导出

1. 缺的 part **先生成**再渲，禁止空本。  
2. 有 stale：警告，默认仍渲当前稿；可勾「先重生成过期分册」。  
3. **拦**：已确认技术 must 在所有 ② 里找不到对应锚。  
4. 顺序：① → 各勾选段②（侧栏序）→ ③ → ④ → ⑤。  
5. `pulldown-cmark` + `docx-rs` / `printpdf`。图=锚附近 BidShot + MD 里的 `objects/…`。  
6. 不回写 docx。⑥ = 新 part + 同一渲染器。

## 7. 不做 / 已知限制

- 一条参数绑一个产品；全书一个排行榜；解析 MD 反推勾选/人评
- iframe PDF；LibreOffice；回写 Word
- ⑥ 函/授权/报价；买方规定表格套红
- 正/负偏离分列（优于招标写在②句子里即可）
- 答疑不作废链：已确认参数手改 `text` 后重勾该段
- 不解析②措辞是否与人评打架，校核靠人
- 商务不做门闩：未做完商务也能进技术段

## 8. 落地

## 9. 验收

- 交换机段排序只看该段参数；勾交换机不让存储段变 cover  
- 3.1 并入 3.2 后只勾一次产品  
- 本段确认即可匹配，不必先确认其它段  
- 商务句抽在技术标题下也不进该段候选  
- 删掉 ② 里某条 must 的锚，导出拦住  
- 改勾选后② stale，不自动改人写的句子；重生成才换  
- 从未打开过的①，第一次导出仍有扉页  
- ended 后不能改稿，能下载
- 进标先到商务；侧栏可进技术段
- 导出物是应答卷，不是装订递交包
