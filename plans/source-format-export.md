# 来源格式与 Word 导出

## Context

投标文件只产出 Word。招标原文可以是 PDF、DOCX，表格类还可以是 Excel。三种解析都冻结成同一批来源对象。Word 要盖住的是这些对象上已经记下的格式，不是再做一套 PDF 版式，也不是另交一份 PDF。

这次是 PDF。合格条件表和评分表已经按格子画成表。后文「现金流量 / 表」仍被拆成五段，因为折行留在正文里，导出还没回来源上判断它是不是真段落。不把 Word 排成与原 PDF 逐页一致。

## Approach

来源存格式定义，只存一份。给模型的是判断所必需的阅读数据，不是把格式定义整份扣掉，也不是再复制一份进请求。导出只按模型返回的引用回来源取格式。模型不返回表格、列宽或换行。

必须给模型的，现在的紧凑视图已经在给，这次不加也不删：

- 表：`grid.rows` 里的格子明文。空字符串是原生空格，`null` 是没有独立单元格。`merged_cells` 只列非 1×1 合并。没有这些，模型分不清评分标准、合格条件和待填空位，也会把一张表当成一段话。
- 正文：该范围的阅读文本，`text` 或共享后的 `text_lines`。折行留在文本里，模型能读懂「现金流量」下一行是「表」。
- 身份：`part_id`、`range_id`，以及这段是模板还是摘录。模型只回这些引用，加上有依据才写的应答。

只留在来源、不进请求的：列宽、字体、页边距、页坐标，以及 `paragraph_breaks` 的字符偏移。偏移不帮助判断含义。同一张表不要把格子再复制进每一行摘录；行摘录给阅读串和 `range_id`，整表格式在对应模板上给一次。已保留且本次没点名的正文和表，继续只标 `retained`。

所以这次不改请求形状，也不增加调用。缺的是导出：拿到引用后回来源，用格子画表，用 `paragraph_breaks` 区分真段落和 PDF 折行。

| 来源里已有的格式 | Word |
| --- | --- |
| 格子 | 画表。只选中部分行时带上表头。空应答留空 |
| `paragraph_breaks` 上的切点 | 新段落 |
| 没有该切点的换行 | 并回原句。字中间断开的也并 |
| 上一行以 `。！？；：` 结束，或下一行是 `13.`、`（1）`、`一、` | 新段落 |
| 多页重复的短行 | 不写入正文 |
| 图片 | 嵌原件 |

同一条要求既在表里又在后文里，两处都留。表画表，正文并段。`###` 只在显示时去掉。

`text_boundaries` 只说明片段有没有顶到原范围两端，不能单独决定合并。切点要回来源上的 `paragraph_breaks` 核对。`materialize` 会从摘录结果里拿掉这个字段，所以导出回查来源范围，不把它抄进摘录或模型请求。

## Files to modify

- `services/docreader/tender/authoring_export.py`：正文导出按来源判断分段。
- `services/docreader/tests/unit/test_response_table_export.py`：PDF 折行与 DOCX 真段落各一个用例。

不改提示词、组装请求和 `authoring_view.py`。那里已经负责把阅读文本交给模型，并在修订时去掉未点名的正文和格子。

## Reuse

- `_flow_lines`、`_hard_paragraph_break`：折行规则已在 `authoring_export.py`，正文路径还没调用。
- `_selected_grid`、`_grid_rows`、`table`：PDF、DOCX、Excel 的表都走这里。
- `paragraph_breaks`：`evidence/packing.py` 只记 DOCX 的真实段落。
- `load_source_excerpt`：继续只给正文，不返回格子。
