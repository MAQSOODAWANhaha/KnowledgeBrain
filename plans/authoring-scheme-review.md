# 编制实现方案审查

## Context

目标仍是：招标文件已经确定的结构留在稿里，有资料才写应答，没依据就留空。模型只做显式判断。宿主不誊写、不猜测适用范围，也不把侧车诊断当成正文已经有了。

上次把根因收成“会话持有结构”，这个方向对，但收法本身不自洽：它让宿主把续表条件抄到另一张表，又把未分配要求放进技术响应表。这两步都是语义归并，和“宿主只比较精确来源、模型判断是否同一张表”冲突。下面先列现有设计里不能同时成立的规则，再给一套不再互相否定的收法。

v3 已经同时采纳 A0、F0、A1，三分卷和空应答都在，缺行、缺条件和页首仍在。所以这些不自洽不是断连造成的。

## 不能同时成立的设计

1. **同一张表有三套继承结果。** 字典写：省略 `response_table` 就继承前版或候选表；重交不完整就保留各份原表；BUG-102 又写必须重交全部 `context_range_ids` 和原行，重组才生效。代码在判定“已经交全”后执行 `table_context = explicit_context`，没被再点名的条件消失。同一次模型回包无法预知会继承、保留还是替换。

2. **目标禁止誊写，合同把誊写当成生效条件。** 架构要求宿主已绑定的行和条件不必由模型再写。BUG-102 把“再写一遍”当成保留它们的前提。模型少写一笔，结构就变。

3. **未分配要求没有一个合法的正文位置。** 逐条响应是交付目标。行又必须由模型选择，宿主不准补行。`outline_rule_unassigned` 只进 JSON 和覆盖侧车。导出仍可成功。于是“文件已生成”和“要求还在”可以同时为真，打开 Word 却看不到要求。把未分配要求直接塞进某一张技术表，等于宿主替模型做了归属，同样不成立。

4. **一个要求被做成两个正文目标。** 一个位置不能同时带原格式和响应表，合同用 `outline_conflicting_table` 拆开。没有原格式时又另造“待补”目标。导出两套都画。目标是一份原表、空位在表内，待补只是这个位置的缺口，不是另一章。

5. **来源给出的分卷判断会被宿主擦掉。** 只有原文明示的独立文件才是 `is_volume=true`，省略等于 false，这点和压缩视图一致。失败保全却把来源已经标成 true 的章节改成 false。下一轮 A1 的 `previous_structure` 看见的是 false，来源判断丢了。不发布正式分卷是对的，抹掉建议再让模型重判是另一件事。

6. **写作和复核对同一段文字标准相反。** 架构允许用招标原文写“可确定的背景/说明”。复核要求：应答位置上的规则复述即使转述准确也要 `reject_content=true`。模型按前一条写出的正文，会被后一条删掉。固定格式和背景事实又被复核排除在外。三句话没有共同边界。

7. **分析里的一种压缩解释，进入编制后变成左栏事实。** 未确认分析要继续编制，不确定解释应保持待核。BUG-124 的事项正文是被压短的一种说法。编制若把它排成完整响应要求，就是选定了这一种解释。

8. **会话、回放和人工稿各说自己是当前稿。** 编制执行按请求摘要复用整包回包。结构只要改成补丁，旧的整树回包就不再是这份稿。工作台的人工 Word 故意不随重渲染覆盖，覆盖统计还要版本、SHA 和执行身份一致。不能既说会话大纲是唯一稿，又说旧 A 回包和人工 Word 也是这份稿。

9. **文档自己还有三套流程。** 调用式同时有 `O+B+W+R+C+R改`、`L=S+A0+F0+[A1]+[F1]+B+W+Rb+C+R2`，以及把复核写成 `R`。F8.4 禁止改名，字段字典和 BUG-135 允许自动 F 使用 `chapter_renames`。验收还写“24 行”，这份文件是 17+14 行，另有两段未进表。BUG-136 台账写待实现，代码和 `test_assembly_fallback_hierarchy.py` 已经做了拼接。

## Approach

只保留一套修改规则。不再加节点、会话表或第二套树。

会话大纲是编制执行里的当前结构。模型回包只表达显式动作：排除、移动、标明同一填写实例、设置分卷、改标题、把一条已登记规则挂到指定表、拒收一块生成文字。没有点名的行、条件、模板和章节保持原样。调用失败、拒收或断连不改这棵树。

宿主不做的事也写死：

- 不因为两段文字相邻或标题像续表，就把条件抄到另一个目标。条件已经在这张 `response_table` 上，省略才继承。它只存在于另一张表，就继续只属于那张表，并在稿内留下待核，直到模型显式挂接。
- 不把未分配规则放进某一张技术表。已登记规则必须出现在导出的 Word 里，位置是“尚未归入响应表”的待核空行，左栏用已绑定原文。这是展示台账，不是判定归属。
- 不把来源的 `is_volume=true` 改成 false。未经过显式分卷动作时不导出独立分卷文件，建议仍留在会话结构里给下一次判断看。
- 已有原表的要求不再另造待补章。待补记在这个目标上，空位留在原表内。
- 事项正文被压短或分析未确认时，对应行标待核，不标已响应。

上下文只带这次动作要看的对象和它们已经绑定的原文，不把整棵树当成选择卷。旧的整树 A 回包不能当作补丁回放。人工 Word 仍是分叉：新导出是新候选，不覆盖已固定的人工稿；覆盖统计只描述这次导出的生成稿。

写作和复核用同一句边界：招标原文可以保留为固定格式或与用途相符的背景；放在应答位置代替应答的规则复述必须拒收并留空。

同配置下 A0 或 A1 再次在响应头前耗尽，停止再发。这只停止无效重试，不代替上面的规则。
