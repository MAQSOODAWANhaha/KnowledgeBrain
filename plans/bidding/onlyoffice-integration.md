> 状态：**方案已确认；普通实施与隔离开发验证已授权，切片状态见[实施台账](../implementation-tasks.md)**。ONLYOFFICE/DOCX 已部分实现并完成隔离验证，真实整稿、生产部署与完整验收仍未完成；本地结果不证明生产许可已落实。
> 业务以 [`../../docs/bidding/prd.md`](../../docs/bidding/prd.md) 为准；编辑、保存、AI 入稿和出件目标以 [`../../docs/bidding/onlyoffice.md`](../../docs/bidding/onlyoffice.md) 为准。

## 1. 实施边界

用户仍按「文件 / 编制 / 导出」操作。最终正文主源是 DOCX；报价、价格内容和需提供附件均进入整本。PDF从同一已保存 DOCX 经 ONLYOFFICE 转换，检查报告独立，用户自行拆分。

用户已授权普通实施与隔离开发验证，并已授权继续后续任务、直接在 main 修改；阶段 A 的只落盘限制是历史范围。采购、生产部署、现有数据操作及提交仍不在此次授权内，O0 的字体与生产许可前置仍须明确。共享工作区按切片文件划分，保留已有 agent 的 P2 改动；原有脏改动不能作为可清理的临时文件。生产实现不得硬编码样稿、业务分类或测试环境参数。

先证明真实 Word 可编辑、可保存、可重开，再接 AI 和高级检查。不先设计通用文档平台、大量新表或新的调度框架。

用户已确认尚未发布，涉及数据库的后续切片按 [平台 baseline 策略](../platform/runtime-foundation.md#2-fresh-baseline)直接修改所属 migration，不建设历史升级链。错误落库与数据库 CI 按 [平台 §7](../platform/runtime-foundation.md#7-实施与验收)收敛；完整 release 自动化、向量基准或 ANN 不是 O0 前置，也不豁免 O0 的环境/许可授权与首发安全验收。废弃的大纲业务链按当前授权直接撤除；核对并保留新链实际消费的共享原语，不操作现有开发数据。

## 3. O0 — 授权、版本与真实样稿 PoC

**当前证据：** [本地 O0 结果](../../docs/bidding/onlyoffice-o0-results.md)已记录用户真实 DOCX 的编辑、保存重开及同稿 PDF；字体基线、生产嵌入/并发许可与最终模板外观仍待落实。完整 O0 未验收；O1-S 的[后端新轮持久化接缝](../../docs/bidding/docx-rounds.md)已有验证，在线编辑和合成生成至保存重开也已接通，真实整稿仍待验收。

**实施前置：** 确定测试环境和可用的 ONLYOFFICE 版本、部署权限与字体；核实生产嵌入、并发及所需 API 的授权，不默认免费或无限制。未获部署授权时只准备样稿和验收方案，不启动服务。

- 选择真实投标 DOCX 样稿，覆盖合并单元格、非等宽列、重复表头、页眉页脚、中文字体、图片和附件页。
- 直接打开 DOCX，人工编辑后保存、关闭、重开；对照原稿检查内容与结构。
- 验证同一保存文件转 PDF的基本可用性，记录服务版本、字体及样稿摘要。
- 验证模板/固定表可读写范围，不沿用“禁止任何用户 DOCX 模板”的旧限制，也不承诺任意文档百分之百保真。
- 区分本体与附加 API：普通在线编辑、保存回调、后台生成 DOCX 初稿及 DOCX→PDF 转换不依赖该附加 API（外部 Automation API）。O0 核实本体部署/嵌入许可与版本能力，不以购买 Automation 作为基础 PoC 前置；选定 ONLYOFFICE Docs 不等于选定或购买该 API，本方案没有采购决定。AI 所需的编辑器内官方插件能力留到 O3 验证。

**验收：** 有真实样稿、保存重开文件及 PDF 对照结果，授权/版本前置有记录；不以编辑器成功加载或截图代替保存验证。无法保真的关键格式须明确，不直接进入切换。

## 4. O1 — 打开、编辑、保存与权限闭环

### F2 核心：招标理解与附表关联 Agent（已确认，实施中）

业务依据为 PRD §1.3、§1.4、§2.3、§2.5；本专题细化实现与验收，不重新定义业务范围。用户确认主 Agent＋独立复核 Agent，先交付全部章节、固定文字、声明格式、章内表格、填写说明和签署位置；企业、人员、业绩、实际报价和具体响应的自动填充后置。

**产物契约：** 完整冻结文件集合产生项目公共数据、编制规则、要求台账、模板/表格规范、待确认项。每条记录保留原文定位与依据，要求的人员/资格/评分等属性可并存；义务强度、适用性与模板用途分别判断。附件可以跨页并包含段落、子附件和多个表格，不能等同于一张网格。固定文字、招标侧已知值、投标侧待填区、说明和签章区分别记录，填写策略细到单元格。原始网格和语义模板分开保存。

**关系契约：** 明确引用、要求指定模板、附件包含子项、要求落到章节/字段、证明材料要求、跨表一致/汇总关系以及补遗修改关系均保存来源依据与核查状态，支持多对多。身份绑定来源版本和所属位置，编号只作显示。明确引用追查原文；推断关系标明依据并独立复核；无法消歧保留候选和待确认。不能按附件名称合并表格、默认全部适用或以最后上传替代本标解释规则。

**Agent 闭环：** 主 Agent 通过索引、分段读取、网格/来源区域读取、搜索、保存记录、查询缺口和请求复核等有界工具自主推进；所有可读来源必须完整阅读，未解析文件单列。取消关键词输入裁剪及默认 mandatory/required 判断，结构拆分只作定位。主 Agent 和复核 Agent 使用独立上下文；复核从全部原文查遗漏、从结果查依据，输出具体问题，主 Agent 修订后重新复核受影响结果。预算和重复无进展均有停止条件，中间结果不可丢失。招标内容为不可信数据，不成为工具或系统指令。

**持久化与接线：** 文件步骤沿用用户触发汇总和 RequirementSetCompile；解析按文件复用，汇总使用全部冻结来源及人工决定。分析版本包含五类产物、关系、阅读覆盖和复核结果；复用要求集合 payload 与 AgentRun/stage/boundary 记录，移除旧固定阶段约束，不新增通用存储平台。模型、工具、提示词和预算随请求冻结；跨 attempt 累计调用预算，复用平台 owner/lease/retry 原则。修改所属 fresh baseline，不新增历史升级 migration，不操作现有数据库。任务查询展示动作、阅读/引用/复核进度，分析结果按版本和类别分页，文件页可定位来源和关系，不新增强制确认向导。

**字段关系当前实现：** 已支持记录内区域、单元格及响应/证明/指标位置，关系绑定两端记录摘要，修改后重新建立并独立复核。相等/汇总关系不再仅指向整张附表，仍不执行自然语言算式。旧单次模型模板预览路径已删除；已在后续批次补分章 Agent 核心与真实 DOCX/位置核验，生产 worker、发布和界面接缝仍未完成。详见[分章实现与边界](../../docs/bidding/docx-composition.md)。

**初稿接缝：** 消费已冻结分析版本，分章组织整本 DOCX，并保存要求/模板到实际文档内容的映射。确定性工具校验真实文件中的章节、固定文字、网格及空位；不能用记录存在冒充已入稿。来源分析有误时创建修订版本，不改写冻结结果或用户稿。

**实施顺序与验收：** ①契约及独立样稿预期；②完整读取和覆盖工具；③主 Agent、独立复核、恢复和发布；④关系展示和实际 DOCX 消费；⑤撤除旧业务链和单次请求原型。真实 PDF 验证附件 1A–1D、8 及子项、G.1/G.2、2A 与 9 的金额一致关系、不适用附件、跨页表和表后说明；不同文件的同号附件不得串联。注入漏项、错链、错误适用性验证独立复核；A→A+B→补遗验证复用和冻结；中断、重复投递、过期 owner 和预算耗尽不得伪成功。确定性测试与真实模型全样稿分别记录，明确项不能全部标待确认逃避验收。最终 DOCX 必需章节/表格实际落位并在真实编辑、保存重开后保持。

**行业范围与解析复用补充：** 目标是网络安全行业各类招标，不限定当前防火墙样稿。文件解析统一由现有 Python `services/docreader` 提供，Agent 增量读取冻结结果，遇到版面/扫描疑点通过该服务回看原页或区域；不能新增业务侧解析器，也不能把原文件一次发送模型等同于完整提取。响应属性允许强制、逐条应答、评分等并存且逐项有依据；指标保留对象、数值、单位和条件。复核必须实际查看全部结果与关系，不能仅凭原文阅读量通过。当前逐步审查、替代方案、验证证据及未完成边界见[实现审查](../../docs/bidding/tender-analysis-review.md)。

废弃旧大纲业务链直接删除，包括固定章节映射、旧候选编排与其专用界面、脚本和测试。共享 Agent 执行、来源解析、对象及保存能力按实际消费者保留；共享工具使用当前职责命名，不保留旧设计作为备用生成路径。撤旧不等于新链运行验收完成。

- O1-S 当前优先交付整本可编辑 DOCX 模板：根据完整冻结招标输入生成全部章节、层级、顺序、目录，以及各章应填写的表格。指定格式优先，保留表头、固定文字、列宽/合并、填写区域及签署位置；不套固定章节、不仅输出空目录或孤立表格。企业/人员/业绩/技术响应/报价等具体内容的自动填充可后置到 O3-A/O3-M；空位可人工填写，不虚构事实或已响应状态。
- 后端按用户、项目、新稿轮次及文档版本生成编辑 config/JWT和受控读取地址；前端嵌入编辑器。
- 复用存储及对象校验。回调验证签名、状态、文件归属和受信下载地址后，持久化 DOCX、摘要及版本身份。
- 对保存完成、forcesave完成、保存错误和非保存通知分别处理；失败不推进当前稿，不返回伪成功。
- 区分编辑会话 `document.key` 与每次保存形成的文件版本；验证关闭、重开、forcesave和新轮时的官方 key 生命周期。
- 实现同一会话保存关联、重复幂等、乱序与过期保护，不以到达时间判断最新版。旧会话或旧轮次不能覆盖新稿。
- JWT secret只留后端；文件读取与回调权限隔离，下载校验主机/协议/重定向/范围及超时、大小预算，不允许任意 URL抓取。

**验收：** 整本模板的全部章节与章内表格可逐项核对，实际文件可编辑，人工填写并保存重开后结构和修改保持；不以上传文件或空目录冒充模板生成。保存重开恢复真实编辑结果；跨项目读取/伪造回调被拒绝；重复回调不重复发布；乱序、迟到旧会话和新轮回调不回滚当前稿；存储失败或损坏 DOCX不被标记为 ready。具体内容自动填充完整实现不作为本期模板验收前置。

## 5. O2 — DOCX 主源、同稿 PDF与独立报告

依赖 O1 的真实保存闭环，不能仅新增一个 iframe后继续从旧块模型导出。

- 编辑后的 DOCX是正文主源；数据库继续保存业务数据、来源和文档版本。停止从 Markdown/ContentBlock逆向重建该正式稿。
- 导出请求明确保存关联：发出 forcesave 后等待正确回调持久化，才冻结本次出件 DOCX；仅请求返回成功不算完成保存。
- 有未保存修改时不能悄悄下载上次文件并称最新。后续继续编辑不改变已经冻结的导出版本，界面明确版本边界。
- DOCX直接下载冻结文件，PDF由同一文件经 ONLYOFFICE转换；转换失败不回退旧自研正式 PDF链。
- 接通独立检查报告取得入口并绑定同一输出/文档版本；保留已有 JSON报告基础，不将当前页面提示替代历史报告。
- 报价和需提供附件进入整本；报告保留单独提交要求及用户自行拆分、拆后复核提示，不自动分册。

**验收：** 修改后导出的 DOCX/PDF均对应正确持久化版本；保存未完成/失败不产生“最新稿”假成功；旧输出及报告不随当前稿改变；报告不混入正文；缺材料仍可出件并有明确提示。

## 6. O3 — AI 定点入稿、报价附件与证据定位

基础编辑和出件通过后，AI 定点入稿优先验证编辑器内官方插件：调用我方知识库/生成服务，在插件 UI 展示候选，用户确认后通过公开插件 API 插入。可验证 `executeMethod` / `PasteHtml` 插入 HTML，但这不是复杂表格保真、目标定位或人工修改保护已通过的证明；仍须验证所用产品部署/嵌入许可及版本能力，不承诺插件免费商用。

仅在采用外部 Connector 从我们网页直接操控打开中的编辑器时，才需要 Docs Developer 加额外 Automation API 授权；不是全部 AI 功能的必买前置，也不能假定插件与 Connector 完全等价。未决定采购；只使用公开插件或获准文档 API，不以跨域 DOM 或私有协议绕过。相关能力和所需许可未验证时如实记为未完成，不把未选用的外部 API 采购当作全部 AI 的前置。

官方依据及插件边界见[技术契约 §6、§9](../../docs/bidding/onlyoffice.md)；不另起第二套接入计划。

- AI继续输出候选，保留来源、生成基线与目标定位；事实需支撑，拟议方案可待确认。
- 用户接受时校验文档版本、目标和人工编辑冲突；通过批准能力定点写入，随后确认保存回调。不整体覆盖已被用户修改的 DOCX。
- 按 PRD 招标文件指定目录/表格优先规划初稿，不强制通用五章节骨架；人员独立数据不等于必增专章。初稿可单向生成；已有文档标题、表格和顺序不被旧 OutlineNode强制回写。锚点丢失/重复时提示重新核对。
- 报价数据按招标表格规范确定性填入实际表格；需提供证明以真实内容嵌入，不能把快照、对象引用或文件名当作已提供内容。
- 验证文档目标标记到真实排版页码的可观测性；Conversion API成功不是页码映射成功。
- 回填后保存、转换并有限轮重检，最终文件、页码映射和报告绑定同一版本。不能稳定时清除/降级未确认数字并验证输出，不能安全出件则技术失败。
- 按实际文件补最终检查，报告持续区分未满足、待确认及技术失败，不把业务 warning变成 Gate。

**验收：** 用户改过的段落不被 AI覆盖；候选失效不误插；报价明细、合计和附件在 DOCX/PDF实际内容中可核对；长表换行、多页证明及不收敛场景不会留下伪确定页码；仅改正文不重新解析招标文件。

## 7. O4 — 真实回归后切换并撤旧入口

- 用同一测试项目走「正文及附件上传 → 要求/规范 → DOCX初稿 → 在线人工编辑 → AI候选确认 → 保存 → 整本 DOCX/PDF＋独立报告」。
- 用 A → A+B → A+B+补遗场景验证只处理需处理文件、汇总完整集合；招标变化开始新轮，新稿不沿用旧响应/检查/页码，旧稿可追溯。
- 无材料或存在高风险时可编制和出件；文件损坏、保存失败、转换失败及不可信页码不得伪装成功。
- 核对运行注册、权限、Schema及真实调用方后，撤除旧 Tiptap正文主写入和自研正式输出入口；中间生成原语仅保留有实际初稿/候选用途的部分。
- 不维持两份正式正文、两套竞争的正式 PDF输出或自动双向同步。新链未验收前不删除尚未替换的运行功能，不用旧链成功代替新链验收。
- 更新存量文档状态和操作手册；功能切换、代码删除、提交和部署仅在用户授权范围内，由父会话按实际交付证据裁决。

**验收：** 新链真实运行可复现，旧入口不再可写同一正式稿；没有依赖旧块正文的隐式出件路径，未被替换的源解析、身份与权限回归通过。

## 8. 聚焦验证与交付记录

实施时优先使用现有测试组织和隔离环境，按变更切片增加测试，不先跑无关全仓任务。计划中的检查不是本轮已经运行的测试。

| 类别 | 必须验证的结果 |
| --- | --- |
| 文档保真 | 合并表、非等宽列、页眉页脚、字体、图片附件保存重开不丢内容；PDF真实页可核对 |
| 保存协议 | forcesave请求与回调落盘分离；重复、乱序、旧会话、新轮、失败重试不覆盖新稿 |
| 授权与安全 | 密钥不入前端；越权文件/回调被拒；下载范围与重定向、资源预算有效 |
| 出件一致性 | 先保存后导出，同一 DOCX版本派生 PDF和报告，不把历史文件称最新 |
| 人工与 AI | 人工修改保留，过期候选/失效定位不自动套用，入稿后确认持久化 |
| 业务范围 | 文件复用、完整集合、新轮整稿、固定目录、整本报价与附件、用户拆分均保持 |
| 风险出口 | 缺材料可导出；报告独立；保存/转换/文件损坏和错误页码不伪装成功 |

每个切片报告修改文件、命令与退出码、真实样稿及输出摘要、服务版本/字体/授权前置、未通过项和剩余工作。区分 implemented、locally verified、committed、deployed、runtime accepted，不因文档或 mock测试通过宣称接入完成。

## 9. 后续实施边界

接入前重新读取源码及工作区差异；不得覆盖既有成果。ONLYOFFICE 编辑与出件顺序为 O0 → O1 → O2 → O3 → O4，文件解析与平台基础按领域契约复用，不要求先完成废弃的固定树/块编辑方案。普通代码实施与隔离开发验证已获授权，按[实施台账](../implementation-tasks.md)逐片实施、独立审查并由父会话验收；旧大纲专用链已按用户后续授权撤除，O4 仍需验证完整新链；采购、生产部署、现有数据操作及提交须对应的明确授权。
