# 招标解析与投标文件生成：统一设计与实施任务

更新时间：2026-09-18。

本文是招投标生成流程的**唯一现行设计和任务账本**。设计已确认；实现与验收状态见第 9 节。方案存在、代码已写或局部单测通过，都不代表产品验收完成。

## 1. 目标与业务边界

唯一用户流程：

```text
上传招标文件及补遗 → 解析完成 → 用户点击“生成章节大纲” → 冻结本次输入
→ 自动生成完整章节大纲和骨架 Word
→ 用户可选 AI 补充内容、自由编辑 → 保存、下载当前投标文件
```

大纲任务内部依次执行：**发现 → 组织 → 核对 → 发布**。这是一个现有 Worker 任务中的四个阶段，不是四个服务、四个 Agent 或四次用户请求。发现过程中可以暂存候选组织建议，但不能提前发布。

约束：

- 不区分草稿和终稿。取消 `official / draft-fill` 双模式及其业务门禁；单值 `mode` 不保留。
- 大纲生成和可选内容补充是两次独立请求；上传后不能自动填完整正文。
- 当前已保存 DOCX 是用户正文主源，ONLYOFFICE 承担编辑和保存；PDF 必须由同一已保存版本转换。
- 企业资质、报价、人员、证书、证明和实际响应未知时保留待填位置，不能由招标要求推断成投标方事实。
- 常见约百页文档以 5–10 分钟为优化目标。**完整性优先，超过 15 分钟仍继续正常处理**；不靠截取前几个窗口满足耗时指标。
- 首次大纲只有核对通过才发布；本期不新增“部分大纲发布”分支。失败保留进度和问题，已有保存文件仍可编辑、下载。
- 用户编辑后的文件含无法可靠保留的图片、签章、域或排版时，阻止有损填充，保留原稿；本期不建设完整 DOCX 定点插入系统。
- **不兼容。** 不读取旧字段、旧枚举、旧工具参数、旧 API、旧检查点，也不做别名、默认填充、双写或升级转换。缺字段或未知字段直接拒绝。`official` / `draft-fill`、字符串版 `issues`、用 `Omitted` 混装失败原因，都不是新合同。旧运行不能恢复。这不授权清空数据库或删除用户已经保存的文件。

“完整”表示冻结范围已检查、所有识别出的适用提交要求有去向、引用有明确处理结论且发布阻断清单为空；未解但不阻断的问题须保留在文件与界面。语义核对仍可能犯错，真实文件必须以人工标注清单验收，不能承诺数学意义上的绝对无遗漏。

## 2. 架构与职责

| 组件 | 职责 | 边界 |
| --- | --- | --- |
| DocReader | 正文、表格、位置、原图、解析问题及回读兼容性 | 不决定章节完整性 |
| 宿主 | 输入校验、分块、投递、阶段推进、工具校验、预算、发布 | 不用关键词切分结果发明必备章节 |
| 模型 | 识别提交要求、组织章节、语义查漏、空章模板内容 | 不改任务预算、数据库版本，不调用发布 |
| Checkpoint | 保存业务进度、要求、章节、问题和核对状态 | 是业务事实来源，不能依赖聊天历史恢复大纲 |
| Journal／Rig session | 请求原字节预约、响应保存、执行提交与重放 | 执行恢复不代替业务完整性 |
| Word 编译与版本层 | 同一章节树编译、对象暂存、版本登记和当前身份更新 | 不判断要求是否适用 |
| 前端 | 操作、进度、问题、编辑和下载 | 不另算一套完成状态 |

复用现有 Worker、Rig、Journal、Checkpoint、对象存储、租约、版本 CAS、DocReader、Word 编译器、ONLYOFFICE 和转换能力。不新增 Agent 服务、队列或平行状态机，也不新增领域表保存重复业务库存。

删除旧正式编制 Agent、仅服务旧流程的提示词／工具／配置／路由／调度／验收门。共享原文读取、模板、编译、权限、存储和版本能力保留。删除以实际调用关系为准，不能按目录整块误删共用能力。

## 3. 四阶段执行

### 3.1 发现：完整检查冻结输入

**输入合同。** 冻结用户选择的文件及解析版本、摘要、角色、补遗／替代关系、处理决定、来源和解析问题。文件未解析完成、缺页、失败来源或只有未读图像的页面不能静默跳过。明确补遗才覆盖旧要求；不确定冲突保留两侧依据并形成问题。

**分块。** 全部有效正文和表格进入确定性分块计划；按文件、原始顺序组织，关键词和标题仅调整优先级。取消 8 窗上限及索引截半。单个长来源按 UTF-8 范围续读；长表按行／单元格续读并携带表头；跨页条款携带相邻上下文，重叠不重复记账。每批容纳多个来源，依实际请求字节、上下文与输出额度组包，不一页一回合。

`structured_forms` 只是解析出的表格，不等于指定投标格式。表格用途依原文、引用和内容判断；`source_unit:<UUID>` 不能当业务表名。无 `heading_path` 的 PDF 使用同一条路径。

**发现结果。** 每批明确提交已检查范围、提交要求、跨章节／跨文件引用及问题。允许“本批无提交要求”，但必须有范围处理结果。索引遍历、搜索命中、部分原文、失败工具、被截断输出不能作为整批完成凭据。

提交清单覆盖组成、分册、顺序、指定格式、资格、商务、报价、证明材料、明确技术响应、方案和评分支撑。普通合同叙述、投诉流程、附件编号不自动成为章节。参数逐项响应通常映射响应表，不逐参数建章。

每条要求保存稳定 ID、描述、适用条件、精确依据、格式依据和待追踪引用。适用条件未知则保留条件性要求；只有明确不适用才可不映射章节。合并同义项须核对适用条件、范围与交付内容，并保留全部依据。

**阶段出口。** 全部有效范围完成检查、文件元数据已处理，跨文件引用均已定位或明确登记为 unresolved 并关联影响要求。发现完成不要求所有提示解决；它要求扫描完整、每条引用有去向而非静默丢失。未解引用是否阻断只由第 3.4 节判定。不以缺口数量两轮未下降中止正常扫描。

### 3.2 组织：要求映射为章节

- 用要求 ID 与章节建立多对多映射，禁止以标题包含匹配代替覆盖关系。
- 保存原始 `grounds`，不能校验后丢弃；章节成立依据与正文格式依据分开。
- 标题可合理归纳，字符串绑定失败不能删除必需章节。格式未找到则保留章节、登记问题。
- 原文明确的分册、层级与顺序优先；未规定时按内容归属组织，不强制三级、不限制只有三级。
- 要求技术文件跟随某卷结构时，实际追踪对应原文并展开；不能只生成空“技术文件”。条款编号不是章节编号，不能强制两个编号体系一致。
- 区分组织性节点与正文承载节点。组织节点不填正文；承载响应要求的父节点即使有子章也不能被“只填叶子”规则跳过。
- 批量变更按最终树原子校验：稳定 ID、父节点存在、同级顺序、无自引用、无祖先环、无孤立节点。删除或合并后要求仍须有去向。
- 不适用、尚未完成、格式缺失三者分开。不得继续用 `Omitted` 混装解析失败、绑定失败、超时和不适用。
- 预览和 Word 共用规范化章节树及过滤规则，不能分别提升子节点或删除父标题。

### 3.3 核对：既查映射，也查清单本身

宿主确定性检查严格使用第 3.4 节唯一阻断清单，不增加未定义的“关键问题”门槛。

**核对输入边界固定。** 仅输入已保存要求、大纲，以及宿主从发现阶段保存的依据中抽出的组成、指定格式、资格、技术结构／响应、报价、评分和补遗片段。扫描时即将这些条款保存为 `review_fragments`，包括判断没有生成要求的相关条款；不能只从已生成章节倒推片段，否则漏提项没有机会被查出。按精确范围去重，保留完整条款及必要表头、跨页续句，不以摘要代替原文。

顶层组成先单独核对一次，输入所有组成／顺序片段和各分册摘要。随后按分册组织核对包，输入该册要求、子树及关联片段。跨册条款作为共享片段引用，顶层不复制整份子树；修改顶层归属／顺序才使顶层核对失效，册内修改只重核该册及受影响共享关系。

核对工具只允许 `read_outline`、读取当前核对包内片段的分页／续段及提交核对结论；宿主检查范围，拒绝包外读取、全书索引、自由搜索和重新发现式翻页。发现包外疑点时提交带原依据和目标描述的问题，由宿主返回发现阶段执行定向查找，禁止从第一窗重扫。新证据补入片段并使受影响核对摘要失效。材料无法取得时登记 unresolved，按唯一发布门处理，不能无限检索。

**有效进展固定。** 每个问题保存最近两轮的语义签名：关联片段内容摘要、要求的内容／适用性／依据、关联章节内容／映射／层级／顺序、引用状态／目标／处置依据。排除时间戳、ID 重排、措辞化的修补笔记和缺口总数。宿主只接受与该问题有关且有来源支撑的字段变化；同一签名重复两轮或出现 A→B→A 循环均视为无进展。阻断问题无进展则任务失败并保留检查点；非阻断提示无进展则保留提示并结束该问题修补，不阻止其他核对和发布。核对结论必须匹配当前片段和大纲摘要。

该核对是生成内部阶段，不恢复逐页 Reviewer。一次初核加有进展的定向修补，不重新通读全文，不因提示未清零继续空转。

### 3.4 发布：核对通过且文件提交成功

**唯一业务发布门：核对包均有当前版本结论，且宿主派生的 `blockers` 为空。** 模型不得自行把 blocker 降级为提示，`issues` 非空不等于禁止发布。

| 阻断码 | 唯一判定条件 |
| --- | --- |
| B_SCAN_INCOMPLETE | 冻结有效正文／表格／元数据未检查完，或已知缺页、失败解析导致该范围无法检查 |
| B_REQUIREMENT_UNMAPPED | 适用／条件性要求无有效章节；未解引用决定必备子项或规定层级且无法枚举时，也属未覆盖，不能用笼统父标题冒充已映射 |
| B_TREE_INVALID | 环、孤儿、无依据章节、非法映射／顺序，或预览与 Word 不是同一树 |
| B_CONFLICT_FALSELY_RESOLVED | 冲突被标为已解决／不适用却没有依据，或编译偷偷选择某一侧；无法同时保留必要结构的冲突按 B_REQUIREMENT_UNMAPPED 处理 |
| B_FORMAT_EVIDENCE_MISSING | 适用要求明确指定格式但未保存有效原文／网格依据，或已保存依据失效、丢失 |

例子：引用外部标准只影响后续填写且不改变章节／格式时，保留 unresolved 提示，可以发布；引用“附件列明的全部资格材料”而附件缺失、无法列出必备子件时，B_REQUIREMENT_UNMAPPED；指定报价表取不到原表时，B_FORMAT_EVIDENCE_MISSING。未确定的适用条件保留条件性章节。可将两侧结构完整保留的冲突按 unresolved 提示交付，不伪造裁决。

非阻断问题在界面显示，并在 Word 中相关章下放系统标记的“待确认说明”；文末集中列出文件／来源位置和问题。该说明是编译产物，不增加虚构投标章节；回读按系统标记识别，不能把仅有提示的章误判为已有用户正文。用户修改提示后按用户正文保护。提示清单绑定发布版本，禁止只存在日志里。

核对尚未执行／摘要失效时任务未到发布阶段；读取失败、版本 CAS、对象或数据库错误是技术发布失败，不能由问题降级机制绕过。不额外建立另一套语义阻断门。

顺序固定：固化结果及核对摘要 → 编译骨架 → 校验可读取和章节身份 → 对象暂存 → 数据库事务登记结果、版本、current 和成功状态 → 前端刷新。

首次生成绑定预期空版本；重新生成绑定提交时 current。执行期间用户保存新版本则 CAS 拒绝覆盖。对象暂存失败不标成功；数据库提交失败可清理暂存；已发布请求重放返回原结果，不再编译和登记第二版。

超性能目标继续；到保护预算，或阻断问题持续无进展时保持未完成，不能自动发布部分骨架。用户已有 current 继续可用。

### 4.2 三种范围状态

| 状态 | 何时写 | 用途 |
| --- | --- | --- |
| 已分配 | 宿主选择工作包 | 调度 |
| 已投递确认 | 原字节请求／工具结果实际确认 | 引用权限 |
| 已完成检查 | 有效扫描提交成功 | 发现完成门 |

复用已有 Coverage 表示投递凭据，新增扫描完成范围；分配窗口不预写全源已读。文本按实际字节范围，网格按实际读取语义，不能用稀疏 cells 数冒充全部网格。工具结果在下一次确认边界前不可被同一响应中的后续写入当成模型已见依据。

| submit_outline_scan | 批量提交实际已检查范围、要求、引用和问题 |
| put_outline_items | 批量新增、修改、合并、删除章节，最终树原子校验 |
| read_outline | 分页恢复要求、章节、依据和问题 |
| submit_outline_check | 提交绑定范围和内容摘要的核对结论 |

宿主控制阶段出口，可提供显式组织完成操作；模型不能直接发布。批量父子节点支持批内临时引用，由宿主返回稳定 ID 映射。分页必须可继续，禁止只返回 truncated 却无法取尾部。读取允许跨窗口，但只能确认实际投递范围。

工具合同创建时冻结，按阶段限制可用操作，不在已预约请求上热改定义。删除旧标题关键词完整性工具和只有旧业务使用的工具。

### 4.4 Session／Journal

每轮从 Checkpoint 投影阶段、当前工作、相关要求、紧凑大纲、祖先与兄弟顺序、依据和问题。小树全量，大树顶层加当前分册，其余分页读取。历史消息可压缩，不能导致业务状态不可恢复。

扫描结果、章节更新、游标和阶段转换在既有提交边界一起保存。准备不推进业务，已预约恢复发原字节，已收到响应恢复不再次调用模型。清理核对上下文必须在完整工具批次处理后进行，不能在工具执行中破坏 assistant/tool 配对。

输入或合同摘要变化拒绝恢复。既有 pending／succeeded／failed 表示任务状态，阶段与未完成原因放进进度，不新增平行状态机。失败检查点保留用于诊断；不声称新合同可以恢复旧运行。

## 5. 预算、性能和异常出口

- 删除 8 窗、80 回合、20 分钟与固定两次尝试的领域捷径。
- `N` 定义为冻结输入经最终组包算法生成的**全部有效发现分块数**，包含长文本续段、网格续段和元数据，不是截断窗口数、来源条数或核对回合数。去重上下文不增加 N，首次创建即冻结分块计划摘要。
- 百页样本基线：已有 106 页／148 来源、124,776 正文字节、42 个表格，旧 8,000 字节按来源组窗离线计数为 20（未含完整网格序列化与元数据预算）。当前离线算法计入正文、网格、空来源及集合元数据后 N=204；废弃此前 20–60 的粗估。这是分块数量校准，不是模型耗时或完整性验收。T1 保留逐块字节、网格、范围及总 N，以实际冻结输入计算额度。
- 覆盖分块与模型阅读包分离：多个短来源在预算内合并投递；正文、网格和元数据仅按实际送达范围确认。游标指向首个未检查块，不要求每轮只检查一块；一次 `submit_outline_scan` 可提交多段结果。实际序列化预算仍由 evidence 投递层限制，分配来源不登记已读。 阅读包不再复用 8KB 常量：取工具结果上限、上下文字节上限的四分之一、预留输出 token 数的四倍的最小值（字节）。这是保守组包启发式，完整请求仍执行实际序列化和 token 估算校验，不宣称 token/字节精确换算。正文可跨记账块、表格可跨记账行片段，实际装不下时有界续读；扫描确认仍按实际区间累积。 完整请求包含历史、工具和状态后若超预算，发现阶段按当前包预算减半重建并重新校验完整请求，直至适配；禁止直接撤掉整包而静默退回自由补读。缩包是本地准备动作，不增加模型回合，也不修改冻结配置。实际包预算随已预留请求的 assigned_evidence.workload_bytes_limit 保存，收件和恢复按同一预算重建内容并校验相等，确认的范围只来自最终发送包。最小有效证据包也无法容纳时明确失败并保留检查点。
- `4N + 12` 仅为待校准初始逻辑保护额度，不能进入完整性判定。T1/T3 必须分别记录发现、补读、顶层核对、分册核对及修补的实测回合；不够则在新请求创建前调整冻结额度，不能运行中改合同或靠截断 N。废弃小输入帽 5／大输入帽 6 等旧断言，改验证全量范围与统一预算。
- 物理尝试、逻辑回合、读取量分别累计。冻结单次调用超时 t、最多三次物理尝试以及其最大退避等待 w；逻辑额度 L 的总时间保护值为 `L × (3t + w) + publish_reserve_secs`，发布预留固定 300 秒。作为运行保护，不承诺一般耗时。
- 首次领取在现有 run 记录确定绝对 `hard_deadline_at`；后续领取复制首次 started_at 和 deadline，不重新加时。剩余不足 300 秒时不再开始新的模型尝试；已有有效核对结果的检查点仍可领取并在绝对截止前完成编译发布。模型阶段的 timeout 不包住编译阶段，SQL 不因进入预留区而拒绝全部重试。SQL claim／heartbeat、分析 heartbeat、Worker 读取同一截止时间。Worker 处理上限是 `max(0, deadline-now)`，外加现有 30 秒只用于清理的 margin。
- T4 已改领取函数、插入约束和 Worker 读取；数据库故障注入尚未在本环境执行，因此不能标已验证。
- 保留短租约、心跳、owner fencing；心跳不等于业务进展。单个任务重试不能延长首次截止或清零花费。
- 到帽、取消、超时、未处理响应或检查未通过，统一走未完成／失败出口；禁止 finish/异常兜底编译、omitted(bind_failed) 或“有节点就发布”。T3/T4 联合覆盖每个错误出口。
- 输出调用数、输入输出量、范围进度、阶段耗时和问题。实测校准完成前 T4 不得标记已验证；不将全时限相乘的故障保护值当成百页正常耗时。

## 6. 可选内容补充与文件保护

填充冻结 current 版本／摘要、原招标输入、大纲结果、回读树／正文摘要和本次模型合同。先确认保存完成，再回读；未保存内容不能进入请求。

以用户当前结构为准。书签优先定位身份，但保留书签不代表标题和依据未变化。改名／改变归属的章清空旧要求关联、格式来源和窗口，再重新定位；单章也必须重绑。失败保留空章和缺口，不能以旧依据填新标题。

已有正文不交给模型改写，只处理空的正文承载节点。没有可处理章时返回无操作结果，不登记无意义版本。

**本期可重建白名单写死：** 编译器标准样式的普通文本段落（含标准章节标题）、受支持网格结构的表格、可识别并重建的 TOC。段落中的混合样式、特殊对象或表格中的不支持属性不能因外层类型是段落／表格而放行。

图片、签章、扫描件、自定义样式、页眉页脚、首章前非 TOC 内容、无法完整回读正文或保留语义的 DATE／REF、其他未知对象，一律提交前拒绝。普通域的可见正文先完整回读，不能直接丢段；本期未通过域语义保真验证的 DATE／REF 仍拒绝。只允许重建的 TOC 例外，目录标题按已识别 TOC 载体处理，不把任意首章前内容当作目录丢弃。

不开发签章语义识别器，也不承诺“签章可重建”：图片／drawing、嵌入对象、数字签名包部件及未列入白名单的载体统一拒绝，覆盖签章和扫描件；检测目标是载体与格式，不是识别印章图案。用户以普通文本输入的名称按普通文本保留，不据此宣称识别或验证签名。

DocReader 检查整份包，包含关系部件、正文、页眉页脚与首章前内容，返回 part、unit_key／ordinal、可获得的章节／段落／表格位置和拒绝原因。无版面页码时返回包部件及顺序位置，不伪造页码。不能“先 continue 丢掉内容再报兼容”。现有图片拒绝只是部分实现，首章前内容和样式检查未完成前 T5 不得验收。

失败不创建填充任务或新版本，原稿继续可编辑下载。编译超过上限时失败保留原稿，禁止删用户正文降级出稿。

用户主动停止填充可发布已安全完成的正文，但保留全部章节和未填章，明确剩余原因。这不是部分大纲发布，因为结构已经完成。

填充发布按原 expected 版本 CAS；冲突不覆盖。成功由 FillPane 通知工作区刷新 current，编辑器和下载使用同一新版本身份。

API：填充统一 `/docx-fills`，含 basis、latest、任务查询和 stop；删除旧 `/docx-compositions` 业务入口及别名。大纲入口沿用现有请求身份并更新合同。

当前 DOCX 可直接下载；PDF 从同版 DOCX 转换。不要求旧正式编制／独立终稿复核。保留权限、已保存状态、文件有效性和转换检查。报告只记实际执行的检查、源版本及问题，不伪造未执行的语义批准。
