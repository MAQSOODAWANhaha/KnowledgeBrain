# 章节要求

applicability.source_reference_exclusions 若有记录，body_windows 是已经核定本次不作为提交响应的参考范本正文，basis_windows/basis_text 保留其依据。不要将同一来源正文重新分配为 chapter/chapters 应答，也不要把参考范本仍在最终Word中解释为已经处理。记录不扩大为删除不同源窗的投标承诺；document 仅用于指南，仍需明确参考含义，未决可保留 unassigned，不虚造企业满足或外部履行。

下面给出一个未切开页面的原文分块，以及已经编译好的章节编号和标题。只为这个分块里的新要求选择起止行和归属。不要抄写原文，不要新起章节名。

章节中的 source_body 是该原式或附证位置已经选定的完整原文，source_obligations 是该章显式引用的补充义务，均为招标来源，不是企业已满足的事实。它们用于明确章节承担的材料职责；技术长章正文仍从本次block和已有章节层次判断，不要求在此重复提供。按材料职责、主体、适用条件及提交时点逐条核对归属，不能只凭附件编号、相邻位置或泛化标题猜用途，不能为安排位置而把要求挂到职责不相干的原式。无法证明由哪章承担时用unassigned保全待核，不虚造对应关系。

scope 只使用 chapter、chapters、document、unassigned。chapter 恰好选择一个已有章节；chapters 选择这些章真正共同适用的要求，不要把只属于一章的句子扩大到其他章；document 表示整份文件都适用；无法判断用 unassigned。chapter_ids 只能填写本次给出的章节 id。

优先把可定位的实质要求落实到实际材料、报价或技术应答章节。最高限价、报价有效期等不能只作为全稿问题清单而没有对应响应位置。评分表本身不作为投标原式，但其要求的资料、证明和方案仍须归属，区分评分项、否决条件及提交时点。原厂或其他主体专属义务、备选路径、触发条件和供货/投标/中标后等时点都要完整保留；不能把供货时证书改成投标时必附。

同一评分表可能混有报价、资格、业绩、人员、技术方案等不同指标。按各完整评分指标及其所需证明分别选择窗口，归给实际承担该指标的章节，保留条件和续句；不能选整张表，再把它作为共同要求分配给所有章。表名含“报价”也不能代替对各行实际职责的阅读。仅确实对所选各章都适用的同一项义务才用chapters；价格评分公式或报价计算规则归报价相关位置，不挂到财务、人员、业绩或售后承诺原式。评价操作及评分表格不要变成企业已经满足的正文。

本分块可能含通用条款，必须同时采用输入所给的全文件适用性上下文。某材料已被本次专用部分明确排除时，不把它的通用要求挂到另一个可选材料；存在原文分歧时保留条件和待核归属，不以单条通用条款覆盖专用不适用依据。投标承诺与中标后实际开立义务分别归属。

已经完整出现在章节模板正文里的要求不要重复报。每个窗口的起止行在同一页，且 end_line 不早于 start_line；一条完整要求可以跨页，首段使用 document_id/page/start_line/end_line，其后同一语义条款的续段用 continuation_windows 逐窗选择，缺省为空。首窗与续窗必须来自本次 block 的同一文件，严格向前且不重叠。

分页、换行和字词断开不是新的应答范围。同一完整义务、适用条件、例外及共同处罚后果应保留在一项 assignment 中，共用 scope 和 chapter_ids；不要把前页句尾与后页续句拆成两次应答，也不要将互相独立的义务强行合并。宿主按坐标复制全文，不要誊写或补写原句。跨出本次 block、无法取得完整依据的条款使用 unassigned 保留当前可见来源供完整性核定，不猜测块外坐标，不把残句当作完整要求挂到章内。

只返回 JSON，字段以宿主 Schema 为准。
