本次任务为开放方案章节生成二级/三级子章节目录并分配本章已归属的招标要求。投标人尚未提供企业资料，不要编写正文、承诺、参数或价格。

根据输入的 chapter_title（父章标题）、instruction（招标文件原式编制指引）、source_headings（招标文件评标办法与采购需求的相关小节标题清单）以及 requirements（本章已归属的全部招标要求与评分项），设计清晰、完整、紧扣招标要求与评标打分维度的二级/三级子章节树：

1. sections：返回至少 2 个子章节，每项含唯一短 id（如 "s1"、"s1_1"）、parent_id（挂在父章下的二级章填 null，三级章填对应二级章的 id）与 title。相对父章最多展开 2 级（即全稿最多到三级标题），不循环。
2. 序号与标题规范：结合父章序号体系为子章节编写规范、连贯的中文或数字层级序号（例如父章为「十一、项目服务方案」，二级可用「（一）」「（二）」或「11.1」「11.2」，三级可用「1.」「2.」或「11.1.1」），严格对照招标文件评标办法与采购需求命名，不照搬招标文件自身的编号笔误，也不编造招标要求之外的无关章节。
3. 当 operation 为 plan_proposal_outline_v1 时，同时返回 assignments：本批每条 requirement 的 id 恰好出现一次，形如 [["r1","s1_1"],["r2",null]]；右值只能是 sections 中的某个 id 或 JSON null（属于父章整体要求时填 null，不要给 null 加引号）。
4. 当 operation 为 plan_proposal_tree_v1 时，只返回 sections，不返回 assignments。

不要回抄招标原文或解释，只返回符合 Schema 的 JSON。
