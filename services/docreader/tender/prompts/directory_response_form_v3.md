# 原文入表范围与责任角色

仅operation=select_native_response_form_v3使用本补充规则。沿用前述原式职责先决裁定的decision、完整mandate核对、mandate_indices、原格及原子唯一归属；下列规则替代基础规则中“rows仅criterion”和“reference/procedure只能进入source_guidance”的限制。

先按全部mandate判断原式是否要求逐条列出完整来源原文，再判断各条款由谁履行。expand并不把所有原文变为投标人义务。每行必须给source_role：criterion为投标人逐项应答的实质条款，reference为需保留的参考规则，procedure为评委、采购人或其他主体的程序。source_role必须与该行全部正文refs的dispositions.kind一致；共同名称、分值及条件仍使用context，不为凑行数改成criterion。

原文明示在该表全列原文时，reference/procedure可按其真实职责进入原表的条款列，保留完整条件、计算公式及执行主体，企业响应和证明格仍留空。不得改写为投标人已履行程序、已澄清、已获分、自评分、已缴费或已满足。原文入表只是原文承载位置，不代表企业事实成立。无全列职责时，按原件选择keep_original或unresolved，保原式及人工核定；不得为了扩大入表范围强选expand。

每个criterion ref绑定一行正文；每个reference/procedure ref只能绑定一行正文或一处source_guidance，两者不能同时拥有同一原子。context仅在上下文池或表级声明一次，navigation和unresolved原规则不变。不能将程序条文升级criterion来绕过责任校验，也不能把应全列的程序留在指南来假称表已完整。原表四列角色、固定行、合并、示例省略行和原空白仍保留，不追加泛表；模型不输出企业值或誊写条文。

宿主依来源排序后复制准确原文，独立保存每行角色并绑定最终行号和实际行身份。结构审核会看到全部mandate及角色，以原件逐项检查全列范围、责任主体、空企业格和唯一原文拥有。只返回Schema允许的refs、source_role及现有有限字段。
