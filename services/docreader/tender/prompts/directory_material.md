# 章内材料

source_line_format=numbered_line_pairs_v1 时，documents 中每页 lines 的每项为 [行号, 完整原文]，行号仍是该物理页的零基行号。所有原文行和空行均保留；第一项数字是来源行号，不是参数序号或新章节编号。返回来源窗口时继续使用给出的 document_id/page/start_line/end_line，不能把数组位置另当坐标。

目录和原式已经由宿主编译。标出各章还要承载的、格式以外的原文范围，并为宿主给出的来源章节选择业务显示名。不要抄写原文，不新建章节或改变材料职责。

chapter_title_catalog 给出有限的源章节与分组身份，包括当前采用项和本次可选的来源候选。title_id 绑定来源锚点，不是两份计划各自的 chapter_id，也不是待生成的正式层级编号。chapter_titles 每项仅返回 {title_id,title}；title_id 只从该目录选择，不重复。结合本次来源取舍，为最终保留的每个章节和源分组提供名称；未保留的候选可以不命名，已命名也不因此被采用。

title 是不超过40字的完整、简短业务名，概括该章真实材料、技术参数或分组用途；保持原厂/投标人职责及真实阶段含义。不要把组成说明长句、要求的第一行或跨页残句当名称，不输出裸附件编号，不带附件/附表/卷章编号、宿主层级编号、星号、句子或省略号。附件编号是映射。显示名必须是该章来源原文里的文件名连续片段，不能新造文件名，也不能用附件编号代替文件名。原文只有编号时，从该编号下的原式里取文件名片段，不能只删编号后返回空名，也不能截取前若干字冒充名称。宿主保留完整来源原名、编号、锚点、原文和原表，并另行生成正式编号；显示名不替换正文或企业应答。

方案章使用投标人的业务响应名称，勿直接沿用评委视角的“某方案评价”“评分标准”等标签。按原件实际应交内容命名；评分依据保留在来源、指南或明确要求的响应表。真实应交的评价报告、评价服务名称保留，不能机械删词。来源格式总标题只作明确结构用途，不另造提交材料。

chapter_id 只能选择本次给出的章节。起止行必须在同一文件的同一页。已经出现在该章模板或表格里的行不要再选。没有额外材料时返回空 assignments。

unplaced_tables 是尚未归入目录章节的原表位置。只选择投标人需要提交、填写或逐项应答的原式与直接响应材料。评标人员填写的资格审查/评分工作表、纯目录索引不能因为尚未归属就搬进投标文件；其中适用义务和评分依据由章节要求环节保留。已明确本次不适用的原式不再搬入。

适用性按具体义务和提交时点判断，不能将中标后不要求实际开立扩大为删除组成清单中的投标承诺及其所附原式。已有 subjects 是待核的来源方案，不是已经证实的提交份数；按原件完整材料的分别提供要求，在给出的方案中核定，不在其他章节另造相同提交实例。

填写主体、证明提供方、签署方与独立整份材料实例须分开。同一基本情况表内列有制造商字段，或要求在该表后附投标人和制造商各自资质证明，不等于两主体各填整份投标人基本表；同一授权函中的投标人/制造商双签章，也不等于分别提交两份同文授权函。核 current/alternative 的 subjects 与完整源条件，选择正确候选，保全一份原式中的所有字段、双方签章及全部附证要求。原文明示各主体分别提供完整财务报表、审计报告或其他材料时，仍保留其独立实例；不得按文字相同全局去重，也不得因企业资料未知删除条件材料。

逐项判断已有章节是否需要该表。需要时返回完整覆盖该表的行窗口，并归给已有章节；多章共用时选择这些章节的共同父章。归属不明的不选，不要新建章节。不要再次选择已经由现有正文承载的同一提交实例，也不要把来源容器标题另当一份提交物。

table_header_catalog 是已经绑定到采用章节、尚未确认重复标题行的原生表，每张源表只提供一次完整网格，包含所有行、空白和合并关系；已有明确计数或可靠原生标题标记的表由宿主保留，不要求重抄。逐表判断哪些连续起始行共同组成应在跨页时重复的标题行，在 table_headers 返回 {table_id,count}：count 为连续起始行数，0 明确不重复，null 表示无法确认。不能根据首行位置猜测，不能将数据行或整表作为重复标题；边界不能切断跨行合并单元格。table_id 只能取本次目录，不回抄单元格、原文或既有材料归属。同一表的主体副本由宿主同步，本轮新归入的表尚未出现在该目录时由宿主保留人工核定出口。

重复标题必须适用于整个 grid。若同一原框已经出现数据或填写行，后续又有另一组不同列名的分块表头，各组表头只属于自身分块，不能把首组当作整框公共标题；没有适用于所有分块的起始公共表头时选 count=0，无法确认时选 null。保留全部内部表头原格，不把间隔的多组表头累计为连续起始行，也不能仅因首行是某一组表头就选 count=1。连续起始的多级公共表头仍按其全部连续行计数。

directory_cases 是两次来源计划仍有分歧、条件或未并入候选的完整有限清单。每个 case_id 必须在 directory_adjudications 恰好裁定一次，不能省略或编造。只能选择给出的来源候选，不能在此重新创造章节正文。完整原文已在本次读取中；按 heading、body_windows、clause_windows、condition_windows 及主体、父级、提交时点核对，不能凭短标题判断。

每项返回 {case_id,action,basis_windows,chapter_ids}。current 采用当前来源方案，alternative 采用所给另一方案；未决选 unresolved 并保留原待核。除 unresolved 外，basis_windows 必须指出本次完整原文中的非空裁定依据。主体或时点相异不是同一提交实例，不可因为文本相似互相替代。

subjects_alternative 是明确的组合取舍：仅将同一材料的完整实例主体布局取自alternative，全部其他字段明确采用current，包括完整原式/原格/空白/签章、response_kind、entry/父子/分组、适用条件和补充义务。只用于同规范节点/heading、同一独立entry、实质正文来源（含原表所属空白）一致且subjects布局确有差异的conflict；不能借此选择另一材料、改其他字段或仅更换同主体的依据。完整原式只有一份时可选已有无subjects候选的布局；明确分别提供的资料仍保留独立主体位置，不按正文相似删主体。此动作只裁本case，其他适用性/来源case仍须分别选择；需要整项替换才用alternative，无法协调用unresolved。不得为修主体而用较弱的格式标题条件替换current的完整项目条件，宿主不据签章个数自动选择此动作。

reference 只用于另一候选的完整标题、正文和义务已经由 chapter_ids 所列当前响应完整承载的来源对应，且响应类型、提交主体必须相符。不能把“不适用”谎称为“已经覆盖”。not_applicable_reference 仅用于独立的 extra 候选，本次明确不要求提交但保留完整参考范本；必须引用本次不适用依据，不表示已经履行或企业满足。投标人投标阶段承诺与中标后银行实际开函要分开核对；保留投标承诺时，不能据此声称银行范本已在Word覆盖。

container 仅把所给来源父标题作为容器，把 chapter_ids 所列采用子项挂在下面；原正文必须已经由这些子项完整承载，不得丢掉独立内容、主体或空白原式。conditional 仅用于已经有明确来源条件的 applicability 事项：来源条件已确定，企业身份、是否采用及是否符合仍未确认。不能把企业未知解释为删除必备原式，也不能将所有有条件材料当成无条件必交。

目录裁定在后续章节要求和参数展开之前应用，随后宿主提供所选章节。依赖另一项选择的引用须依据整批最终结果，不得利用已被另一选择替换的旧候选冒充正文已覆盖。真正无法确定的来源取舍使用 unresolved，有具名来源和人工核定出口。

not_applicable_reference 与整批最终响应正文必须一致：选择仅供参考的候选时，同一候选实际正文源行不能仍由 current、alternative 或新增 assignments 搬入投标正文。需要先在给定有限方案中正确保留投标承诺、退出本次不提交的独立范本；无法协调则保留 unresolved，不能一边关事项一边原文仍要求签章。

只返回 JSON，字段以宿主 Schema 为准。
