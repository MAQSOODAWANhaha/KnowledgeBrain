# 来源分册与原式条款展开范围

仅 operation=select_response_forms_and_groups_v2 时使用本补充职责；材料、主体、条件及来源取舍继续遵循本请求前面的章内材料规则。

source_groups 只补原件明确要求、当前尚未形成的投标文件分册。直接依据本次完整原件选择分组标题所在的 heading、包含该精确锚和分册职责的完整 basis_windows、最终采用后尚未分组的根章 chapter_ids，以及不超过40字的完整业务名称 title。标题不用源编号，不把“应包括：”等说明句直接作章名。分册成员和业务职责来自原件，不按材料标题的词语、页码接近或章节数组位置猜分组。

source_group_candidates 给出当前已采用章的来源和位置状态，directory_cases 中的有限候选仍按原取舍职责核定。只能选择最终已采用、没有已采用父章、尚未分组且同一原件中的根章；整棵既有子树、原式正文、空位和主体随根章保留。封面和 content 材料留在既有位置，已经有来源分组的章不再选择；每个根章至多属于一组，同源组只声明一次。不改已有父子关系，不把子章拆出重复列为成员。没有足够依据则不补组，保留原安排并继续既有未决出口，不制造分册或正文。输出组和成员的数组顺序不决定最终层级编号及源分册顺序，宿主依据真实来源锚与原组成编排。

response_form_catalog 若存在，是已经采用的原生表的有限目录。仅对原文明示需要在这份表中逐条列出来源要求原文、而条款列尚待展开的原式返回 response_forms；每项只选已给 table_id、完整 mandate_windows 及相关完整 source_windows，保留所属章节续页、共同规则和必要程序供后继区分。

没有上述明确职责返回 response_forms=[]。表中已有完整要求原文，或只需企业填写资料、报价、偏离、签章时，不因此展开全部来源条款；不能把所有表都选入。未给 response_form_catalog 时保持 response_forms=[]。本次只选来源、职责及分组，不抄条文或生成企业值；宿主保原文、原格、签章和来源身份。

技术方案的编写说明与方案必须响应的采购要求承担不同职责。候选只含“项目服务方案”等格式标题或编写提示时，核对另一来源候选及完整技术需求，不能据此认定实质要求或采购原表已经承载。结合完整来源选择正文方案或补充完整材料窗口，保留需要逐项响应的技术数据、授权/采购清单及共同条件；这类来源表即使没有企业待填空格，也可能是本章实质响应材料。不得仅因候选更长而采用，也不得把后继要求阶段可能重新发现正文当作删除原格的理由。已有完整原式和不同主体/阶段仍分别保留，确实无法协调用unresolved。
