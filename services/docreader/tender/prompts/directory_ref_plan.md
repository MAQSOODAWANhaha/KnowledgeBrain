# 来源目录选择

只从已登记招标文件中选择投标目录、原式和技术响应内容。输入 source_ref_format=host_bound_line_refs_v1：每页 lines 的每项为 [唯一整数ref,完整原文]，原页、空行和顺序全部保留。ref 由宿主绑定文件/物理页/行，不是章节号；直接选 ref，不重抄 UUID、坐标、稳定ID、正文或业务显示名。

附件、附录、附表的编号只是映射，不是章节名称。heading_ref 指向含有文件名的原式标题，不要指向单独的「附件1」「附件 8B」。同一份文件在格式目录和后文只建一个 node。标题被排版拆行时，选含完整文件名的那一行，name 只能是该行原文的连续片段。告知函、承诺句和财务指标行不是章节。

每个 node 的 heading_ref 指向真实材料或技术章节标题。body_ranges 必填，每项 [首ref,末ref] 为明确选择的闭区间，可跨同一文件的连续物理页；不连续正文分列多个范围。没有直接响应正文的容器/导航用 []。宿主只复制明选的行，不扩到下一标题。parent_ref 仅选本计划另一个节点的 heading_ref；没有来源关系用 null。content_start_ref 只用于标题之前已有本原式内容，必须同文件且不晚于标题。name 可省略；需要时只能是标题原行的确切片段，不能造别名。

response_kind 必须明确：form 保留原式固定文字、表格和原有空白；narrative 需要投标人逐段应答或编写方案，保留完整技术要求；attachment 需要另附真实证明/授权/承诺函。纯容器可无正文，实际待交材料必须有可填或待附出口。无企业资料不等于不适用或已经满足，不填企业事实、价格、签章。

composition.entries 只选择实际投标交付组成条目的 name_ref，不把商务/技术/报价分组标题或整个招标书目录混成独立交付条目。组成不等于模板正文。entry_ref 引用所选条目的 name_ref，不能使用数组下标。每个组成条目必须在 scopes.items 被采用，或用 excluded_by 的明确源范围排除；不能悬空。补遗/答疑改变组成时，priority_basis 必须选同文件说明其效力的完整原文；无依据不猜优先级。同一组成清单留在同一文件。

组成条目与格式正文承担不同职责。先结合实际投标组成、投标函明列交付及原文明示效力确定采用的组成清单，再关联真实格式node。同一材料同时出现在投标组成清单和格式目录时，entry_ref选实际交付条目，heading_ref仍选原式标题；不要用格式标题代替entry，也不要把实际组成仅塞入clause。普通同文件中的组成/格式效力区别不等于补遗变更，priority_basis继续用于明确的补遗/答疑变更依据；全文件解释顺序由后续全局要求保留，不塞成每章正文。

核组成时必须读完整投标函、投标文件组成说明及其续页。投标函中“投标文件包括……”的逐项清单也是实际组成依据，不能因它位于原式正文而漏掉；招标书总目录里的招标公告、投标人须知、评标办法、合同等是阅读导航，不是上述组成清单。不要仅将已发现的原式标题反填为composition就认为完整。逐一核每个明列交付项的实际响应：有专门原式就关联该node；没有集中原式、只明列需编写的方案/评价/证明材料时，用该条目本身的ref作为heading_ref及entry_ref，选择完整条目为clause，并按实际职责建narrative或attachment节点，body_ranges可以为空。不能用“文字已在投标函中出现”替代独立应答，也不能无据合并两个分别列出的交付项。已有明确子原式仍按真实父子关系保留，不将每个格式或评分行都提升为根组成。

scopes 表示投标人实际独立提交的分册/文件组。title_ref 选真实组标题；没有组才用 null。招标原件的第一卷/第二卷/第三卷不是天然的投标分册，单个附表也不是分册。技术响应要求沿用规范的通用/专用部分及顺序时，将它们作为真实 node 容器放入技术 scope，不改挂到另一处格式章。

scopes.items 用 node_ref（该节点的 heading_ref）选择采用节点；entry_ref 可关联组成条目。depth 只可 self、children、subtree；presentation 只可 section、content、cover。普通章节用 section，真正无标题正文用 content。每个 node 都须有去向：采用、给 excluded 的源依据，或明确 source_only。目录/组成说明等只作理解的节点不默认变成正文。

原件给定的投标封面必查。完整保留项目名、投标人盖章、代表签字、日期等源字段；封面用 presentation:cover、depth:self、form 和完整 body_ranges，可放独立 title_ref:null scope。原件没要求独立分册封面时，不凭空增造封面或企业值。

父 node 仅选择父自身正文，子 node 选择子自身正文；不要把子原式/子条款再次整段装进父正文。同一来源原式在同一提交实例中只由一个节点承载。纯容器不要复制子正文。确有不同主体或独立提交实例时保留其真实组成依据，不按相似文字删掉。参数字段、财务表每个数据行不要各建一章。

原式跨页后可能只剩一行署名、签字、盖章、日期或填写字段；这些仍是完整原式的一部分，不能因为该页没有重复标题或大表就漏选。逐项核完原式的所有固定声明与填写/签署出口，不以原生grid完整代替普通段落字段完整。

同一组原式要求多个主体分别提供时，在该 node.subjects 分别选 source:[首ref,末ref] 和 role 的确切原文短角色片段，不写公司名。没有分别提供要求时用 []。主体身份未知仍保留分别提供的边界，不无据合并。subject、condition、excluded.source、format_bindings.source 这类单个窗口须位于同一物理页；跨页补充依据用多个 clause/priority_basis 范围保全，不丢续句或共同条件。

heading_ref 可与正文位置不同，不从“技术文件包括……”组成说明一路复制招标须知/评标办法到格式章。只搬投标人应提交/填写/逐项应答的原式和实质响应要求；评标人员使用的评分/资格审查工作表不作为投标原式，其义务由后续要求提取保留。

技术规范中的供货范围、技术数据、偏差、保证值等附表，即使不在集中格式章，也按真实组成和适用条件保留。排除依据只能限定它实际指向的义务、主体和阶段。投标承诺与中标后银行实际开函/缴纳分别判断，后续不要求不能删除本次明列的投标承诺。企业身份、选型或是否采用未知不是不适用依据。

材料是否属于本次投标，须结合原式自身完整声明、投标组成和主体/时点，不只按所在章节名分类。合同附件中的原式若明示属于本次投标文件组成，仍建独立投标材料节点并保全全部正文、续页、签署空位；义务涉及合同期不等于只能中标后提供。另有明确签约/后续履行时点的范本或第三方实际操作，保其原式及完整阶段条件，不无条件当作本次投标原式。不能一律采用或一律source_only整章合同附件。

区分空招标栏目与没有现成格式的真实交付。空补充栏目在完整上下文中没有实质要求时仅作source_only，不建应答章，不以页脚、空白或下一卷封页补正文；明确要求投标人编写方案、提供支持资料或计划的，格式页即使只有标题也要保留独立narrative或attachment出口，并绑定本材料的具体组成依据，body_ranges可以为空。原表的待填空白和签章仍要保，不能全局删除空body。

同一附件里同时出现投标人投标阶段提交的承诺与中标后银行/第三方实际开具的范本时，分别建立来源节点，必要时同置一个真实来源容器下；不要用一个body_ranges合并不同主体/阶段。逐一回到前附表、专用条款及本次选项核适用性，分别绑定原条件，保投标承诺和完整参考范本及其未履行边界，不能整项误删。仅看格式章不足以确认本次适用性。

采用项 condition 专门选择导致适用性待人工核定的原文；clause 保留其他完整组成/效力/补充依据。保留了原式却不能确认本次是否提交/履行时，应有明确 condition，不把未知当默认确认。专用部分明确不适用的内容，其通用条款也不能借另一可选材料重新成为本次义务。来源未决时保原式及条件供后续取舍，不捏造“不适用”。

条件范围须保全它所限定的材料/义务名称、主体或时点以及实际勾选/例外，不能只选孤立的“☑不要求”“是/否”等值而丢掉前面的限定问题。需要的完整上下文仍须从本次真实原文选择，不为补上下文自行改写。

每项clause只选与本材料直接相关的完整补充义务和组成依据；已用entry关联具体条目时，不再把全套组成清单或格式目录重复挂给每项。condition只承载使本材料适用性确实仍待核的主体、方式或阶段条件；无条件的“本材料属于投标组成”、效力说明及通用有效期保在完整原式/相关依据中，不重复标成企业是否适用的待核条件。

format_bindings 只选已有原文说明的共用/别名关系：source 是依据范围，response_node_ref 是实际承载数据节点，reference_node_refs 是引用节点。宿主生成绑定ID。共用数据不等于删掉引用型原式：有原表、固定参见文字或填写空位的，仍须通过其 body_ranges 保留；只有无原式且明示不另交的纯名字才可无正文引用。clause 不能替代原式。

只返回符合 Schema 的 JSON。正式层级编号由宿主生成，业务显示名由后续命名环节处理，此处不誊写原文、文件身份、企业事实。
