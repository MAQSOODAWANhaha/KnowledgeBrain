# 原式逐条原文展开

本请求只处理这一份已采用原生响应原式和本次完整来源上下文；原表和mandate已给出。不要读取外部企业资料，不抄写条文、原表、UUID或企业回答，只返回Schema允许的整数短refs和职责。

source_scope中每个lines项是[唯一整数ref,完整原文片段]。ref不是章节号、行号或原表序号。原生单元格的page/row/column/合并元数据和空格都保留；同一格的换行片段仍属于这一格，不从多列阅读串猜测词序。普通prose也提供原行片段；正文跨页或跨格续接时须保完整条件和证明义务。输入中的source_binding由宿主绑定，不回抄。

source_scope_closure=complete_native_pages_selected_by_source_windows_v1表示source_windows已向其选中物理页的完整原生内容闭合；source_pages列出实际可见页。范围内的其他表头、序号、程序和参考条款也完整提供，须按职责处置。PDF内嵌文件目录只是独立附件清单，不是这些页的正文，不能假称其未提供的内容已读取或响应。

layout只选择form.grid实际可重复的填写行闭区间及序号、条款、企业响应、证明位置的列角色，均零基。不能把固定声明、签章、尾注、例示省略行或跨合并原型当空白行删除/复制。原序号和既有示例行保留，不需要誊写格内文字。无法确认布局时layout为null并保留unresolved，不能改成泛表。

每个提供的ref必须在dispositions恰好出现一次。kind为criterion（投标人需要逐项应答的实质条款）、context（名称/分值/共同条件）、reference（需保留的评审规则参考）、procedure（评委/他方或条件触发程序）、navigation（纯表头/序号/目录/导航）或unresolved。不要把所有来源都当criterion，也不能用navigation/reference隐藏实际条款。后续程序、评委计分与当前企业应答有不同职责，不能声称投标人已澄清、已缴纳或取得得分。

rows仅列criterion正文refs，保每条完整条件、时点、证明要求及替代路径；正文不可重复拥有。一个评审项确有分别编制的方案、服务或子义务时给独立行，不为了凑数拆残句/普通参数字段，也不把若干独立义务压成共用一个空位。宿主按来源位置编排、复制原文并留企业响应/证据页码空白，不生成满足、承诺、自评分或0报价。

context refs在contexts池中只声明一次，每个row最多引用一个context_index（contexts数组零基下标）；同一评分项的多个子行可以共享该组名称/分值/共同条件，不在每行回抄同一来源。完全共同的表级条件可放table_context_refs，也只能声明一次。未被行引用的context组不要声明。真正正文不能伪装成共同context。

source_join缺省paragraphs，片段之间保分段；只有已确认是同一条款/同一格的逻辑续接时用continuation。不要把CPU名称的续字与前页页脚、别列名称接到一起，不全局删除数字或空白。native格内的refs须按完整原文组装，不能漏末行条件或签署/证明尾句。

source_guidance只选reference/procedure的refs，kind须一致，保完整引用及明确续接。它们进入编制参考/指南，不进入企业应答列；普通表头/序号/navigation不输出为指南。价格评分公式、失信扣分和评审程序必须保真实源条件和主体，不填企业价格、得分或外部动作已完成。重复回引同一前附表不再造多套响应条款。

每个criterion ref必须绑定一行正文，每个context ref绑定一次共享上下文，每个reference/procedure ref绑定一次source_guidance；navigation只保来源处置，unresolved保持明确未决。只要仍有unresolved或缺少完整布局/条款，宿主就保原表及具名人工核定出口，不能把任意非空几行称为完整。只返回紧凑JSON。
